## UF-001: 콘서트 목록 조회

### 입력
- 사용자가 홈 페이지에 접속

### 처리
1. 서버에 콘서트 목록 요청 전송
2. 현재 날짜 및 시간 확인
3. 데이터베이스에서 콘서트 정보 조회
4. 각 콘서트별 진행일 확인
   - 진행일 전날 23:59:59까지인 콘서트만 필터링
5. 각 콘서트별 예약 현황 계산
   - 총 좌석 수: 320석 (4x20 x 4구역)
   - 예약된 좌석 수 카운트
   - 예약 가능한 좌석 수 계산
6. 콘서트 목록 데이터 정렬 (진행일 오름차순 또는 등록일 기준)
7. 응답 데이터 생성

### 출력
- **성공 케이스**:
  - 콘서트 목록 렌더링
  - 각 콘서트 카드에 다음 정보 표시:
    - 콘서트 제목
    - 콘서트 일시
    - 장소
    - 예약 현황 (예약인원/총정원)
    - 썸네일 이미지 (있는 경우)
  - 각 카드는 클릭 가능한 상태로 표시

- **엣지 케이스**:
  - **예약 가능한 콘서트가 없는 경우**:
    - 빈 상태 메시지 표시
    - 안내 텍스트 표시

  - **모든 좌석이 매진된 콘서트**:
    - 목록에는 표시하되 매진 표시
    - 카드 클릭 시 상세 페이지 이동은 가능하나 예약하기 비활성화

  - **서버 에러**:
    - 에러 메시지 표시
    - 재시도 버튼 표시

  - **네트워크 타임아웃**:
    - 로딩 인디케이터 표시
    - 타임아웃 에러 메시지
    - 재시도 옵션 제공

## UF-002: 콘서트 상세 조회

### 입력
- 사용자가 콘서트 목록에서 특정 콘서트 카드 클릭
- URL 파라미터: `concertId`

### 처리
1. URL에서 `concertId` 추출
2. 서버에 해당 콘서트 상세 정보 요청
3. 데이터베이스에서 콘서트 정보 조회
   - 콘서트 기본 정보 (제목, 설명, 일시, 장소 등)
   - 좌석 예약 현황
4. 콘서트 존재 여부 확인
5. 예약 가능 여부 확인
   - 진행일이 현재 날짜보다 미래인지
   - 진행일 전날까지인지 확인
6. 예약 가능한 좌석 수 계산
7. 응답 데이터 생성

### 출력
- **성공 케이스**:
  - 콘서트 상세 정보 렌더링
    - 콘서트 제목
    - 상세 설명
    - 공연 일시
    - 장소
    - 출연진 정보
    - 예약 가능 좌석 수
  - 예약하기 버튼 표시 (활성화 상태)

- **엣지 케이스**:
  - **콘서트를 찾을 수 없는 경우** (잘못된 concertId):
    - 404 에러 페이지 표시
    - 홈으로 돌아가기 버튼 제공

  - **예약 기간이 종료된 경우**:
    - 콘서트 정보는 표시
    - 예약하기 버튼 비활성화
    - 예약 마감 안내 메시지 표시

  - **모든 좌석이 매진된 경우**:
    - 콘서트 정보는 표시
    - 예약하기 버튼 비활성화
    - 매진 안내 메시지 표시

  - **서버 에러**:
    - 에러 메시지 표시
    - 뒤로가기 또는 재시도 버튼 제공

  - **동시 접속으로 인한 데이터 변경**:
    - 최신 예약 현황 반영
    - 남은 좌석 수 실시간 업데이트 (선택적 폴링)

## UF-003: 좌석 선택

### 입력
- 사용자가 콘서트 상세 페이지에서 예약하기 버튼 클릭
- 예약 페이지에서 빈 좌석 클릭

### 처리
1. **예약 페이지 진입 시**:
   - URL에서 `concertId` 추출
   - 서버에 좌석 배치 정보 요청
   - 데이터베이스에서 320개 좌석의 현재 상태 조회
   - 각 좌석의 상태 확인 (예약됨/빈자리)
   - 좌석 배치도 데이터 생성 (4개 구역, 각 4x20)
   - 응답 전송

2. **좌석 클릭 시**:
   - 클릭된 좌석의 위치 정보 확인 (구역, 행, 열)
   - 해당 좌석의 현재 상태 확인
   - 현재 선택된 좌석 수 카운트
   - 선택 가능 여부 검증:
     - 좌석이 이미 예약된 상태인지 확인
     - 이미 선택된 좌석인지 확인
     - 선택된 좌석 수가 4개 미만인지 확인
   - 검증 통과 시:
     - 해당 좌석을 선택된 상태로 변경
     - 선택된 좌석 목록에 추가
     - 우측 사이드바 데이터 업데이트

### 출력
- **예약 페이지 진입 시 성공**:
  - 좌석 배치도 렌더링 (4개 구역)
  - 각 좌석의 상태 시각적 표시:
    - 빈 좌석: 클릭 가능한 상태
    - 예약된 좌석: 비활성화 상태
  - 우측 사이드바 표시:
    - 전체 남은 좌석 수
    - 선택된 좌석 목록 (초기: 비어있음)
    - 예약하기 버튼 (초기: 비활성화)

- **좌석 선택 성공**:
  - 선택된 좌석 시각적 상태 변경 (강조 표시)
  - 우측 사이드바 업데이트:
    - 선택된 좌석 정보 추가 (구역, 행, 열)
    - 각 좌석 옆에 X 아이콘 표시
    - 선택된 좌석 수 표시
  - 예약하기 버튼 활성화 (1개 이상 선택 시)

- **엣지 케이스**:
  - **이미 예약된 좌석을 클릭한 경우**:
    - 클릭 무시
    - 시각적 피드백 없음 또는 간단한 툴팁 표시

  - **4개를 이미 선택한 상태에서 추가 선택 시도**:
    - 클릭 무시
    - 최대 선택 개수 도달 안내 메시지 표시 (토스트/알림)

  - **이미 선택된 좌석을 다시 클릭한 경우**:
    - 선택 해제로 처리 (UF-004로 분기)

  - **페이지 로드 중 좌석 정보 조회 실패**:
    - 에러 메시지 표시
    - 뒤로가기 버튼 제공

  - **좌석 데이터가 없는 경우**:
    - 빈 상태 메시지 표시
    - 관리자 문의 안내

  - **네트워크 지연으로 인한 로딩 시간**:
    - 로딩 인디케이터 표시
    - 스켈레톤 UI 표시

## UF-004: 좌석 선택 해제

### 입력
- **방법 1**: 사용자가 이미 선택된 좌석을 다시 클릭
- **방법 2**: 사용자가 우측 사이드바에서 X 아이콘 클릭

### 처리
1. 클릭된 좌석 또는 X 아이콘에 해당하는 좌석 식별
2. 선택된 좌석 목록에서 해당 좌석 확인
3. 해당 좌석을 선택된 목록에서 제거
4. 좌석 상태를 선택 해제 상태로 변경
5. 남은 선택된 좌석 수 확인
6. 사이드바 데이터 업데이트

### 출력
- **성공 케이스**:
  - 해당 좌석의 시각적 상태 변경 (선택 해제)
  - 우측 사이드바 업데이트:
    - 선택된 좌석 목록에서 해당 좌석 제거
    - 남은 선택 좌석 수 업데이트
  - 선택된 좌석이 0개가 된 경우:
    - 예약하기 버튼 비활성화

- **엣지 케이스**:
  - **존재하지 않는 좌석 해제 시도**:
    - 에러 로깅
    - 사용자에게는 영향 없음

  - **동시에 여러 좌석 해제 시도** (빠른 클릭):
    - 각 클릭 이벤트를 순차 처리
    - 중복 처리 방지 (디바운싱)

## UF-005: 예약 정보 입력 및 제출

### 입력
- **단계 1**: 사용자가 좌석 선택 후 예약하기 버튼 클릭
- **단계 2**: 사용자가 예약자 정보 입력
  - 예약자명 (텍스트)
  - 휴대폰번호 (숫자, 하이픈 포함/미포함)
  - 비밀번호 4자리 (숫자)
- **단계 3**: 사용자가 제출 버튼 클릭

### 처리

#### 단계 1: 정보입력 화면 전환
1. 현재 선택된 좌석 목록 확인 (1개 이상)
2. 정보입력 UI로 화면 전환
3. 선택된 좌석 정보 유지

#### 단계 2: 입력 검증 (클라이언트 측)
1. 각 입력 필드의 실시간 검증:
   - **예약자명**:
     - 공백이 아닌지 확인
     - 최소/최대 길이 검증 (예: 2-50자)
   - **휴대폰번호**:
     - 숫자만 포함하는지 확인
     - 길이 검증 (10-11자리)
     - 형식 검증 (010으로 시작 등)
   - **비밀번호 4자리**:
     - 정확히 4자리 숫자인지 확인
2. 모든 필드가 유효한 경우 제출 버튼 활성화

#### 단계 3: 예약 제출 및 처리
1. 제출 버튼 비활성화 (중복 제출 방지)
2. 로딩 상태 표시
3. 서버에 예약 요청 전송:
   - `concertId`
   - 선택된 좌석 목록 (구역, 행, 열)
   - 예약자명
   - 휴대폰번호
   - 비밀번호 (해시 처리 전송)
4. **서버 측 처리**:
   - 트랜잭션 시작
   - 콘서트 존재 여부 확인
   - 예약 기간 유효성 재검증
   - 선택된 각 좌석의 현재 상태 조회 (Lock)
   - **좌석 상태 재검증**:
     - 모든 좌석이 여전히 예약 가능한지 확인
     - 하나라도 예약된 좌석이 있는지 확인
   - **검증 실패 시**:
     - 트랜잭션 롤백
     - 실패 응답 전송
   - **검증 성공 시**:
     - 예약 레코드 생성
     - 비밀번호 해싱 후 저장
     - 선택된 좌석들의 상태를 예약됨으로 업데이트
     - 예약-좌석 연결 레코드 생성
     - 트랜잭션 커밋
     - 성공 응답 전송 (예약 ID 포함)

### 출력
- **정보입력 화면 전환 성공**:
  - 좌석 선택 UI 숨김
  - 정보입력 폼 표시
  - 선택된 좌석 요약 정보 표시 (읽기 전용)
  - 뒤로가기 버튼 표시

- **예약 성공**:
  - 예약 완료 페이지로 리디렉션
  - URL: `/bookings/:bookingId/complete`
  - 예약 완료 안내 메시지 표시
  - 예약 상세 정보 표시:
    - 예약 번호
    - 콘서트 정보
    - 예약자명
    - 예약된 좌석 목록
  - 예약취소 버튼 표시
  - 홈으로 돌아가기 버튼 표시

- **예약 실패 (좌석 중복)**:
  - Alert 또는 모달 창 표시
  - 좌석 선택 화면으로 복귀
  - 좌석 배치도 최신 상태로 갱신
  - 이전에 선택했던 좌석 중 현재 예약 가능한 것만 자동 선택 (선택사항)
  - 제출 버튼 재활성화

- **엣지 케이스**:
  - **필수 필드 누락**:
    - 해당 필드에 에러 메시지 표시
    - 제출 버튼 비활성화 유지

  - **유효하지 않은 형식 입력**:
    - 실시간 에러 메시지 표시 (필드 아래)
    - 제출 버튼 비활성화

  - **중복 제출 시도** (더블 클릭):
    - 첫 번째 요청만 처리
    - 버튼 즉시 비활성화
    - 로딩 인디케이터 표시

  - **네트워크 타임아웃**:
    - 타임아웃 에러 메시지 표시
    - 재시도 버튼 제공
    - 입력했던 정보 유지

  - **서버 에러 (500)**:
    - 일반 에러 메시지 표시
    - 재시도 버튼 제공
    - 입력 정보 유지

  - **콘서트 예약 마감** (서버 검증 실패):
    - 예약 마감 안내 메시지 표시
    - 홈으로 돌아가기 버튼 제공

  - **잘못된 concertId**:
    - 404 에러 메시지 표시
    - 홈으로 돌아가기 버튼 제공

  - **세션 만료 또는 데이터 손실**:
    - 선택된 좌석 정보가 없는 경우
    - 안내 메시지 표시
    - 좌석 선택 화면으로 복귀 또는 홈으로 이동

## UF-006: 예약 조회

### 입력
- 사용자가 예약 조회 페이지 접속
- 사용자가 조회 정보 입력:
  - 휴대폰번호 (숫자)
  - 비밀번호 4자리 (숫자)
- 사용자가 조회 버튼 클릭

### 처리
1. **페이지 로드**:
   - 예약 조회 폼 렌더링

2. **입력 검증 (클라이언트 측)**:
   - 휴대폰번호 형식 검증
   - 비밀번호 4자리 숫자 검증
   - 모든 필드 입력 시 조회 버튼 활성화

3. **조회 요청 처리**:
   - 조회 버튼 비활성화
   - 로딩 상태 표시
   - 서버에 조회 요청 전송:
     - 휴대폰번호
     - 비밀번호 (해시 처리)

4. **서버 측 처리**:
   - 입력받은 휴대폰번호로 예약 레코드 조회
   - 비밀번호 해시 비교 검증
   - 일치하는 예약 건 필터링
   - 각 예약 건에 대해:
     - 콘서트 정보 조회
     - 예약된 좌석 정보 조회
     - 예약 일시 확인
   - 예약 목록 데이터 생성 (최신순 정렬)
   - 응답 전송

### 출력
- **조회 성공 (예약 건 있음)**:
  - 예약 목록 렌더링
  - 각 예약 건 카드 표시:
    - 예약 번호
    - 콘서트 제목
    - 공연 일시
    - 예약 일시
    - 예약된 좌석 목록 (구역, 행, 열)
    - 예약 상태 (확정/취소됨)
    - 예약취소 버튼 (취소되지 않은 경우만)

- **조회 성공 (예약 건 없음)**:
  - 빈 상태 메시지 표시
  - 안내 텍스트 표시
  - 다시 조회하기 버튼 또는 홈으로 가기 버튼

- **엣지 케이스**:
  - **잘못된 휴대폰번호 또는 비밀번호**:
    - 에러 메시지 표시
    - 보안을 위해 구체적인 실패 이유는 숨김
    - 재시도 가능

  - **입력 형식 오류**:
    - 필드별 실시간 에러 메시지 표시
    - 조회 버튼 비활성화

  - **서버 에러**:
    - 에러 메시지 표시
    - 재시도 버튼 제공

  - **네트워크 타임아웃**:
    - 타임아웃 메시지 표시
    - 재시도 옵션 제공

  - **다수의 예약 건 존재** (페이지네이션 고려):
    - 최신 예약부터 표시
    - 필요 시 페이지네이션 또는 무한 스크롤 적용

  - **과거 콘서트 예약 건**:
    - 목록에 표시하되 완료된 상태 표시
    - 예약취소 버튼 숨김 또는 비활성화

## UF-009: 페이지 새로고침 처리

### 입력
- 사용자가 브라우저 새로고침 버튼 클릭 (F5, Cmd+R)
- 사용자가 페이지를 떠났다가 뒤로가기로 복귀

### 처리
1. 현재 URL 및 페이지 상태 확인
2. 페이지별 처리:

   **홈 페이지 (`/`)**:
   - 콘서트 목록 재조회
   - 일반적인 페이지 로드

   **콘서트 상세 페이지 (`/concerts/:concertId`)**:
   - URL에서 `concertId` 추출
   - 콘서트 정보 재조회
   - 일반적인 페이지 로드

   **콘서트 예약 페이지 (`/concerts/:concertId/booking`)**:
   - URL에서 `concertId` 추출
   - 좌석 정보 재조회 (최신 상태)
   - 선택된 좌석 정보 초기화 (세션 스토리지에 저장된 경우 복원 선택사항)
   - 정보입력 단계에 있었다면 좌석 선택 단계로 복귀

   **예약 완료 페이지 (`/bookings/:bookingId/complete`)**:
   - URL에서 `bookingId` 추출
   - 예약 정보 재조회
   - 일반적인 페이지 로드

   **예약 조회 페이지 (`/bookings/search`)**:
   - 조회 폼으로 초기화
   - 이전 조회 결과는 삭제
   - 입력 필드 초기화

### 출력
- **성공 케이스**:
  - 최신 데이터로 페이지 렌더링
  - 이전 상태는 유지되지 않음 (예약 페이지의 선택된 좌석 제외 옵션)

- **엣지 케이스**:
  - **예약 완료 페이지에서 bookingId가 유효하지 않음**:
    - 404 에러 페이지 표시
    - 예약 조회 또는 홈으로 이동 옵션 제공

  - **콘서트 상세/예약 페이지에서 concertId가 유효하지 않음**:
    - 404 에러 페이지 표시
    - 홈으로 이동 옵션 제공

  - **예약 페이지에서 콘서트가 마감된 경우**:
    - 예약 마감 안내 메시지 표시
    - 좌석 선택 비활성화
    - 콘서트 상세 또는 홈으로 이동 옵션

  - **네트워크 오프라인**:
    - 오프라인 안내 메시지 표시
    - 재시도 버튼 제공

  - **서버 점검 중**:
    - 점검 안내 페이지 표시

## 추가 시나리오

### UF-010: 동시성 제어 (Race Condition)

#### 시나리오
- 여러 사용자가 동일한 좌석을 동시에 선택하고 예약 시도

#### 처리
1. 각 사용자가 좌석 선택 및 정보 입력 진행 (클라이언트 측에서는 모두 가능)
2. 첫 번째 사용자가 예약 제출:
   - 서버에서 트랜잭션 시작
   - 해당 좌석에 Lock 걸기
   - 좌석 상태 확인 → 예약 가능
   - 예약 처리 및 좌석 상태 업데이트
   - 트랜잭션 커밋
   - Lock 해제
3. 두 번째 사용자가 예약 제출 (거의 동시):
   - 서버에서 트랜잭션 시작
   - 해당 좌석에 Lock 시도 (첫 번째 사용자의 트랜잭션 완료 대기)
   - 좌석 상태 확인 → 이미 예약됨
   - 예약 실패 응답
   - 트랜잭션 롤백

#### 출력
- 첫 번째 사용자: 예약 성공
- 두 번째 사용자: 중복 예약 실패 메시지 (UF-005 참조)

---

### UF-011: 브라우저 탭 간 동기화

#### 시나리오
- 사용자가 동일한 콘서트 예약 페이지를 여러 탭에서 열어둠
- 한 탭에서 좌석을 예약하면 다른 탭의 상태는?

#### 처리
1. 각 탭은 독립적으로 작동
2. 실시간 동기화는 구현하지 않음 (선택사항)
3. 각 탭에서 예약 시도 시 서버에서 최신 상태 검증

#### 출력
- 실시간 동기화 없음:
  - 각 탭에서 예약 시도 시 서버 검증으로 중복 방지
  - 사용자가 수동으로 새로고침하여 최신 상태 확인

- 실시간 동기화 구현 시 (선택사항):
  - WebSocket 또는 Server-Sent Events 사용
  - 좌석 상태 변경 시 모든 연결된 클라이언트에 브로드캐스트
  - 각 탭의 좌석 배치도 자동 업데이트

---

### UF-012: 세션 타임아웃 (선택사항)

#### 시나리오
- 사용자가 좌석 선택 후 장시간 방치
- 다른 사용자가 해당 좌석을 예약할 수 있는가?

#### 처리 (현재 구현)
- 좌석 임시 예약 없음
- 선택만으로는 좌석 상태 변경 없음
- 최종 제출 시점에 검증

#### 대안 (향후 고려)
- 좌석 선택 시 임시 예약 (10분)
- 타이머 표시
- 시간 초과 시 임시 예약 해제

---

### UF-013: 뒤로가기/앞으로가기 처리

#### 입력
- 사용자가 브라우저 뒤로가기 버튼 클릭

#### 처리 및 출력

**예약 페이지 (정보입력 단계) → 뒤로가기**:
- 좌석 선택 단계로 복귀
- 선택된 좌석 정보 유지 (세션 스토리지 활용)

**예약 페이지 (좌석 선택) → 뒤로가기**:
- 콘서트 상세 페이지로 이동
- 선택된 좌석 정보 삭제

**예약 완료 페이지 → 뒤로가기**:
- 뒤로가기 방지 (선택사항)
- 또는 홈 페이지로 리디렉션
- 예약 페이지로 돌아가지 않도록 처리

**콘서트 상세 → 뒤로가기**:
- 홈 페이지로 이동

---

## 엣지 케이스 종합

### 1. 네트워크 관련
- 네트워크 오프라인
- 타임아웃
- 느린 연결

### 2. 데이터 무결성
- 존재하지 않는 리소스 (404)
- 중복 요청
- 동시성 문제

### 3. 사용자 입력
- 유효하지 않은 형식
- 필수 필드 누락
- 악의적인 입력 (SQL Injection, XSS 등)

### 4. 비즈니스 로직
- 예약 마감
- 좌석 매진
- 최대 선택 개수 초과
- 이미 취소된 예약

- 새로고침
- 뒤로가기/앞으로가기
- 탭 간 동기화
- 세션/로컬 스토리지 제한

### 6. 서버 상태
