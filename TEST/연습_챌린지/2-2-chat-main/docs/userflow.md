# Userflow: 실시간 채팅 서비스

## 개요
이 문서는 실시간 채팅 서비스의 기능별 상세 유저플로우를 정의합니다. 각 플로우는 **입력(Input)**, **처리(Process)**, **출력(Output)** 단계로 구성되며, 발생 가능한 엣지케이스를 포함합니다.

---

## 1. 인증 관련 플로우

### 1.1 회원가입

#### 입력
- 사용자가 회원가입 페이지(`/signup`)에 접근
- 닉네임, 이메일, 비밀번호, 비밀번호 확인 필드에 값 입력
- 제출 버튼 클릭

#### 처리
1. 클라이언트 측 입력값 유효성 검증 (React Hook Form + Zod)
   - 닉네임: 2~20자, 특수문자 제외
   - 이메일: 유효한 이메일 형식
   - 비밀번호: 8자 이상, 영문+숫자 조합
   - 비밀번호 확인: 비밀번호와 일치 여부
2. 검증 통과 시 서버에 회원가입 요청 전송 (`POST /api/auth/signup`)
3. 서버에서 Supabase Auth를 통한 사용자 생성
4. 사용자 프로필 테이블에 닉네임 저장
5. 회원가입 완료 처리

#### 출력
- **성공**: 로그인 페이지(`/login`)로 리다이렉트, 성공 메시지 표시
- **실패 (클라이언트 검증)**: 해당 필드 아래 에러 메시지 표시, 폼 제출 차단
- **실패 (서버 에러)**: 이메일 중복, 네트워크 에러 등의 에러 메시지 표시

#### 엣지케이스
- 이미 가입된 이메일 입력 시: 이메일 중복 에러 메시지 표시
- 네트워크 연결 끊김: 요청 실패 에러 메시지 표시, 재시도 안내
- 비밀번호와 비밀번호 확인이 다른 경우: 비밀번호 확인 필드에 불일치 에러 표시
- 서버 응답 지연: 로딩 인디케이터 표시, 일정 시간 후 타임아웃 처리

---

### 1.2 로그인

#### 입력
- 사용자가 로그인 페이지(`/login`)에 접근
- 이메일, 비밀번호 필드에 값 입력
- 로그인 버튼 클릭

#### 처리
1. 클라이언트 측 입력값 기본 검증 (비어있지 않은지 확인)
2. 서버에 로그인 요청 전송 (`POST /api/auth/login`)
3. Supabase Auth를 통한 인증 처리
4. 세션 토큰 생성 및 쿠키/로컬 스토리지 저장
5. 인증 상태 업데이트

#### 출력
- **성공**: 홈 페이지(`/`) 또는 `redirectedFrom` 파라미터로 지정된 페이지로 리다이렉트
- **실패 (인증 정보 오류)**: 이메일 또는 비밀번호가 잘못되었다는 에러 메시지 표시
- **실패 (서버 에러)**: 네트워크 에러 또는 서버 에러 메시지 표시

#### 엣지케이스
- 존재하지 않는 이메일 입력: 인증 실패 에러 메시지 표시
- 잘못된 비밀번호 입력: 인증 실패 에러 메시지 표시
- 이미 로그인된 상태에서 로그인 페이지 접근: 자동으로 홈 페이지로 리다이렉트
- 네트워크 연결 끊김: 요청 실패 에러 메시지 표시
- 로그인 후 세션 만료: 자동으로 로그인 페이지로 리다이렉트, 재로그인 안내

---

### 1.3 로그아웃

#### 입력
- 사용자가 마이페이지(`/my-page`)에서 로그아웃 버튼 클릭

#### 처리
1. 로그아웃 확인 요청 (선택 사항)
2. 서버에 로그아웃 요청 전송 (`POST /api/auth/logout`)
3. Supabase Auth 세션 종료
4. 클라이언트 측 세션 토큰 제거 (쿠키/로컬 스토리지)
5. 인증 상태 초기화

#### 출력
- **성공**: 로그인 페이지(`/login`)로 리다이렉트
- **실패**: 에러 메시지 표시, 재시도 안내

#### 엣지케이스
- 네트워크 연결 끊김: 클라이언트 측 세션만 삭제 후 로그인 페이지로 이동
- 이미 로그아웃된 상태: 로그인 페이지로 즉시 리다이렉트

---

### 1.4 닉네임 수정

#### 입력
- 사용자가 마이페이지(`/my-page`)에서 닉네임 입력 필드 수정
- 저장 버튼 클릭

#### 처리
1. 클라이언트 측 닉네임 유효성 검증 (2~20자, 특수문자 제외)
2. 서버에 닉네임 수정 요청 전송 (`PATCH /api/users/me`)
3. 사용자 프로필 테이블 업데이트
4. 응답 처리

#### 출력
- **성공**: 저장 완료 메시지 표시 (토스트 또는 인라인 메시지)
- **실패 (유효성 검증)**: 닉네임 필드 아래 에러 메시지 표시
- **실패 (서버 에러)**: 서버 에러 메시지 표시

#### 엣지케이스
- 변경 사항 없이 저장 시도: 변경 사항이 없다는 메시지 표시 또는 요청 자체를 보내지 않음
- 닉네임 길이 초과: 최대 글자 수 초과 에러 메시지 표시
- 특수문자 포함: 특수문자 사용 불가 에러 메시지 표시
- 네트워크 연결 끊김: 요청 실패 에러 메시지 표시

---

## 2. 채팅방 관리 플로우

### 2.1 채팅방 목록 조회

#### 입력
- 사용자가 홈 페이지(`/`)에 접근

#### 처리
1. 서버에 채팅방 목록 요청 전송 (`GET /api/chat-rooms`)
2. 모든 채팅방 데이터 조회 (최근 메시지 시간 기준 정렬)
3. 각 채팅방의 최근 메시지 정보 포함 (미리보기, 시간)
4. 응답 데이터를 UI에 렌더링

#### 출력
- **성공**: 채팅방 목록 표시 (카드 형태)
  - 각 카드: 채팅방 이름, 최근 메시지 미리보기, 최근 메시지 시간
- **빈 목록**: 채팅방이 없다는 안내 메시지 및 채팅방 추가 버튼 강조
- **실패**: 에러 메시지 표시, 재시도 버튼 제공

#### 엣지케이스
- 채팅방이 하나도 없는 경우: 빈 상태 UI 표시, 채팅방 추가 안내
- 채팅방 개수가 많은 경우 (100개 이상): 페이지네이션 또는 스크롤 최적화
- 최근 메시지가 없는 채팅방: 기본 안내 문구 표시
- 네트워크 연결 끊김: 에러 메시지 및 재시도 버튼 표시
- 로딩 중: 스켈레톤 UI 또는 로딩 인디케이터 표시

---

### 2.2 채팅방 생성

#### 입력
- 사용자가 홈 페이지에서 '채팅방 추가' 버튼 클릭
- 채팅방 추가 페이지(`/chat-rooms/new`)로 이동
- 채팅방 이름 입력 필드에 값 입력
- 제출 버튼 클릭

#### 처리
1. 클라이언트 측 채팅방 이름 유효성 검증 (1~50자)
2. 서버에 채팅방 생성 요청 전송 (`POST /api/chat-rooms`)
3. 채팅방 테이블에 신규 레코드 삽입 (생성자 ID 포함)
4. 생성 완료 처리

#### 출력
- **성공**: 홈 페이지(`/`)로 리다이렉트, 생성된 채팅방이 목록에 표시
- **실패 (유효성 검증)**: 입력 필드 아래 에러 메시지 표시
- **실패 (서버 에러)**: 서버 에러 메시지 표시, 재시도 안내

#### 엣지케이스
- 빈 채팅방 이름 입력: 필수 입력 에러 메시지 표시
- 채팅방 이름 길이 초과 (50자 이상): 최대 길이 초과 에러 메시지 표시
- 중복된 채팅방 이름: 허용 (제약 조건 없음) 또는 중복 경고 메시지
- 취소 버튼 클릭: 홈 페이지로 이동, 입력 내용 삭제
- 네트워크 연결 끊김: 요청 실패 에러 메시지 표시

---

### 2.3 채팅방 상세 조회

#### 입력
- 사용자가 채팅방 목록에서 채팅방 카드 클릭
- 채팅방 상세 페이지(`/chat-rooms/:id`)로 이동

#### 처리
1. 서버에 채팅방 정보 요청 전송 (`GET /api/chat-rooms/:id`)
2. 채팅방 존재 여부 확인
3. 채팅방 정보 및 메시지 목록 조회
4. UI에 렌더링

#### 출력
- **성공**: 채팅방 상세 페이지 표시
  - 헤더: 뒤로가기 버튼, 채팅방 이름
  - 메시지 목록
  - 하단 입력 영역
- **실패 (채팅방 없음)**: 404 에러 페이지 또는 에러 메시지 표시, 홈으로 이동 안내
- **실패 (서버 에러)**: 에러 메시지 표시, 재시도 버튼 제공

#### 엣지케이스
- 존재하지 않는 채팅방 ID 접근: 404 에러 또는 채팅방을 찾을 수 없다는 메시지
- 채팅방이 삭제된 경우: 채팅방이 삭제되었다는 메시지, 홈으로 이동
- 네트워크 연결 끊김: 에러 메시지 및 재시도 버튼
- 로딩 중: 스켈레톤 UI 또는 로딩 인디케이터 표시

---

## 3. 메시지 관련 플로우

### 3.1 메시지 목록 조회

#### 입력
- 사용자가 채팅방 상세 페이지(`/chat-rooms/:id`)에 접근

#### 처리
1. 서버에 메시지 목록 요청 전송 (`GET /api/chat-rooms/:roomId/messages`)
2. 해당 채팅방의 모든 메시지 조회 (시간 순 정렬)
3. 각 메시지의 발신자 정보, 답장 대상, 좋아요 정보 포함
4. UI에 렌더링
5. (선택) Supabase Realtime 구독으로 실시간 업데이트

#### 출력
- **성공**: 메시지 목록 표시
  - 각 메시지: 발신자 닉네임, 메시지 내용, 답장 대상 정보, 좋아요 개수 및 상태, 메시지 시간, 메뉴 버튼
- **빈 목록**: 첫 메시지를 보내라는 안내 메시지
- **실패**: 에러 메시지 표시, 재시도 버튼

#### 엣지케이스
- 메시지가 없는 경우: 빈 상태 UI 표시, 메시지 전송 안내
- 메시지가 많은 경우 (50개 이상): 무한 스크롤 또는 페이지네이션 적용
- 답장 대상 메시지가 삭제된 경우: 삭제된 메시지라는 표시 또는 답장 정보 생략
- 네트워크 연결 끊김: 에러 메시지 및 재시도 버튼
- 로딩 중: 스켈레톤 UI 또는 로딩 인디케이터 표시
- 실시간 업데이트 중 새 메시지 수신: 자동으로 목록에 추가, 스크롤 하단 유지

---

### 3.2 텍스트 메시지 전송

#### 입력
- 사용자가 채팅방 상세 페이지 하단 입력창에 텍스트 입력
- 전송 버튼 클릭 또는 Enter 키 입력

#### 처리
1. 입력값 유효성 검증 (1~1000자, 비어있지 않은지 확인)
2. 답장 대상 메시지 ID가 있는지 확인
3. 서버에 메시지 전송 요청 (`POST /api/chat-rooms/:roomId/messages`)
   - 요청 본문: 메시지 타입 (text), 내용, 답장 대상 ID (선택)
4. 메시지 테이블에 신규 레코드 삽입
5. 응답 처리

#### 출력
- **성공**: 메시지가 목록에 즉시 표시, 입력창 초기화, 답장 대상 상태 초기화
- **실패 (유효성 검증)**: 입력창 아래 에러 메시지 표시, 전송 차단
- **실패 (서버 에러)**: 에러 메시지 표시, 재시도 안내

#### 엣지케이스
- 빈 메시지 전송 시도: 전송 버튼 비활성화 또는 필수 입력 에러 메시지
- 메시지 길이 초과 (1000자 이상): 최대 길이 초과 에러 메시지, 글자 수 카운터 표시
- 네트워크 연결 끊김: 메시지 전송 실패 에러 메시지, 재시도 버튼
- 전송 중 페이지 이탈: 전송 취소 또는 백그라운드 완료 후 알림
- 답장 대상 메시지가 삭제된 경우: 답장 대상 정보 무시하고 일반 메시지로 전송

---

### 3.3 이모티콘 메시지 전송

#### 입력
- 사용자가 채팅방 상세 페이지 하단 이모티콘 버튼 클릭
- 이모티콘 선택 팝업 표시
- 원하는 이모티콘 클릭

#### 처리
1. 선택한 이모티콘 ID 확인
2. 답장 대상 메시지 ID가 있는지 확인
3. 서버에 메시지 전송 요청 (`POST /api/chat-rooms/:roomId/messages`)
   - 요청 본문: 메시지 타입 (emoticon), 이모티콘 ID, 답장 대상 ID (선택)
4. 메시지 테이블에 신규 레코드 삽입
5. 팝업 닫기 및 응답 처리

#### 출력
- **성공**: 이모티콘 메시지가 목록에 즉시 표시, 팝업 닫기, 답장 대상 상태 초기화
- **실패**: 에러 메시지 표시, 팝업 유지 또는 닫기

#### 엣지케이스
- 이모티콘 팝업 외부 클릭: 팝업 닫기, 전송 취소
- 이모티콘 로딩 실패: 에러 메시지 또는 기본 이모티콘 표시
- 네트워크 연결 끊김: 메시지 전송 실패 에러 메시지
- 이모티콘 선택 후 바로 취소: 팝업만 닫기, 전송 안 됨
- 답장 대상 메시지가 삭제된 경우: 답장 대상 정보 무시하고 일반 메시지로 전송

---

### 3.4 메시지 답장

#### 입력
- 사용자가 메시지 메뉴 버튼 클릭 (남의 메시지)
- 답장 버튼 클릭

#### 처리
1. 선택한 메시지를 답장 대상 메시지로 설정
2. 입력창 상단에 답장 대상 메시지 미리보기 UI 표시
   - 발신자 닉네임 + 메시지 내용 (텍스트 또는 이모티콘 표시)
   - X 버튼 (답장 취소)
3. 상태 업데이트

#### 출력
- **성공**: 답장 대상 메시지 미리보기가 입력창 상단에 표시
- **취소**: X 버튼 클릭 시 답장 대상 상태 초기화, 미리보기 UI 제거

#### 엣지케이스
- 답장 대상 메시지가 삭제된 경우: 메시지 삭제 시 답장 대상 상태 자동 초기화
- 다른 메시지에 답장 시도: 기존 답장 대상 덮어쓰기
- 내 메시지에 답장 시도: 허용 (답장 버튼이 표시되지 않으므로 발생하지 않음)
- 답장 대상 설정 중 페이지 이탈: 상태 초기화

---

### 3.5 메시지 좋아요 / 좋아요 취소

#### 입력
- **좋아요 추가**: 사용자가 메시지 메뉴 버튼 클릭 (남의 메시지) → 좋아요 버튼 클릭
- **좋아요 취소**: 사용자가 이미 좋아요한 메시지의 하트 아이콘 클릭

#### 처리
1. 현재 좋아요 상태 확인 (좋아요 여부)
2. **좋아요 추가**: 서버에 좋아요 추가 요청 (`POST /api/messages/:messageId/likes`)
   - 좋아요 테이블에 레코드 삽입 (사용자 ID + 메시지 ID)
3. **좋아요 취소**: 서버에 좋아요 취소 요청 (`DELETE /api/messages/:messageId/likes`)
   - 좋아요 테이블에서 레코드 삭제
4. 응답 처리 및 UI 업데이트

#### 출력
- **성공 (좋아요 추가)**: 하트 아이콘이 핑크색으로 변경, 좋아요 개수 +1
- **성공 (좋아요 취소)**: 하트 아이콘이 회색으로 변경, 좋아요 개수 -1
- **실패**: 에러 메시지 표시, 상태 롤백

#### 엣지케이스
- 중복 좋아요 시도: 서버에서 중복 방지 (UNIQUE 제약 조건), 에러 처리
- 이미 좋아요 취소된 상태에서 취소 시도: 서버에서 레코드 없음 처리, 에러 무시
- 네트워크 연결 끊김: 요청 실패 에러 메시지, 상태 롤백
- 내 메시지에 좋아요 시도: 허용 (좋아요 버튼이 표시되지 않으므로 발생하지 않음)
- 좋아요한 사용자가 탈퇴한 경우: 좋아요 개수는 유지, 사용자 정보만 표시 안 함

---

### 3.6 메시지 삭제 (단일)

#### 입력
- 사용자가 자신의 메시지 메뉴 버튼 클릭
- 삭제 버튼 클릭

#### 처리
1. 삭제 모드 진입
2. 해당 메시지를 삭제 대상 메시지로 설정 (파란색 체크)
3. 내 메시지에 체크박스 표시 (회색)
4. 하단 입력창을 '취소', '일괄삭제(1개)' 버튼으로 대체
5. 상태 업데이트

#### 출력
- **성공**: 삭제 모드 UI로 전환
  - 내 메시지에 체크박스 표시
  - 삭제 대상 메시지: 파란색 체크
  - 그 외 내 메시지: 회색 체크
  - 하단: 취소, 일괄삭제(1개) 버튼

#### 엣지케이스
- 남의 메시지 삭제 시도: 삭제 버튼이 표시되지 않으므로 발생하지 않음
- 삭제 모드 중 다른 메시지 삭제 버튼 클릭: 해당 메시지도 삭제 대상으로 추가

---

### 3.7 메시지 일괄 삭제

#### 입력
- 사용자가 삭제 모드에서 삭제 대상 메시지 선택 (체크박스 클릭하여 토글)
- '일괄삭제(N개)' 버튼 클릭

#### 처리
1. 삭제 대상 메시지 ID 수집
2. 서버에 일괄 삭제 요청 전송 (`DELETE /api/messages/batch`)
   - 요청 본문: 메시지 ID 배열
3. 메시지 테이블에서 해당 메시지 삭제
4. 삭제 모드 종료 및 메시지 목록 새로고침

#### 출력
- **성공**: 삭제된 메시지가 목록에서 제거, 삭제 모드 종료, 입력창 복원
- **실패**: 에러 메시지 표시, 삭제 모드 유지 또는 종료

#### 엣지케이스
- 삭제 대상 메시지가 없는 경우: 일괄삭제 버튼 비활성화
- 삭제 대상이 이미 삭제된 경우: 서버에서 무시, 에러 처리 안 함
- 네트워크 연결 끊김: 요청 실패 에러 메시지, 삭제 모드 유지
- 삭제 중 페이지 이탈: 삭제 취소 또는 백그라운드 완료 후 알림
- 취소 버튼 클릭: 삭제 모드 종료, 입력창 복원, 선택 상태 초기화

---

### 3.8 삭제 모드 취소

#### 입력
- 사용자가 삭제 모드에서 '취소' 버튼 클릭

#### 처리
1. 삭제 모드 종료
2. 삭제 대상 메시지 선택 상태 초기화
3. 체크박스 UI 제거
4. 하단 입력창 복원

#### 출력
- **성공**: 일반 모드로 전환, 입력창 표시, 체크박스 제거

---

## 4. 마이페이지 플로우

### 4.1 마이페이지 조회

#### 입력
- 사용자가 홈 페이지 헤더에서 마이페이지 링크 클릭
- 마이페이지(`/my-page`)로 이동

#### 처리
1. 서버에 사용자 정보 요청 전송 (`GET /api/users/me`)
2. 사용자 프로필 정보 조회 (이메일, 닉네임)
3. UI에 렌더링

#### 출력
- **성공**: 마이페이지 표시
  - 헤더: 뒤로가기 버튼
  - 이메일 (읽기 전용)
  - 닉네임 (수정 가능)
  - 저장 버튼
  - 로그아웃 버튼
- **실패**: 에러 메시지 표시, 홈으로 이동 안내

#### 엣지케이스
- 인증되지 않은 상태: 로그인 페이지로 리다이렉트
- 네트워크 연결 끊김: 에러 메시지 및 재시도 버튼
- 로딩 중: 스켈레톤 UI 또는 로딩 인디케이터

---

## 5. 네비게이션 및 인증 플로우

### 5.1 비인증 사용자 접근 제어

#### 입력
- 비로그인 사용자가 인증이 필요한 페이지 접근 시도 (홈, 채팅방 상세, 마이페이지 등)

#### 처리
1. 클라이언트 또는 서버에서 인증 상태 확인
2. 인증되지 않은 경우 리다이렉트 처리

#### 출력
- 로그인 페이지(`/login`)로 리다이렉트
- `redirectedFrom` 파라미터에 원래 접근하려던 페이지 URL 저장
- 로그인 완료 후 해당 페이지로 이동

#### 엣지케이스
- 로그인 후 `redirectedFrom` 파라미터가 없는 경우: 홈 페이지로 이동
- 로그인 후 `redirectedFrom` 파라미터가 비인증 페이지인 경우: 홈 페이지로 이동

---

### 5.2 인증된 사용자의 로그인/회원가입 페이지 접근

#### 입력
- 이미 로그인된 사용자가 로그인(`/login`) 또는 회원가입(`/signup`) 페이지 접근 시도

#### 처리
1. 인증 상태 확인
2. 이미 인증된 경우 리다이렉트 처리

#### 출력
- 홈 페이지(`/`)로 자동 리다이렉트

---

### 5.3 페이지 간 이동

#### 입력
- 사용자가 헤더의 링크, 버튼, 뒤로가기 버튼 등을 클릭

#### 처리
1. Next.js 클라이언트 라우팅 처리
2. 페이지 전환

#### 출력
- **성공**: 해당 페이지로 이동
- **실패**: 404 페이지 또는 에러 페이지 표시

#### 엣지케이스
- 존재하지 않는 경로 접근: 404 페이지 표시
- 뒤로가기 버튼 클릭: 이전 페이지로 이동 (브라우저 히스토리)
- 네트워크 연결 끊김: 페이지 로딩 실패 에러

---

## 6. 전역 엣지케이스

### 6.1 세션 만료

#### 시나리오
- 사용자가 서비스를 이용하던 중 세션이 만료됨

#### 처리
1. API 요청 시 401 Unauthorized 응답 수신
2. 인증 상태 초기화
3. 로그인 페이지로 리다이렉트

#### 출력
- 로그인 페이지로 이동
- 세션 만료 안내 메시지 표시

---

### 6.2 네트워크 오류

#### 시나리오
- 사용자가 네트워크 연결이 끊긴 상태에서 API 요청 시도

#### 처리
1. 요청 실패 감지
2. 재시도 로직 실행 (선택 사항)
3. 에러 상태 표시

#### 출력
- 네트워크 오류 메시지 표시
- 재시도 버튼 또는 자동 재시도 안내

---

### 6.3 서버 오류 (5xx)

#### 시나리오
- 서버에서 예상치 못한 오류 발생

#### 처리
1. 5xx 응답 수신
2. 에러 로깅 (서버 측)
3. 사용자에게 일반적인 에러 메시지 표시

#### 출력
- 서버 오류 안내 메시지
- 재시도 버튼 또는 홈으로 이동 안내

---

### 6.4 입력값 XSS 공격 시도

#### 시나리오
- 사용자가 악의적인 스크립트를 입력값에 포함

#### 처리
1. 클라이언트 및 서버 측 입력값 sanitization
2. HTML 태그 이스케이프 처리
3. 안전한 내용만 저장 및 표시

#### 출력
- 스크립트가 실행되지 않고 텍스트로 표시
- 필요 시 입력값 거부 및 에러 메시지

---

## 7. 실시간 업데이트 플로우 (선택 사항)

### 7.1 실시간 메시지 수신

#### 입력
- 사용자가 채팅방 상세 페이지에 머무르는 중
- 다른 사용자가 메시지 전송

#### 처리
1. Supabase Realtime 구독 활성화
2. 새 메시지 이벤트 수신
3. 메시지 목록에 새 메시지 추가
4. 스크롤 위치 조정 (하단에 있을 경우 자동 스크롤)

#### 출력
- 새 메시지가 목록에 즉시 표시
- 스크롤이 하단에 있으면 자동 스크롤, 그 외에는 "새 메시지" 알림 표시

#### 엣지케이스
- 사용자가 과거 메시지를 읽고 있는 경우: 자동 스크롤 안 함, 새 메시지 알림만 표시
- 연결 끊김: 재연결 시도, 실패 시 수동 새로고침 안내

---

### 7.2 실시간 좋아요/삭제 반영

#### 입력
- 사용자가 채팅방 상세 페이지에 머무르는 중
- 다른 사용자가 메시지에 좋아요 또는 메시지 삭제

#### 처리
1. Supabase Realtime 구독 활성화
2. 좋아요/삭제 이벤트 수신
3. 해당 메시지의 좋아요 개수 업데이트 또는 메시지 제거

#### 출력
- 좋아요 개수 실시간 업데이트
- 삭제된 메시지가 목록에서 제거

---
