## 2. 워크플로우 3단계 구조

### Research 단계
- 목적: 정보 수집·분석·정제
- 원칙: 큰 데이터는 코드/스크립트로 전처리 후 AI에게 전달
- 산출물: `research/` 폴더 내 분석 문서

### Planning 단계
- 목적: 계획 수립, 구조화, **사람의 검토·승인**
- 원칙: 사람이 승인하지 않으면 Implementation으로 넘어가지 않음
- 산출물: `workflow.md` (설계도)

### Implementation 단계
- 목적: 실제 실행 및 산출물 생성
- 원칙: workflow.md에 기술된 내용만 실행
- 산출물: 프로젝트별 결과물

---

## 3. 에이전트 역할 분류

### Orchestrator (팀장)
- SOT 파일 쓰기 권한 보유
- 전체 흐름 조율 및 품질 검증
- status.md 관리

### Worker Agent (팀원)
- 특정 단계의 실행 담당
- SOT 파일 읽기 전용
- 산출물 파일만 생성

### Interactive Agent (대화형)
- 사람과 주고받으며 진행
- 결정이 필요한 단계에 배치

### Auto Agent (자동형)
- 승인 없이 자동 실행
- 명확히 정의된 입출력만 처리

---

## 4. 팀 설계 원칙

```
Orchestrator
  ├→ Agent A: [역할 명시]
  ├→ Agent B: [역할 명시]
  └→ Agent C: [역할 명시]
```

- 한 에이전트가 너무 많은 역할을 맡지 않도록 분리
- 병렬 실행 가능한 것은 병렬로 (∥)
- 의존 관계가 있는 것은 순차로 (→)

---

## 5. 품질 보장 (2계층)

### L0 — Anti-Skip Guard
산출물 파일이 실제로 존재하고 내용이 있는지 확인.
"완료했다"는 보고보다 파일이 증명합니다.

### L1 — Verification Gate
기능적 목표를 100% 달성했는지 에이전트가 자기검증.
체크리스트 형태로 각 항목을 명시적으로 확인합니다.

---

## 6. 에러 처리 원칙

1. 에러 발생 시 조용히 넘어가지 않고 즉시 보고
2. 같은 방법으로 3번 이상 재시도하지 않음 (다른 접근법 시도)
3. 해결 불가 시 사람에게 명확히 보고 (무엇이, 왜 안 되는지)
