# Implementation 단계 프롬프트 템플릿

> 사용 시점: Planning 승인 후 실제 실행 시작
> 목적: workflow.md에 정의된 내용을 실제로 구현

---

## 기본 실행 템플릿

```
workflow.md에 따라 Implementation을 시작해줘.

## 현재 단계
Phase {N}: {단계명}

## 실행 조건
- SOT 파일 위치: {경로}
- 산출물 저장 경로: {경로}
- 완료 기준: {구체적 조건}

## 주의사항
- SOT 파일에서만 데이터를 읽는다
- 완료 후 status.md를 업데이트한다
- 오류 발생 시 즉시 보고한다
```

---

## 병렬 실행 템플릿

```
다음 두 작업을 병렬로 실행해줘.

## 작업 A: {이름}
- 입력: {파일 또는 데이터}
- 실행 내용: {구체적 지시}
- 산출물: {파일명과 경로}

## 작업 B: {이름}
- 입력: {파일 또는 데이터}
- 실행 내용: {구체적 지시}
- 산출물: {파일명과 경로}

두 작업 완료 후 각각 결과를 보고하고
status.md를 업데이트해줘.
```

---

## 에이전트 소환 템플릿

```
{에이전트명} 에이전트를 소환해서 다음 작업을 수행해줘.

## 에이전트 역할
{이 에이전트가 담당하는 작업}

## 입력 데이터
{파일 경로 또는 데이터}

## 출력 요구사항
- 형식: {Markdown / HTML / DOCX 등}
- 저장 경로: {경로}
- 품질 기준: {구체적 기준}

## 완료 보고
완료 후 다음 정보를 포함해서 보고:
- 생성된 파일 목록
- 주요 결정 사항
- 다음 단계를 위한 인수인계 사항
```

---

## 품질 검증 템플릿 (L1 Verification)

```
방금 생성한 산출물의 품질을 검증해줘.

## 검증 항목
- [ ] 파일이 실제로 생성되었는가 (경로 확인)
- [ ] 내용이 비어있지 않은가 (최소 {N}줄 이상)
- [ ] SOT 데이터와 일치하는가
- [ ] 요청한 형식에 맞는가
- [ ] 누락된 항목이 없는가

## 판정
- PASS: 모든 항목 통과 → 다음 단계 진행
- FAIL: 하나라도 실패 → 해당 항목만 재작업

결과를 보고하고 PASS/FAIL을 명확히 표시해줘.
```
