# Architecture Decision Records

## 철학
심플하되 빠짐없이 — Google 생태계 안에서 최소 복잡도로 완전한 수강관리를 구현한다.

---

### ADR-001: Google Apps Script 웹앱

**결정**: GAS 웹앱으로 전체 시스템을 구현한다.

**이유**:
- 구글드라이브/스프레드시트와 네이티브 연동 (추가 인증 불필요)
- 서버리스 — 별도 호스팅/배포 인프라 불필요
- 사용자가 요청한 "심플 구현"에 가장 부합

**트레이드오프**:
- 6분 실행 제한 (BatchRunner로 대응)
- iframe 샌드박스로 프론트엔드 제약
- 디버깅 도구 제한적

**대안 검토**:
| 대안 | 탈락 이유 |
|------|----------|
| Next.js + Vercel | 외부 서버, Google OAuth 설정 복잡 |
| Flutter Web | 오버엔지니어링, 스프레드시트 직접 접근 불가 |
| Google Workspace Add-on | 배포 심사 필요, UI 자유도 낮음 |
| PWA + Sheets API | REST API 인증 복잡, 서버 필요 |

### ADR-002: Google Spreadsheet를 DB로 사용

**결정**: 별도 DB 없이 Google Spreadsheet를 유일한 데이터 저장소로 사용한다.

**이유**:
- 관리자가 직접 시트에서도 데이터 확인/수정 가능
- 추가 비용 없음
- GAS에서 SpreadsheetApp으로 네이티브 접근

**트레이드오프**:
- 동시 쓰기 충돌 가능 (LockService로 대응)
- 복잡한 쿼리 불가 (인메모리 필터링)
- 1000만 셀 제한

**대안 검토**:
| 대안 | 탈락 이유 |
|------|----------|
| Firebase | 외부 서비스, 비용 발생, GAS 연동 복잡 |
| Cloud SQL | 서버 필요, 과도한 복잡성 |
| Apps Script JDBC | 외부 DB 필요 |

### ADR-003: NotebookLM 직접 연동 제외 (Out of Scope)

**결정**: NotebookLM API 직접 연동은 MVP 범위에서 제외한다. CSV/JSON 내보내기까지만 구현한다.

**이유**:
- 구글드라이브 계정(waveainetworks@gmail.com)과 NotebookLM 계정이 상이
- NotebookLM에 공식 REST API가 없음
- Claude Code MCP(mcp__notebooklm__)로 별도 브릿지 가능

**트레이드오프**:
- 수동으로 내보낸 파일을 NotebookLM에 업로드해야 함

### ADR-004: 동적 과제 관리

**결정**: 과제를 하드코딩하지 않고, 과제_정의 시트에서 동적으로 관리한다.

**이유**:
- 카테고리/클래스별로 과제가 다름
- 학기 중 과제 추가/수정 필요
- 과제 비중(weight)으로 가중 평균 계산 지원

**트레이드오프**:
- 과제 정의 변경 시 기존 현황 데이터와 정합성 유지 필요

### ADR-005: 파일명 패턴 기반 자동 분류

**결정**: Google Drive 내 응답 스프레드시트의 파일명을 파싱하여 category, class_level, target, region을 자동 추출한다.

**이유**:
- 기존 파일명에 분류 정보가 이미 포함되어 있음
- 수동 분류 없이 자동화 가능

**패턴**:
| 패턴 | 예시 | 추출 |
|------|------|------|
| A | (4월 목회자 통합신청서)(응답) | target=목회자 |
| B | (4월 일반 Class #1 & 3통합신청서)(응답) | target=일반, class=[1,3] |
| C | (3월 교회강의 목회자 Class#1 수강신청)(응답) | category=교회강의, target=목회자, class=1 |
| D | (3월 교회강의 일반 Class #1 수강신청)(응답) | category=교회강의, target=일반, class=1 |
| E | (4월 꿈별 교회강의 신청서)(응답) | region=꿈별, category=교회강의 |
| F | (4월 부산 교회강의 Class#1 수강신청서)(응답) | region=부산, category=교회강의, class=1 |

**트레이드오프**:
- 새 파일명 패턴 추가 시 파서 업데이트 필요
- 파싱 실패 시 MEDIUM 에러 로그 + 수동 분류 필요

**대안 검토**:
| 대안 | 탈락 이유 |
|------|----------|
| 수동 분류 | 매번 관리자 개입 필요 |
| 폴더 구조 기반 | 기존 폴더 구조가 일관되지 않음 |

### ADR-006: 헤더 텍스트 기반 컬럼 매핑

**결정**: 스프레드시트 컬럼을 인덱스가 아닌 헤더 텍스트의 키워드 매칭으로 매핑한다.

**이유**:
- 폼마다 컬럼 순서가 다름
- 헤더 텍스트에 한글 키워드가 포함되어 있어 매칭 가능
- 새 폼 추가 시 별도 설정 불필요

**트레이드오프**:
- 헤더에 키워드가 없는 경우 매핑 실패 (MEDIUM 에러)
- 동일 키워드가 여러 컬럼에 있으면 첫 번째 매칭 사용

### ADR-007: Soft Delete 정책

**결정**: 모든 삭제는 is_active = false로 처리하며, 물리적 행 삭제는 하지 않는다.

**이유**:
- 실수로 삭제한 데이터 복구 가능
- 감사 추적 용이
- 삭제 후에도 통계에서 참조 가능

**트레이드오프**:
- 시트 데이터 누적 (주기적 아카이브 고려)

---

### ADR-008: clasp CLI 로컬 개발

**결정**: clasp CLI로 로컬에서 개발하고 push로 배포한다.

**이유**:
- 로컬 IDE 사용 가능 (VS Code)
- Git 버전 관리 가능
- Jest 단위 테스트 실행 가능

**트레이드오프**:
- clasp login 필요 (초기 1회)
- .clasp.json에 프로젝트 ID 노출 주의

### ADR-009: LockService 동시성 제어

**결정**: 마스터 시트 쓰기 작업 시 LockService.getScriptLock()으로 직렬화한다.

**이유**:
- 다수 관리자 동시 접근 시 데이터 충돌 방지
- GAS 네이티브 기능으로 추가 의존성 없음

**트레이드오프**:
- 락 획득 실패 시 30초 대기 후 에러 (사용자에게 재시도 안내)

### ADR-011: SPA 시뮬레이션 패턴

**결정**: HTML Service의 iframe 내에서 해시 라우팅으로 SPA를 시뮬레이션한다.

**이유**:
- 페이지 전환 시 전체 리로드 방지
- 사용자 경험 개선
- 상태 유지 가능

**트레이드오프**:
- 브라우저 뒤로가기 제한적
- google.script.run 비동기 통신 필수

### ADR-012: CacheService 캐싱

**결정**: 자주 조회되는 데이터(대시보드 통계, 수강생 목록 등)를 CacheService로 캐싱한다.

**이유**:
- 스프레드시트 읽기 속도 개선
- 동일 요청 반복 시 서버 부하 감소

**트레이드오프**:
- 캐시 무효화 로직 필요 (데이터 변경 시)
- 100KB/항목 제한

### ADR-013: 기수 = 월 기반 자동 태깅

**결정**: 기수(cohort)를 파일명의 월 정보에서 자동 추출하여 YYYY-MM 형식으로 태깅한다.

**이유**:
- 기수 관리 자동화
- 월별 수강생 분리 조회 가능

**트레이드오프**:
- 파일명에 월 정보가 없는 경우 _config의 CURRENT_COHORT 사용

### ADR-014: Boolean 입력 정규화

**결정**: 폼 응답의 예/아니오 계열 입력을 통일된 Boolean으로 정규화한다.

**이유**:
- Google Forms에서 "예", "Yes", "네", "O" 등 다양한 형태로 입력됨
- 일관된 데이터 처리를 위해 입력 시점에서 정규화 필수

**매핑 테이블**:
- true: "예", "네", "Yes", "yes", "Y", "TRUE", "true", "1", "O", "o", "확인"
- false: "아니오", "아니요", "No", "no", "N", "FALSE", "false", "0", "X", "x"
- 빈 값: false
