# PRD: Wave Academy 수강관리 시스템

## 목표
구글드라이브 스프레드시트(수강신청 폼 응답)를 기반으로 강의별 수강생을 자동 분류하고, 과제 수행 체크와 학점 이수 현황을 관리하는 Google Apps Script 웹앱.

## 배경
Wave AI Networks는 교회·일반인 대상으로 생성형 AI 강의를 운영한다. 수강신청은 구글 폼으로 받고 있으며, 응답 데이터가 구글드라이브에 `.gsheet`로 자동 저장된다. 현재 수강생 관리는 수작업이며, 강의가 늘어남에 따라 분류·과제 추적·이수 판정의 자동화가 필요하다.

## 사용자

### 관리자 (1~3명)
- Wave Academy 운영진
- 수강생 분류 확인/보정, 과제 등록, 수강 완료 체크, 학점 부여
- 새 카테고리/클래스 생성, 설정 변경

### 열람자 (5~10명)
- 관계자 (강사, 협력 기관)
- 수강생 현황 조회만 가능, 데이터 수정 불가

## 핵심 기능

### F1. 수강신청 데이터 자동 수집

**정상 흐름:**
1. 관리자가 "스캔" 버튼 클릭 또는 매일 자동 트리거 실행
2. 지정된 폴더(루트 + `Wave_class 수강신청/`)에서 `(응답).gsheet` 파일 탐색
3. 각 시트의 데이터를 읽어서 마스터 시트에 병합
4. 이미 수집된 행은 건너뜀 (중복 방지)
5. 수집 결과 요약 표시 (신규 N명, 중복 스킵 N명, 오류 N건)

**원본 데이터 필드 (구글 폼 응답):**
| # | 필드명 | 필수 | 비고 |
|---|--------|------|------|
| 1 | 타임스탬프 | ✅ | 구글 폼 자동 생성 |
| 2 | 이메일 주소 | ✅ | 중복 판별 키 |
| 3 | 성함 | ✅ | |
| 4 | 연락처 (휴대전화) | ✅ | |
| 5 | 섬기시는 교회/기관명 | ✅ | |
| 6 | 직분 | ✅ | |
| 7 | 수강 희망 클래스 | ✅ | 복수 선택 가능 (통합신청서) |
| 8 | 선수 학습 확인 | ⬜ | Class2/3 신청자만 |
| 9 | AI 사용 빈도 | ⬜ | |
| 10 | 시급 도입 분야 | ⬜ | |
| 11 | 목표 | ⬜ | |
| 12 | 수강료 입금 여부 | ✅ | |
| 13 | 입금자명 | ⬜ | 입금 시에만 |
| 14 | 오픈채팅방 입장 여부 | ⬜ | |
| 15 | 개인정보 동의 | ✅ | |

**엣지케이스:**
- EC1-1: 통합신청서와 개별신청서의 컬럼 구조가 다름 → 필드 매핑 테이블로 처리
- EC1-2: 같은 수강생이 여러 폼에 중복 응답 → 이메일 + 클래스 조합으로 중복 판별
- EC1-3: 같은 이메일로 다른 클래스에 신청 → 정상 케이스 (복수 수강), 각각 별도 레코드
- EC1-4: 폼 응답 시트에 컬럼 순서가 다를 수 있음 → 헤더 텍스트 기반 매칭 (인덱스 기반 X)
- EC1-5: 응답 시트가 비어있음 (폼 생성만 하고 응답 0건) → 건너뛰고 로그
- EC1-6: 스프레드시트 접근 권한 없음 → 에러 로그 + 나머지 파일 계속 처리
- EC1-7: 파일명에 `(응답)` 없는 `.gsheet` (예: `GroupMailSender.gsheet`) → 무시
- EC1-8: 새 폴더에 신규 응답 파일 추가됨 → 스캔 대상 폴더 목록을 Config에서 관리
- EC1-9: 파일명에 `의 사본` 포함 → 사본 태그 제거 후 정상 파싱, 원본과 중복 주의
- EC1-10: 개인정보 동의가 "미동의"인 응답 → 수집하되 `consent = false` 플래그 + 관리자에게 알림, 개인정보 마스킹 강제
- EC1-11: 원본 시트에 헤더만 있고 데이터 행 없음 → 빈 시트로 간주, 스킵
- EC1-12: 원본 시트에 여러 탭(시트)이 있음 → 첫 번째 시트만 읽기 (구글 폼 응답은 항상 첫 시트)
- EC1-13: 행 중간에 빈 행이 있음 → 빈 행 무시하고 계속 읽기 (마지막 데이터 행까지)
- EC1-14: 수강료 입금 여부가 텍스트 다양 ("예", "네", "Y", "입금완료" 등) → 긍정 키워드 매칭으로 Boolean 변환

**에러 핸들링:**
| 에러 | 처리 | 사용자 알림 |
|------|------|------------|
| 스프레드시트 열기 실패 | 스킵, 다음 파일 계속 | "⚠️ {파일명} 접근 불가 — 권한 확인 필요" |
| 헤더 컬럼 매칭 실패 | 스킵, 로그 기록 | "⚠️ {파일명} 컬럼 구조 인식 불가 — 수동 확인 필요" |
| API 할당량 초과 | 중단, 재시도 안내 | "⛔ API 한도 초과. 1분 후 재시도하세요" |
| 마스터 시트 쓰기 실패 | 중단 | "⛔ 마스터 시트 쓰기 오류. 시트 접근 권한 확인" |
| 타임스탬프 파싱 실패 | 원본 텍스트 그대로 저장 | 무음 처리 |

### F2. 강의별 수강생 자동 분류

**분류 체계:**
```
카테고리 (Level 1)
├── 교회강의
│   ├── Class#1 (파운데이션)
│   ├── Class#2 (심화)
│   └── Class#3 (활용)
├── Wave Academy
│   ├── Class#1
│   ├── Class#2
│   └── Class#3
├── 자격증과정
│   ├── 1급
│   └── 2급
└── 외부강의
    ├── 학교강의 (총신대, 한세대 등)
    ├── 교사대학
    └── 평생교육원
```

**분류 로직 (우선순위 순):**
1. **파일명 파싱** — 정규식으로 월, 대상, 클래스, 지역 추출
   - 패턴 A: `({월} {대상} Class#{N})` → 예: `(3월 교회 Class#1)`
   - 패턴 B: `({월} {대상} Class {N})` → 예: `(3월 일반 Class2)` (# 없음)
   - 패턴 C: `({월} {대상} Class #{N} & {M}통합)` → 예: `(4월 일반 Class #1 & 3통합신청서)`
   - 패턴 D: `({지역} Class#{N})` → 예: `(부산 Class#1)`, `(꿈별 Class#1)`
   - 패턴 E: `({월} {대상} 통합신청서)` → 예: `(4월 목회자 통합신청서)`
2. **응답 내 "희망 클래스" 필드** — 파일명으로 판별 불가 시 폴백
3. **수동 분류** — 자동 분류 실패 시 "미분류" 상태로 두고 관리자에게 알림

**대상 판별:**
| 키워드 | 분류 |
|--------|------|
| 목회자, 목클 | 목회자 |
| 일반, 일반인 | 일반 |
| 교회 | 교회 (성도) |
| 꿈별, 부산, 충남 등 | 지역 태그 추가 |

**엣지케이스:**
- EC2-1: 통합신청서에 복수 클래스 선택 → 선택된 클래스 수만큼 레코드 분리 생성
- EC2-2: 파일명에 대상 정보 없음 → "희망 클래스" 필드와 직분 필드로 추론
- EC2-3: 새로운 카테고리/지역 등장 → "미분류"로 저장 + 관리자에게 분류 요청 알림
- EC2-4: 파일명 `Class#` 뒤에 숫자가 아닌 텍스트 → 파싱 실패 → 수동 분류
- EC2-5: 같은 수강생이 카테고리를 이동 (예: 교회강의 → Wave Academy) → 이전 기록 유지, 새 레코드 추가
- EC2-6: 파일명에 이중 공백 있음 (예: `목회자  통합신청서`) → 정규식에서 `\s+`로 처리

**에러 핸들링:**
| 에러 | 처리 | 사용자 알림 |
|------|------|------------|
| 파일명 정규식 매칭 실패 | "미분류" 태그 | "📋 {파일명} 자동 분류 실패 — 수동 분류 필요" |
| 희망 클래스 필드 비어있음 | "미분류" | 스캔 결과에 포함 |
| 분류 규칙 충돌 (파일명 ≠ 응답 내용) | 파일명 우선, 플래그 표시 | "⚠️ {수강생} 분류 불일치 — 확인 필요" |

### F3. 과제 수행 관리

**정상 흐름:**
1. 관리자가 클래스를 선택
2. "과제 추가" → 과제명, 마감일(선택) 입력
3. 수강생 목록에 해당 과제 컬럼이 추가됨
4. 관리자가 수강생별로 체크박스 토글 → 완료 처리
5. 완료 시 자동으로 완료일 기록
6. 과제 완료율 실시간 계산

**과제 데이터 구조:**
| 필드 | 타입 | 설명 |
|------|------|------|
| 과제ID | String | `{클래스코드}_{순번}` (예: `WA_C1_01`) |
| 과제명 | String | 관리자 입력 |
| 클래스 | String | 소속 클래스 |
| 마감일 | Date | 선택 (null 허용) |
| 생성일 | Date | 자동 |
| 순서 | Number | 표시 순서 |

**엣지케이스:**
- EC3-1: 과제 추가 후 이미 완료 체크한 수강생이 있는 상태에서 과제 삭제 → 삭제 확인 팝업 + 관련 체크 데이터도 삭제
- EC3-2: 과제명 중복 → 허용하되 과제ID로 구분 (같은 이름 과제 존재 가능)
- EC3-3: 과제 0개인 클래스 → 과제 완료율 N/A 표시, 이수 판정에서 과제 조건 스킵
- EC3-4: 수강생이 클래스 변경됨 → 기존 클래스 과제 기록 보존, 새 클래스 과제는 미완료 초기화
- EC3-5: 과제 추가 시 기존 수강생 자동으로 미완료 초기화
- EC3-6: 마감일 지난 미완료 과제 → 시각적 강조 (빨간색)
- EC3-7: 과제명에 특수문자 포함 → 허용하되 스프레드시트 수식 깨짐 방지 위해 앞 `=`, `+`, `-`, `@` 이스케이프

**에러 핸들링:**
| 에러 | 처리 | 사용자 알림 |
|------|------|------------|
| 과제 추가 시 시트 컬럼 한도 초과 | 차단 | "⛔ 과제 수가 시트 한도에 도달했습니다" |
| 체크박스 토글 시 동시 편집 충돌 | 마지막 쓰기 우선 (last-write-wins) | 무음 (드문 케이스) |
| 과제 삭제 중 시트 오류 | 롤백 시도, 실패 시 수동 안내 | "⚠️ 과제 삭제 중 오류. 시트에서 직접 확인하세요" |

### F4. 수강 완료 및 학점 카운팅

**이수 판정 기준:**
| 조건 | 가중치 | Pass 기준 |
|------|--------|-----------|
| 수강 완료 (출석) | 필수 | 반드시 Y |
| 과제 완료율 | 선택 | 60% 이상 (관리자 설정 가능) |
| 수강료 입금 | 필수 | 반드시 Y |

**판정 로직:**
```
IF 수강완료 == N → "진행중"
ELSE IF 입금확인 == N → "미이수 (미입금)"
ELSE IF 과제 0개 → "이수" (과제 조건 없음)
ELSE IF 과제완료율 >= 이수기준 → "이수"
ELSE → "미이수 (과제 미달)"
```

**대시보드 통계:**
- 카테고리별 총 수강생 수
- 클래스별 이수/미이수/진행중 인원
- 클래스별 이수율 (%)
- 전체 이수율

**엣지케이스:**
- EC4-1: 이수 기준 변경 시 기존 판정 재계산 여부 → 관리자에게 확인 후 일괄 재계산
- EC4-2: 수강 완료를 체크했다가 다시 해제 → 이수 판정도 "진행중"으로 롤백
- EC4-3: 입금 상태가 나중에 Y로 변경 → 자동 재판정
- EC4-4: 한 수강생이 여러 클래스 수강 → 클래스별 독립 판정, 전체 이수 현황에 클래스 수로 표시
- EC4-5: 이수기준 퍼센트가 0% → 출석 + 입금만으로 이수
- EC4-6: 이수기준 퍼센트가 100% → 모든 과제 완료 필수

**에러 핸들링:**
| 에러 | 처리 | 사용자 알림 |
|------|------|------------|
| 판정 계산 중 데이터 누락 | 해당 수강생 "판정불가" 표시 | "⚠️ {수강생} 데이터 불완전 — 확인 필요" |
| 일괄 재계산 중 타임아웃 (6분 제한) | 배치 분할 처리, 이어서 실행 | "⏳ 재계산 중... {N}/{전체}명 완료" |

### F5. 정제 데이터 출력

**출력 형태:**
1. **강의별 정리 시트** — 마스터 스프레드시트 내 클래스별 탭
2. **내보내기 스프레드시트** — NotebookLM 연동용 별도 파일
   - 카테고리별 1개 파일 (예: `Wave_Academy_정제_2026-04.gsheet`)
   - 시트 구성: 수강생 요약, 과제 현황, 이수 통계

**NotebookLM 연동 프로세스 (시스템 범위 외, 참조용):**
1. 이 시스템이 정제 스프레드시트 생성
2. 관리자가 Claude Code에서 `mcp__notebooklm__` 도구로 해당 시트를 NotebookLM에 전송
3. 구글드라이브 계정 ≠ NotebookLM 계정이므로, 정제 시트를 NotebookLM 계정과 공유하거나 내보내기

**엣지케이스:**
- EC5-1: 내보내기 파일이 이미 존재 → 덮어쓰기 확인 팝업
- EC5-2: 데이터가 0건인 클래스 → 빈 시트 생성하되 "데이터 없음" 표시
- EC5-3: 내보내기 중 타임아웃 → 카테고리별 분할 내보내기

**에러 핸들링:**
| 에러 | 처리 | 사용자 알림 |
|------|------|------------|
| 내보내기 중 시트 생성 실패 | 중단, 기존 파일 보존 | "⛔ 내보내기 실패. 드라이브 용량 확인" |
| 내보내기 대상 데이터 0건 | 빈 파일 생성 안 함 | "ℹ️ 내보내기 대상 데이터 없음" |
| 드라이브 용량 부족 | 중단 | "⛔ 구글 드라이브 용량 부족" |

---

### F6. 검색 및 필터

**정상 흐름:**
1. 대시보드 또는 클래스 뷰에서 검색바/필터 사용
2. 실시간 필터링 (클라이언트 사이드) 또는 서버 사이드 검색

**검색 대상 필드:** 성함, 이메일, 소속(교회/기관명)

**필터 옵션:**
| 필터 | 값 |
|------|-----|
| 카테고리 | 전체 / 교회강의 / Wave Academy / 자격증과정 / 외부강의 |
| 클래스 | 전체 / Class#1 / Class#2 / Class#3 |
| 기수(월) | 전체 / 2026-03 / 2026-04 / ... |
| 대상 | 전체 / 목회자 / 일반 / 교회 |
| 지역 | 전체 / 본부 / 부산 / 충남 / 꿈별 / ... |
| 이수 상태 | 전체 / 이수 / 미이수 / 진행중 / 판정불가 |
| 입금 상태 | 전체 / 입금완료 / 미입금 |
| 분류 상태 | 전체 / 자동분류 / 수동분류 / 미분류 |

**엣지케이스:**
- EC6-1: 검색어가 빈 문자열 → 전체 결과 반환
- EC6-2: 한글 초성 검색 → MVP 범위 외 (정확 매칭만)
- EC6-3: 필터 복수 조합 → AND 조건으로 결합
- EC6-4: 결과 0건 → "조건에 맞는 수강생이 없습니다" 표시
- EC6-5: 대량 결과 (500명+) → 페이지네이션 (50행/페이지)

---

### F7. 수강생 수동 추가/편집

**정상 흐름:**
1. 관리자가 "수강생 추가" 버튼 클릭
2. 필수 정보 입력 (성함, 이메일, 소속, 카테고리, 클래스)
3. 마스터 시트에 레코드 추가 (classification_method = "manual")

**편집 가능 필드 (관리자만):**
- 카테고리, 클래스, 지역, 대상 (분류 수정)
- 입금 확인, 수강 완료 (상태 변경)
- 비활성화 (soft delete)

**엣지케이스:**
- EC7-1: 수동 추가 시 이메일 중복 → 동일 클래스면 경고, 다른 클래스면 허용
- EC7-2: 필수 필드 누락 → 저장 차단 + 누락 필드 하이라이트
- EC7-3: 분류 수정 시 기존 과제 기록 → 이전 클래스 과제는 보존, 새 클래스 과제는 미완료 초기화
- EC7-4: 비활성화된 수강생 재활성화 → "재활성화" 버튼 제공

**에러 핸들링:**
| 에러 | 처리 | 사용자 알림 |
|------|------|------------|
| 이메일 형식 오류 | 저장 차단 | "이메일 형식이 올바르지 않습니다" |
| 마스터 시트 쓰기 실패 | 롤백 | "⚠️ 저장 실패. 다시 시도하세요" |

### F8. 초기 설정 (최초 실행)

**최초 실행 흐름:**
1. 웹앱 최초 접근 시 마스터 스프레드시트 존재 여부 확인
2. 없으면 자동 생성: 마스터 시트 + 모든 시스템 시트 (_config, _log, _scan_history 등)
3. _config 시트에 기본값 세팅
4. 관리자에게 설정 페이지로 안내 (스캔 대상 폴더 ID, 관리자/열람자 이메일 입력)

**_config 시트 설정 항목:**
| 키 | 기본값 | 설명 |
|-----|--------|------|
| `master_sheet_id` | 자동 생성 | 마스터 스프레드시트 ID |
| `scan_folder_ids` | `[]` | 스캔 대상 폴더 ID 목록 (JSON 배열) |
| `scan_include_root` | `true` | 드라이브 루트도 스캔할지 |
| `admin_emails` | `[소유자 이메일]` | 관리자 이메일 목록 |
| `viewer_emails` | `[]` | 열람자 이메일 목록 |
| `pass_threshold` | `60` | 이수 기준 과제 완료율 (%) |
| `page_size` | `50` | 테이블 페이지당 행 수 |
| `auto_scan_enabled` | `true` | 매일 자동 스캔 활성화 |
| `auto_scan_hour` | `2` | 자동 스캔 실행 시각 (0~23) |
| `export_folder_id` | `null` | 정제 시트 저장 폴더 (null이면 루트) |
| `archive_threshold` | `1000` | 아카이브 분리 기준 행 수 |
| `masking_enabled` | `true` | 열람자 개인정보 마스킹 |

**엣지케이스:**
- EC8-1: 마스터 시트가 실수로 삭제됨 → 재생성 + 경고 "기존 데이터 유실됨"
- EC8-2: 설정 값이 유효하지 않음 (예: pass_threshold = 150) → Validator가 0~100 범위 강제
- EC8-3: scan_folder_ids에 접근 불가한 폴더 ID → 스캔 시 해당 폴더 스킵 + 경고 로그
- EC8-4: 관리자 이메일 목록이 비어있음 → 스크립트 소유자를 기본 관리자로 자동 추가

### F9. 기수(코호트) 관리

**개념:**
같은 Class#1이라도 3월반과 4월반은 별개의 기수. 기수는 `{연도}-{월}` 형식으로 표현.

**정상 흐름:**
- 수집 시 파일명의 월 정보로 자동 기수 태깅
- 대시보드에서 기수별 필터링 가능
- 이수 통계는 기수별로 독립 집계

**엣지케이스:**
- EC9-1: 파일명에 월 정보 없음 (패턴 D: 지역만) → 파일 생성 날짜에서 추론
- EC9-2: 한 폼에 여러 달에 걸쳐 응답 (3월에 시작, 4월에도 응답 유입) → 파일명의 월을 기수로 사용 (응답 타임스탬프 아님)
- EC9-3: 기수 간 수강생 비교 → MVP 범위 외 (필터로 전환하여 조회)

## MVP 제외 사항
- NotebookLM 직접 API 연동 (계정 상이 → Claude Code MCP로 별도 처리)
- 수강생 본인 자가 입력/조회 포털
- 수강료 결제 시스템 연동
- 이메일/카카오 자동 알림 발송
- 수료증/성적 증명서 PDF 발급
- 강의 자료 관리 (이미 Wave 강의 폴더에서 관리 중)
- 강사 평가 시스템
- 모바일 네이티브 앱 (웹앱 반응형으로 대체)

## 비기능 요구사항

### 성능
- 스캔: 50개 스프레드시트 처리 < 3분
- 웹앱 페이지 로드 < 3초
- 체크박스 토글 응답 < 1초
- Apps Script 실행 시간 제한: 6분/실행 → 대량 작업은 배치 분할

### 확장성
- 수강생 1,000명까지 안정 동작
- 클래스 50개까지 지원
- 과제 클래스당 최대 20개

### 보안
- 접근: 구글 계정 기반, 웹앱 배포 시 "특정 사용자만"
- 원본 데이터: 읽기 전용, 수정 불가
- 관리자/열람자 역할 분리
- 개인정보 (연락처, 이메일): 열람자에게는 마스킹 표시

### 데이터 무결성
- 원본 스프레드시트 절대 수정 금지
- 수집 시 중복 방지 (이메일 + 클래스 + 타임스탬프 조합)
- 삭제 대신 "비활성" 플래그 (soft delete)
- 마스터 시트 백업: 내보내기 시 자동 스냅샷
