[작업 목적]                                                                                                                                   
한 문장: 현재의 "제품 실행(사용) 모드" 인터페이스를 **CLI** vs **브라우저 대시보드** 중 무엇으로 가야 하는지, 전수조사 기반의 의견을 제시한다.                                                                                        
                                                                                                                                                
[역할]                                                                                                                                        
10년간 개발자 도구 / 워크플로우 엔진 UX를 설계한 시니어.                                                                                      
판단 기준: 워크플로우의 본질에 어떤 인터페이스가 정합적인가.                                                                                  
인기/트렌드/일반론이 아닌, 이 프로젝트 고유의 성격이 기준이다.                                                                                
                                                                                                                                                
[전수조사 읽기 프로토콜 — 4단계]                                                                                                              
                                                                                                                                                
1차 — 본질(What/Why)                                                                                                                          
     워크플로우의 목적과 철학은 무엇인가?                         
     이 프로젝트가 "반드시 지키려는 것"과 "명시적으로 배제한 것"은?                                                                             
                                                                                                                                                
2차 — 연관 확장                                                                                                                               
     작동 방식: 실행이 어떻게 흐르는가(입력/처리/출력/상태 전환).                                                                               
     결과물 종류와 스타일: 무엇이 만들어지고, 어떤 형태로 사용자에게 전달되는가.                                                                
     사용자의 조작 빈도/지속 시간/집중도.                                                                                                       
                                                                                                                                                
3차 — 중간 보충                                                                                                                               
     SOT/RLM이 인터페이스 선택에 부과하는 제약은?                                                                                               
     실행 모드 진입점, 사용자 안내 모드, 선택지 노출 구조가                                                                                     
     CLI/대시보드 각각에 어떻게 맵핑되는가.                                                                                                     
                                                                                                                                                
4차 — [역방향] 없는 것 찾기                                                                                                                   
     판단에 필요하지만 문서/코드에 없는 정보는?                                                                                                 
     (예: 동시 세션 수, 오프라인 사용 여부, 로그/트레이스 가시화 요구,                                                                          
      협업자 유무, 결과물의 시각적 비중 등)                                                                                                     
     → "없는 것" 목록을 별도로 명시하라. 없으면 없다고 적어라.

[조사 결과]                                                     
  - 목적/철학: (1~2문장)
  - 작동 방식: (입력→처리→출력의 핵심 축)                                                                                                       
  - 결과물 종류와 스타일: (텍스트 중심인가 / 구조화된 상태인가 / 시각 산출물인가)                                                               
  - 사용자 상호작용 특성: (단발적 / 지속적 / 감시형 / 대화형)

  - 충돌 지점: (근거)

  - 이 워크플로우의 본질에 부합하는 지점: (근거)                                                                                                
  - 충돌 지점: (근거)                                             
                                                                                                                                                
[충돌 축]
두 선택지가 실제로 갈라지는 결정 축 2~3개만 뽑아라. (예: "상태의 지속적 가시화 필요성", "결과물의 시각적 비중", "SOT/RLM 노출 깊이", "사용자의 작업 리듬")                                                                                                   
                                                                                                                                                
[최종 의견]                                                                                                                                   
  - 권고: CLI / 브라우저 대시보드 / 하이브리드 중 하나.                                                                                         
  - 이유: 위 충돌 축에서 어느 쪽이 본질에 정합적인가.                                                                                           
  - 리스크: 이 권고가 틀릴 수 있는 조건.                                                                                                        
  - 판단 불가 영역: 4차에서 찾은 "없는 것" 중 결정에 영향을 주는 항목.                                                                          
                                                                                                                                                
[금지]                                                                                                                                        
  - 일반론("대시보드가 보통 더 직관적이다" 류) 금지.                                                                                            
  - 양비론("둘 다 장단점이 있다") 금지 — 반드시 한쪽으로 권고하거나,                                                                            
    하이브리드로 가는 명확한 구조적 이유를 제시하라.                                                                                            
  - 구현 코드/파일 수정 제안 금지. 이번 턴은 판단까지다.                                                                                        
  - 4차 역방향 읽기 생략 금지. "없는 것"이 진짜 없으면 없다고 명시하라.
