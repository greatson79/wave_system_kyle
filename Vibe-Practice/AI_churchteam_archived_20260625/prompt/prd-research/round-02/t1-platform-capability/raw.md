## Branch 1.1: Maximum Utilization (플랫폼 최대 활용 관점)

**관점**: "플랫폼이 제공하는 기능을 깊이 이해하면 외부 의존 없이 강력한 시스템을 만들 수 있다."

### 구현 가능 패턴 (12 에이전트 AI 목회 보조 시스템 기준)

| 패턴 | 가능 여부 | 구현 복잡도 | 로컬 실행 |
|-----|---------|-----------|---------|
| 단일 설교 파이프라인 (순차) | ✅ 가능 | 낮음 | LOCAL-OK |
| 슬래시 커맨드 → 에이전트 라우팅 | ✅ 가능 | 낮음 | LOCAL-OK |
| 12 에이전트 역할 분화 (Skills) | ✅ 가능 | 중간 | LOCAL-OK |
| Theology Filter (PostToolUse Hook) | ✅ 가능 | 중간 | LOCAL-OK |
| 3개 파이프라인 병렬 실행 (Task tool) | ✅ 가능 | 높음 | LOCAL-OK |
| 세션 간 상태 유지 (state.yaml) | ✅ 가능 (파일 기반) | 중간 | LOCAL-OK |
| 자동 트리거 (스케줄링) | ❌ 불가 | — | LOCAL-BLOCKED: Claude Code는 사용자 개시 전제, 크론 내장 없음 |
| 한국어 신학 용어 특화 필터 | ✅ 가능 (프롬프트 기반) | 높음 | LOCAL-OK |

### 플랫폼 기능 상세

**Hooks 시스템**
- 지원 이벤트: PreToolUse, PostToolUse, SessionStart, Stop, PreCompact, SessionEnd
- 조건 분기: 도구명 regex 매처 기반 (단순 패턴)
- 실행 가능 범위: 로컬 셸 스크립트, Python 스크립트

**Task tool (Sub-agents)**
- 독립 컨텍스트 생성 → 병렬 실행 가능
- 동시 실행 수 상한: 공식 문서 미명시 (실험적)
- 결과 통합: 파일 기반 (공유 메모리 없음)

**CLAUDE.md**
- 전체 세션에 자동 로드 → 크기 비례 컨텍스트 소비
- 계층 구조: 프로젝트 루트 + 서브디렉터리 계층 지원
- .claude/skills/ → 필요할 때 명시적 로드 (온디맨드)

### 강점 Top 3
1. 외부 의존 없음 → 이식성 최고
2. 슬래시 커맨드 진입점으로 목회자 사용 경험 단순화
3. Hooks + Skills 조합으로 12 에이전트 역할 완전 분화 가능

### 한계
- 자동 트리거 구조적 불가
- 12 에이전트 직렬 실행 시 단일 세션 컨텍스트 소진 위험 (추정 50k~100k 토큰/세션)

🅿️ 파킹 로트: 자동 스케줄링은 T4 Integration에서 cron(OS 기본) 연동으로 처리

## Branch 1.2: Limitation-Aware (한계 인식 관점)

**관점**: "플랫폼의 한계를 정확히 알아야 현실적인 설계가 가능하다."

### 구조적 한계 목록

| 한계 | 실제 영향 | 예측 가능성 | 로컬 실행 |
|-----|---------|-----------|---------|
| 컨텍스트 윈도우 (200k) | 설교 5단계 × 에이전트 다중 호출 시 소진 가능 | 예측 가능 | LOCAL-OK (파일 분할 우회) |
| 토큰 소비 한도 (Max 5배) | 하루 12 에이전트 전체 실행 시 한도 초과 가능 | 예측 가능 | LOCAL-OK (Phase 분리 우회) |
| 병렬 Task 수 상한 미명시 | 3개 파이프라인 동시 실행 안정성 미보증 | 예측 불가 | LOCAL-OK (단, 모니터링 필요) |
| Hook 조건 분기 한계 | 복잡한 신학 판단 로직 Hook 내 불가 | 예측 가능 | LOCAL-OK (프롬프트 위임) |
| 세션 간 상태 소멸 | 중단 시 이전 맥락 소실 | 예측 가능 | LOCAL-OK (state.yaml 우회) |
| 자동 트리거 불가 | 모든 실행은 사용자 개시 필수 | 구조적 불가 | LOCAL-BLOCKED |

### 가장 심각한 한계 Top 3
1. **컨텍스트 소진**: 설교 파이프라인 1회가 단일 세션 50~100k 토큰 소비 추정. 12 에이전트 전체 실행 시 중단 위험.
2. **병렬 Task 수 상한 불명**: 3개 파이프라인 동시 실행 실패 시 전체 세션 영향 가능.
3. **Hook 복잡 조건 불가**: Theology Filter의 신학 판단을 Hook 단독으로 수행 불가 → 반드시 프롬프트 기반 에이전트와 병행 필요.

### 우회 전략

| 한계 | 우회 전략 | 복잡도 | 로컬 실행 |
|-----|---------|-------|---------|
| 컨텍스트 소진 | 파이프라인 단계별 세션 분할 + 요약 체인 | 중간 | LOCAL-OK |
| 세션 상태 | state.yaml SOT 패턴 | 낮음 | LOCAL-OK |
| Hook 신학 판단 | 2중 방어 (1차: 프롬프트, 2차: 키워드 Hook) | 중간 | LOCAL-OK |
| 자동 트리거 | OS cron → 슬래시 커맨드 호출 스크립트 | 중간 | LOCAL-OK |

### 우회 불가 (구조적)
- Claude Code 단독 자동 실행: 구조적 불가, 외부 트리거 필수

🅿️ 파킹 로트: 실제 설교 파이프라인 토큰 소비량 측정 필요 (현재 추정치만 존재)
