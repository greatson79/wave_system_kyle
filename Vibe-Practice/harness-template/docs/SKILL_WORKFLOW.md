# 스킬 제작 워크플로우

이 문서는 하네스 프레임워크 위에서 스킬을 만드는 전체 단계와 각 단계의 프롬프트를 정의한다.

---

## 전체 흐름

```
기획 → 설계 → 점검(3회) → 구현
 ↓       ↓                   ↓
계획    계획              계획 보고
보고    보고              후 실행
후 실행 후 실행
```

각 단계(점검 제외)는 **실행 전 계획 보고 → 사용자 승인 → 실행** 순서를 따른다.

---

## 1단계: 기획 (`/skill-plan`)

### 목적
스킬이 해결하는 문제를 구조화하고, 입력/출력/경계/성공 기준을 확정한다.

### 프롬프트 순서

**[보고 프롬프트]** — 실행 전 사용자에게 보고
```
## 기획 계획 보고

스킬명 (가안): [이름]
파악한 목적: [한 줄]

기획 인터뷰 순서:
1. 스킬이 해결하는 문제
2. 입력 / 출력 / 트리거
3. 스킬의 경계 (하지 않는 것)
4. 성공 기준
5. 유사 스킬과의 차별점

산출물: docs/skill-brief.md 생성

승인하시면 인터뷰를 시작합니다.
```

**[인터뷰 프롬프트 Q1]**
```

- 스킬이 만들어내는 것 (출력):
- 언제 이 스킬을 부르는가, 커맨드명:
```

### 산출물

## 2단계: 설계 (`/skill-design`)

### 목적
기획서를 바탕으로 하네스 문서 5종과 Step 파일을 작성한다.

### 프롬프트 순서

**[보고 프롬프트]** — 실행 전 사용자에게 보고
```
## 설계 계획 보고

기획서 요약: [3줄]

작성할 문서:
- [ ] CLAUDE.md
- [ ] docs/PRD.md
- [ ] docs/ARCHITECTURE.md
- [ ] docs/ADR.md
- [ ] docs/UI_GUIDE.md (UI 있을 경우)

Step 분할 초안:
- Step 0: [기반 세팅]
- Step 1: [핵심 로직]
- Step N: [통합 검증]

확인이 필요한 판단:
1. [모호한 부분]
2. [기술 결정 필요 부분]

승인하시면 문서 작성을 시작합니다.
```

**[보완 질문 프롬프트]** — 최대 3개
```
설계를 위해 확인이 필요한 사항:

1. [질문 — 이 결정이 구조에 미치는 영향]
   → 제 가정: [대안]

2. [질문]
   → 제 가정: [대안]
```

**[문서 작성 순서]**
1. CLAUDE.md — 기술 스택 + 절대 규칙
2. docs/PRD.md — 기능 명세 + 엣지케이스 + 에러 처리
3. docs/ARCHITECTURE.md — 구조 + 데이터 흐름
4. docs/ADR.md — 기술 결정 근거
5. phases/0-mvp/ — Step 파일 초안

### 산출물
- `CLAUDE.md`
- `docs/PRD.md`
- `docs/ARCHITECTURE.md`
- `docs/ADR.md`
- `phases/0-mvp/index.json` + `step*.md`

## 3단계: 점검 (`/skill-review 1|2|3`)

계획 보고 없이 바로 체크리스트를 실행한다.

---

### 1차 점검: 문서 완성도 + 기능 완성도

**[점검 프롬프트]**
```
1차 점검을 시작합니다.

[A. 문서 완성도]
□ skill-brief.md: 목적/입출력/경계/성공기준 모두 기재
□ CLAUDE.md: 기술스택, CRITICAL 규칙 2개↑, 커맨드, placeholder 없음
□ PRD.md: 기능 번호, 시나리오, 엣지케이스 3행↑, 에러 처리, placeholder 없음
□ ARCHITECTURE.md: 디렉토리 트리, 데이터 모델, 흐름, placeholder 없음
□ ADR.md: ADR-001 이상, 결정/이유/트레이드오프/대안 모두 있음
□ Step 파일: 목표/지시/AC 있음

[B. 기능 완성도]
□ skill-brief.md의 모든 기능이 PRD.md에 F번호로 등록됨
□ 기획서의 성공 기준이 PRD의 AC에 반영됨
□ 기획서의 경계("하지 않는 것")가 PRD 제약/에러 처리에 명시됨
□ PRD 각 기능(F1, F2...)에 대응하는 모듈이 ARCHITECTURE에 존재함
□ PRD의 모든 기능이 최소 1개의 Step에 구현 지시로 포함됨
□ Step AC가 해당 기능의 성공 기준을 직접 검증함

[자동 확인]
grep -rE '\{\{[^}]+\}\}' . --include="*.md" | grep -v "SKILL.md" | grep -v "commands/"
```

**[보고 형식]**
```
## 1차 점검 결과

[A. 문서 완성도] 통과: N / 전체 N
[B. 기능 완성도] 통과: N / 전체 N

미통과:
- [ ] [항목] — [보완 방법]

placeholder 잔여: [있음/없음]

판정: 통과 / 보완 필요
```

### 2차 점검: 구조 파악 및 안전성

**[점검 프롬프트]**
```
2차 점검을 시작합니다.

확인 항목:
□ PRD 기능명 ↔ ARCHITECTURE 모듈명 일치
□ ADR 결정 ↔ CLAUDE.md 기술 스택 충돌 없음
□ Step 순서 ↔ ARCHITECTURE 데이터 흐름 일치
□ CRITICAL 규칙을 위반하는 Step 없음
□ 삭제/덮어쓰기/외부 API 있다면 ADR 근거 있음
□ 동시성 이슈 처리 명시됨
□ 각 Step 단독 실행 시 오류 처리 있음
□ 파일 크기 800줄 규칙 준수
□ 외부 의존성 ADR에 근거 있음
```

**[보고 형식]**
```
## 2차 점검 결과

문서 간 충돌:
- [항목] — [수정 방향]

안전성 위험:
- [항목] — [대응]

수정 필요 문서:
- [파일]: [내용]

판정: 통과 / 수정 후 재점검 필요
```

### 3차 점검: 엣지케이스 + 보완 + 오류

**[점검 프롬프트]**
```
3차 점검을 시작합니다.

확인 항목:
□ 입력 null / 빈값 / 잘못된 형식 처리
□ 데이터 0건 / 1건 / 대용량 처리
□ 권한 없는 접근 처리
□ 네트워크 / 외부 서비스 장애 처리
□ 동시 실행 / 중복 호출 처리
□ PRD 모든 기능 → ARCHITECTURE 모듈 대응 확인
□ Step AC가 PRD 성공 기준 커버
□ ADR이 모든 주요 결정 기록
□ 1·2차 지적 항목 수정 완료
□ 수정으로 인한 새 충돌 없음

[자동 확인]
grep -rE '\{\{[^}]+\}\}' . --include="*.md" | grep -v "SKILL.md" | grep -v "commands/"
python3 -c "import json; json.load(open('phases/0-mvp/index.json')); print('JSON valid')"
```

**[보고 형식]**
```
## 3차 점검 결과

엣지케이스 누락:
- [항목] — [추가 위치]

잠재 오류:
- [항목] — [수정 방법]

1·2차 미수정 항목:
- [항목]

최종 판정: 구현 진행 가능 / 추가 보완 필요
```

### 판정 기준
| 판정 | 조건 | 다음 |
|------|------|------|
| 통과 | 전체 통과, placeholder 0 | 다음 회차 또는 /skill-build |
| 보완 필요 | 1~3개 미통과 | 수정 후 재점검 |
| 재설계 필요 | 구조 충돌 또는 5개↑ 미통과 | /skill-design 으로 복귀 |

## 4단계: 구현 (`/skill-build`)

### 목적
3차 점검 통과 후 `execute.py`로 step을 순차 실행한다.

### 프롬프트 순서

**[보고 프롬프트]** — 실행 전 사용자에게 보고
```
## 구현 계획 보고

실행할 Phase: 0-mvp
총 Step 수: N개

Step 실행 순서:
| Step | 제목 | 산출물 | 의존성 |
|------|------|--------|--------|
| 0    | ...  | ...    | 없음   |
| 1    | ...  | ...    | Step 0 |

CLAUDE.md 핵심 제약:
- CRITICAL: [규칙 1]
- CRITICAL: [규칙 2]

실패 시 대응:
- 1~2회 자동 재시도
- 3회 실패 → status: error, 사용자 보고

추정 소요: 약 N분

승인하시면 execute.py를 실행합니다.
```

**[실행 커맨드]**
```bash
python3 scripts/execute.py 0-mvp
# 자동 push 포함 시:
python3 scripts/execute.py 0-mvp --push
```

**[Step 완료 보고 프롬프트]** — 각 step마다
```
Step N 완료
- 생성된 파일: [목록]
- AC 통과: Y / N개
- 다음 Step: [제목]
```

**[Step 실패 보고 프롬프트]**
```

- 오류: [error_message]
- 원인: [분석]
- 권장 대응:
  1. index.json에서 status → "pending", error_message 삭제
  2. 재실행: python3 scripts/execute.py 0-mvp
  또는
  - 설계 문제라면 /skill-design 으로 복귀
```

**[완료 검증 프롬프트]**
```
구현 완료 후 최종 검증:
```

## 단계 간 이동 규칙

```
기획 완료 → /skill-design
설계 완료 → /skill-review 1
1차 통과  → /skill-review 2
2차 통과  → /skill-review 3
3차 통과  → /skill-build
구현 완료 → /skill-review 3 (선택, 결과물 재검증)
```

재작업이 필요한 경우:
```
1차 점검 재설계 → /skill-design
2차 점검 재설계 → /skill-design
3차 점검 보완   → 문서 수정 후 /skill-review 3 재실행
```
