# PRD: 실시간 채팅 서비스

## 1. 제품 개요

### 1.1 제품 비전
누구나 쉽게 참여할 수 있는 오픈형 실시간 채팅 서비스로, 채팅방 참여 제한 없이 자유롭게 대화하고 소통할 수 있는 플랫폼을 제공합니다.

### 1.2 제품 목표
- 간단하고 직관적인 채팅 경험 제공
- 카카오톡과 유사한 친숙한 UI/UX 구현
- 텍스트 및 이모티콘을 활용한 다양한 표현 지원
- 답장 및 좋아요 기능을 통한 활발한 상호작용 촉진

### 1.3 기술 스택
- **Frontend**: Next.js 15, React, TypeScript, Tailwind CSS, shadcn-ui
- **Backend**: Hono.js (Next.js API Routes)
- **Database & Auth**: Supabase (PostgreSQL + Auth)
- **State Management**: React Query, Zustand
- **Form Management**: React Hook Form + Zod

### 2.1 내부 이해관계자
- **제품 책임자 (Product Owner)**: 제품 로드맵 및 우선순위 결정

### 2.2 외부 이해관계자
- **최종 사용자 (End Users)**: 채팅 서비스를 이용하는 모든 사용자
- **운영 관리자 (Operations)**: 채팅방 관리 및 모니터링

## 3. 포함 페이지

### 3.1 인증 페이지 (비로그인 사용자만 접근)
1. **로그인 페이지** (`/login`)
   - 이메일 + 비밀번호 입력
   - 회원가입 페이지로 이동 링크
   - Supabase Auth 연동

2. **회원가입 페이지** (`/signup`)
   - 닉네임, 이메일, 비밀번호, 비밀번호 확인 입력
   - 유효성 검증 (React Hook Form + Zod)
   - 로그인 페이지로 이동 링크

### 3.2 메인 페이지 (로그인 필수)
3. **홈 - 채팅방 목록** (`/`)
   - 헤더: 서비스 로고, 사용자 정보, 마이페이지 링크
   - 채팅방 목록 (카드 형태)
   - '채팅방 추가' 버튼 (상단 또는 플로팅 버튼)

4. **채팅방 추가** (`/chat-rooms/new`)
   - 채팅방 이름 입력 폼
   - 생성 완료 시 홈으로 이동

5. **채팅방 상세** (`/chat-rooms/:id`)
   - 카카오톡 스타일 레이아웃
   - 메시지 목록 (스크롤 가능)
   - 메시지 입력창 (하단 고정)
   - 이모티콘 선택 팝업
   - 메시지 액션 메뉴 (삭제, 답장, 좋아요)
   - 삭제 모드 UI

6. **마이페이지** (`/my-page`)
   - 헤더
   - 사용자 정보 표시 (이메일, 닉네임)
   - 닉네임 수정 폼
   - 로그아웃 버튼

## 4. 사용자 여정 (User Journey)

### 4.1 타겟 유저 세그먼트

#### Segment A: 신규 사용자
- **특징**: 서비스를 처음 이용하는 사용자
- **니즈**: 간편한 회원가입, 직관적인 첫 화면

#### Segment B: 활성 사용자
- **특징**: 정기적으로 채팅방을 이용하는 사용자
- **니즈**: 빠른 메시지 전송, 다양한 표현 수단, 원활한 상호작용

#### Segment C: 채팅방 생성자
- **특징**: 새로운 주제의 채팅방을 만드는 사용자
- **니즈**: 쉬운 채팅방 생성, 관리 기능

```
[로그인] → [홈] → [채팅방 입장] → [메시지 읽기] → [답장/좋아요] → [메시지 전송]

## 5. Information Architecture (IA)

### 5.1 IA Tree 구조

```

│   └── 회원가입 (/signup)
│
└── 🔐 인증 영역 (Authenticated)
    │
    ├── 홈 - 채팅방 목록 (/)
    │   ├── 헤더
    │   │   ├── 서비스 로고

## 6. 핵심 기능 명세

### 6.1 인증 및 사용자 관리

#### F-001: 회원가입
- **입력**: 닉네임, 이메일, 비밀번호, 비밀번호 확인
- **검증**:
  - 닉네임: 2~20자, 특수문자 제외
  - 이메일: 유효한 이메일 형식
  - 비밀번호: 8자 이상, 영문+숫자 조합
  - 비밀번호 확인: 비밀번호와 일치
- **처리**: Supabase Auth 회원가입 + 사용자 프로필 테이블에 닉네임 저장
- **결과**: 회원가입 완료 → 로그인 페이지로 이동

#### F-002: 로그인
- **입력**: 이메일, 비밀번호
- **처리**: Supabase Auth 로그인
- **결과**: 로그인 성공 → 홈 페이지로 이동 (또는 redirectedFrom 파라미터)

#### F-003: 로그아웃
- **위치**: 마이페이지
- **처리**: Supabase Auth 로그아웃
- **결과**: 로그인 페이지로 이동

#### F-004: 닉네임 수정
- **위치**: 마이페이지
- **입력**: 새로운 닉네임
- **검증**: 2~20자, 특수문자 제외
- **처리**: 사용자 프로필 테이블 업데이트
- **결과**: 저장 성공 메시지 표시

---

### 6.2 채팅방 관리

#### F-005: 채팅방 목록 조회
- **위치**: 홈 (`/`)
- **조회**: 모든 채팅방 목록 (최근 메시지 시간 기준 정렬)
- **표시 정보**: 채팅방 이름, 최근 메시지 미리보기, 최근 메시지 시간
- **액션**: 채팅방 클릭 → 채팅방 상세로 이동

#### F-006: 채팅방 생성
- **위치**: `/chat-rooms/new`
- **입력**: 채팅방 이름 (1~50자)
- **처리**: 채팅방 테이블에 신규 채팅방 생성
- **결과**: 생성 완료 → 홈으로 이동

---

### 6.3 메시지 전송 및 조회

#### F-007: 메시지 목록 조회
- **위치**: 채팅방 상세 (`/chat-rooms/:id`)
- **조회**: 해당 채팅방의 모든 메시지 (시간 순 정렬)
- **표시 정보**:
  - 발신자 닉네임
  - 메시지 내용 (텍스트 또는 이모티콘)
  - 답장 대상 메시지 (있는 경우)
  - 좋아요 개수 및 내 좋아요 여부
  - 메시지 시간
- **실시간 업데이트**: Supabase Realtime 구독 (선택 사항)

#### F-008: 텍스트 메시지 전송
- **위치**: 채팅방 상세 하단 입력창
- **입력**: 텍스트 (1~1000자)
- **처리**: 메시지 테이블에 신규 메시지 생성
  - 메시지 유형: `text`
  - 답장 대상 메시지 ID (있는 경우)
- **결과**: 메시지 목록에 즉시 표시

#### F-009: 이모티콘 메시지 전송
- **위치**: 채팅방 상세 하단 이모티콘 버튼
- **입력**: 이모티콘 선택
- **처리**: 메시지 테이블에 신규 메시지 생성
  - 메시지 유형: `emoticon`
  - 이모티콘 ID 저장
  - 답장 대상 메시지 ID (있는 경우)
- **결과**: 메시지 목록에 즉시 표시

---

### 6.4 메시지 상호작용

#### F-010: 메시지 답장
- **위치**: 메시지 메뉴 → 답장 버튼 (남의 메시지)
- **처리**:
  1. 답장 대상 메시지 설정
  2. 입력창 상단에 답장 대상 메시지 미리보기 표시
  3. 메시지 전송 시 답장 대상 메시지 ID 포함
- **취소**: 답장 미리보기 영역의 X 버튼 클릭

#### F-011: 메시지 좋아요
- **위치**: 메시지 메뉴 → 좋아요 버튼 (남의 메시지)
- **처리**:
  - 좋아요 테이블에 레코드 추가 (사용자 ID + 메시지 ID)
  - 메시지에 좋아요 개수 표시 업데이트
- **토글**: 이미 좋아요한 메시지는 좋아요 취소
- **표시**: 하트 아이콘 (내가 좋아요: 핑크, 그 외: 회색) + 좋아요 개수

#### F-012: 메시지 삭제 (단일)
- **위치**: 메시지 메뉴 → 삭제 버튼 (내 메시지)
- **처리**:
  1. 삭제 모드 진입
  2. 해당 메시지를 삭제 대상으로 설정 (파란색 체크)
  3. 내 메시지에 체크박스 표시 (회색)
  4. 하단에 '취소', '일괄삭제(1개)' 버튼 표시

#### F-013: 메시지 일괄 삭제
- **위치**: 삭제 모드에서 하단 '일괄삭제(N개)' 버튼
- **처리**:
  1. 체크된 메시지 ID 수집
  2. 메시지 테이블에서 해당 메시지 삭제
  3. 삭제 모드 종료 및 메시지 목록 새로고침
- **조건**: 삭제 대상 메시지가 1개 이상일 때만 버튼 활성화

## 8. API 명세

### 8.1 인증 (Supabase Auth)
- `POST /api/auth/signup` - 회원가입
- `POST /api/auth/login` - 로그인
- `POST /api/auth/logout` - 로그아웃

### 8.2 사용자 프로필
- `GET /api/users/me` - 내 프로필 조회
- `PATCH /api/users/me` - 닉네임 수정

### 8.3 채팅방
- `GET /api/chat-rooms` - 채팅방 목록 조회
- `POST /api/chat-rooms` - 채팅방 생성
- `GET /api/chat-rooms/:id` - 채팅방 상세 조회

### 8.4 메시지
- `GET /api/chat-rooms/:roomId/messages` - 메시지 목록 조회
- `POST /api/chat-rooms/:roomId/messages` - 메시지 전송 (텍스트/이모티콘)
- `DELETE /api/messages/:id` - 메시지 삭제 (단일)
- `DELETE /api/messages/batch` - 메시지 일괄 삭제

### 8.5 좋아요
- `POST /api/messages/:messageId/likes` - 좋아요 추가
- `DELETE /api/messages/:messageId/likes` - 좋아요 취소

## 9. 비기능 요구사항

### 9.1 보안
- 모든 API 엔드포인트는 인증된 사용자만 접근 가능 (Supabase Auth 세션 검증)
- 메시지 삭제는 본인의 메시지만 가능
- XSS 방지: 사용자 입력 sanitization

### 9.2 성능
- 메시지 목록 조회: 페이지네이션 또는 무한 스크롤 (50개 단위)

- 이미지/이모티콘 로딩: 레이지 로딩
- API 응답 시간: 평균 500ms 이하

### 9.3 사용성
- 모바일 반응형 디자인
- 카카오톡 스타일 UI/UX
- 직관적인 메시지 액션 (메뉴 버튼)
- 명확한 삭제 모드 UI (체크박스, 색상 구분)

### 9.4 확장성
- Supabase Realtime을 활용한 실시간 메시지 업데이트 (선택 사항)
- 이모티콘 추가/관리 기능 (향후 확장)
- 채팅방 검색 기능 (향후 확장)
- 메시지 검색 기능 (향후 확장)

## 10. 성공 지표 (Success Metrics)

### 10.1 사용자 지표
- **DAU (Daily Active Users)**: 일일 활성 사용자 수
- **신규 가입자 수**: 일일 신규 회원가입 수
- **회원가입 완료율**: (회원가입 완료 / 회원가입 시도) × 100

### 10.2 참여 지표
- **메시지 전송 수**: 일일 총 메시지 전송 수
- **채팅방 생성 수**: 일일 신규 채팅방 생성 수
- **평균 세션 시간**: 사용자 1인당 평균 체류 시간
- **메시지당 좋아요 비율**: (총 좋아요 수 / 총 메시지 수) × 100
- **답장 메시지 비율**: (답장 메시지 수 / 총 메시지 수) × 100

### 10.3 기술 지표
- **API 응답 시간**: 평균 응답 시간 < 500ms
- **에러율**: 전체 요청 대비 5xx 에러 비율 < 1%
- **페이지 로딩 시간**: First Contentful Paint < 1.5초

### 10.4 품질 지표
- **사용자 만족도**: NPS (Net Promoter Score)
- **버그 발생률**: 주요 기능별 버그 리포트 수
- **기능 사용률**: 각 기능별 사용 비율 (답장, 좋아요, 이모티콘, 삭제 등)

## 11. 제약사항 및 가정

### 11.1 제약사항
- 채팅방 참여 개념 없음: 모든 사용자가 모든 채팅방에 접근 가능
- 메시지 수정 불가: 한 번 전송된 메시지는 수정할 수 없음 (삭제만 가능)
- 파일 업로드 미지원: 텍스트 및 이모티콘 메시지만 지원
- 채팅방 삭제 불가: 채팅방 생성 후 삭제 기능 없음 (향후 확장 가능)

### 11.2 가정
- Supabase Auth 사용: 자체 인증 시스템 구축 안 함
- 클라이언트/서버 동일 인증: Supabase 세션 기반 인증 통일
- 이모티콘 사전 정의: 고정된 이모티콘 세트 사용 (DB 또는 코드에 정의)
- 실시간 업데이트 선택 사항: 초기 버전은 수동 새로고침, 이후 Realtime 적용 가능
