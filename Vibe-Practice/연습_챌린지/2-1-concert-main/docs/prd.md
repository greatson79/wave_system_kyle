# PRD: 콘서트 예약 플랫폼

## 제품 개요

### 제품명
콘서트 예약 플랫폼

### 목적
사용자가 간편하게 콘서트를 검색하고, 좌석을 선택하여 예약할 수 있는 웹 기반 플랫폼입니다. 별도의 로그인 절차 없이 휴대폰번호와 간단한 비밀번호만으로 예약을 생성하고 관리할 수 있습니다.

### 핵심 가치 제안
- **간편한 접근성**: 회원가입/로그인 없이 즉시 예약 가능
- **직관적인 좌석 선택**: 시각적 좌석 배치도를 통한 실시간 선택
- **빠른 예약 조회**: 휴대폰번호와 비밀번호만으로 예약 관리
- **투명한 가격 정보**: 좌석 등급별 차등 가격 제공

### 주요 기능
1. 예약 가능한 콘서트 목록 조회
2. 콘서트 상세 정보 확인
3. 실시간 좌석 선택 및 예약 (등급별 색상 표시)
4. 예약 정보 조회 및 취소 (좌석별 가격 및 총 금액 표시)

---

## Stakeholders

### Primary Stakeholders
- **최종 사용자 (콘서트 관람객)**: 콘서트를 예약하고 관리하는 일반 사용자
- **제품 관리자**: 제품 방향성 결정 및 우선순위 관리
- **개발팀**: 기능 구현 및 유지보수

### Secondary Stakeholders
- **콘서트 주최측**: 콘서트 정보를 등록하고 예약 현황을 관리 (향후 확장)
- **고객 지원팀**: 예약 관련 문의 및 문제 해결 (향후 확장)

---

## 포함 페이지

### 1. 홈 (콘서트 목록)
**경로**: `/`

**주요 기능**:
- 예약 가능한 콘서트 목록 표시
- 진행일 전날까지만 예약 가능한 콘서트 필터링
- 각 콘서트별 예약인원/정원 표시
- 콘서트 클릭 시 상세 페이지로 이동

**표시 정보**:
- 콘서트 제목
- 콘서트 일시
- 장소
- 예약 현황 (예: "45/320명")
- 썸네일 이미지 (선택사항)

---

### 2. 콘서트 상세
**경로**: `/concerts/:concertId`

**주요 기능**:
- 콘서트 상세 정보 표시
- 예약하기 버튼을 통한 예약 프로세스 시작

**표시 정보**:
- 콘서트 제목
- 상세 설명
- 공연 일시
- 장소
- 출연진
- 좌석 등급별 가격 정보 (S: 250,000원, P: 190,000원, A: 170,000원, R: 140,000원)
- 예약 가능 좌석 수
- 예약하기 CTA 버튼

---

### 3. 콘서트 예약
**경로**: `/concerts/:concertId/booking`

**단계 구성**:

#### 3-1. 좌석 선택 단계
**주요 기능**:
- 좌석 배치도 표시 (4x20 그리드 × 4구역 = 총 320석)
- 실시간 좌석 상태 표시 (빈 좌석 / 예약된 좌석)
- 좌석 등급별 색상 표시
  - S등급 (1-3행): 보라색 (#9333EA)
  - P등급 (4-7행): 하늘색 (#0EA5E9)
  - A등급 (8-15행): 초록색 (#10B981)
  - R등급 (16-20행): 주황색 (#F97316)
- 좌석 선택 (최대 4석)
- 선택된 좌석 우측 사이드바 표시
- 개별 좌석 선택 해제 기능

**좌석 배치**:
```
구역 A (4x20)  구역 B (4x20)
구역 C (4x20)  구역 D (4x20)
```

**우측 사이드바**:
- 남은 좌석 수
- 선택된 좌석 목록 (구역, 행, 열, 등급, 가격)
- 각 좌석별 X 아이콘 (선택 해제)
- 총 금액 표시
- 예약하기 버튼 (1석 이상 선택 시 활성화)

#### 3-2. 정보 입력 단계
**주요 기능**:
- 예약자 정보 입력 폼
- 예약 제출 전 좌석 상태 재검증
- 중복 예약 방지

**입력 필드**:
- 예약자명 (필수)
- 휴대폰번호 (필수, 형식: 010-XXXX-XXXX)
- 비밀번호 4자리 (필수, 숫자)

**검증 로직**:
1. 폼 제출 시 선택된 모든 좌석의 예약 상태 재확인
2. 하나라도 이미 예약된 좌석이 있으면:
   - 예약 실패
   - Alert: "이미 예약된 좌석입니다."
   - 좌석 선택 단계로 복귀
3. 모든 좌석이 예약 가능하면:
   - 예약 성공
   - 예약 완료 페이지로 이동

---

### 4. 예약 완료
**경로**: `/bookings/:bookingId/complete`

**주요 기능**:
- 예약 성공 메시지
- 예약 상세 정보 표시
- 예약 취소 기능

**표시 정보**:
- 예약 완료 확인 메시지
- 콘서트 정보 (제목, 일시, 장소)
- 예약자명
- 예약된 좌석 목록 (구역, 행, 열, 등급, 가격)
- 총 결제 금액
- 예약번호 (선택사항)
- 예약취소 버튼

---

### 5. 예약 조회
**경로**: `/bookings/search`

**주요 기능**:
- 예약 정보 조회
- 예약 목록 표시
- 예약 취소 기능

**입력 필드**:
- 휴대폰번호 (필수)
- 비밀번호 4자리 (필수)

**조회 결과**:
- 해당 정보로 예약된 모든 예약 건 표시
- 각 예약 건별:
  - 콘서트 정보
  - 예약 일시
  - 좌석 정보 (구역, 행, 열, 등급, 가격)
  - 총 결제 금액
  - 예약취소 버튼

## 사용자 여정

### 타겟 유저 Segment

#### Primary Segment: 일반 콘서트 관람객
- **연령**: 20-40대
- **특징**: 간편하고 빠른 예약을 선호
- **니즈**: 복잡한 회원가입 없이 즉시 예약
- **기술 수준**: 기본적인 웹 사용 능력

#### Secondary Segment: 단체 예약자
- **특징**: 여러 좌석을 한번에 예약 (최대 4석)
- **니즈**: 인접 좌석 선택 및 빠른 예약 확정

## IA (Information Architecture)

```
콘서트 예약 플랫폼
│
├── 홈 (/)
│   └── 콘서트 목록
│       ├── 콘서트 카드 1 → [클릭] → 콘서트 상세
│       ├── 콘서트 카드 2 → [클릭] → 콘서트 상세
│       └── 콘서트 카드 N → [클릭] → 콘서트 상세
│
├── 콘서트 상세 (/concerts/:concertId)
│   ├── 콘서트 정보
│   ├── 좌석 등급별 가격 정보
│   └── [예약하기 버튼] → 콘서트 예약
│
├── 콘서트 예약 (/concerts/:concertId/booking)
│   ├── [단계 1] 좌석 선택
│   │   ├── 좌석 배치도 (등급별 색상 표시)
│   │   │   ├── 구역 A (4×20)
│   │   │   ├── 구역 B (4×20)
│   │   │   ├── 구역 C (4×20)
│   │   │   └── 구역 D (4×20)
│   │   │
│   │   └── 우측 사이드바
│   │       ├── 남은 좌석 수
│   │       ├── 선택된 좌석 목록 (등급, 가격 포함)
│   │       ├── 총 금액 표시
│   │       └── [예약하기 버튼] → 정보 입력 단계
│   │
│   └── [단계 2] 정보 입력
│       ├── 예약자명 입력
│       ├── 휴대폰번호 입력
│       ├── 비밀번호 4자리 입력
│       └── [제출] → 예약 완료 또는 실패 Alert
│
├── 예약 완료 (/bookings/:bookingId/complete)
│   ├── 예약 정보 표시
│   ├── 좌석별 가격 및 총 금액 표시
│   └── [예약취소 버튼]
│
└── 예약 조회 (/bookings/search)
    ├── 조회 폼
    │   ├── 휴대폰번호 입력
    │   └── 비밀번호 4자리 입력
    │
    └── 예약 목록 결과
        ├── 예약 1
        │   ├── 콘서트 정보
        │   ├── 좌석 정보 (등급, 가격)
        │   ├── 총 금액
        │   └── [예약취소 버튼]
        │
        └── 예약 N
            ├── 콘서트 정보
            ├── 좌석 정보 (등급, 가격)
            ├── 총 금액
            └── [예약취소 버튼]
```

### 네비게이션 구조

```
글로벌 네비게이션 (헤더)
├── 로고 → 홈
├── 콘서트 목록 → 홈
└── 예약 조회 → 예약 조회 페이지

페이지별 네비게이션
├── 홈: 글로벌 네비게이션만
├── 콘서트 상세: 글로벌 네비게이션 + 뒤로가기
├── 콘서트 예약: 글로벌 네비게이션 + 뒤로가기 + 단계 표시
├── 예약 완료: 글로벌 네비게이션 + 홈으로 가기
└── 예약 조회: 글로벌 네비게이션
```

## 기술적 요구사항

### 비기능적 요구사항

#### 1. 성능
- 페이지 로드 시간: 3초 이내
- 좌석 선택 반응 시간: 100ms 이내
- 동시 예약 처리: 최소 100명 동시 접속 지원

#### 2. 보안
- 비밀번호 4자리 해싱 처리
- 개인정보(휴대폰번호) 암호화 저장
- XSS 방지
- CSRF 방지

#### 3. 가용성
- 예약 시스템 가동률: 99% 이상
- 좌석 중복 예약 방지 (Race Condition 처리)

#### 4. 사용성
- 반응형 디자인 (모바일, 태블릿, 데스크톱)
- 접근성 준수 (WCAG 2.1 AA 레벨)
- 브라우저 호환성: Chrome, Safari, Firefox, Edge 최신 2개 버전

## 제약사항 및 가정

### 제약사항
1. 로그인/회원가입 기능 없음 (비로그인 사용)
2. 한번에 최대 4석까지만 예약 가능
3. 진행일 전날까지만 예약 가능
4. 총 320석 (4×20 × 4구역) 고정
5. 좌석 등급 4단계 (S, P, A, R) 고정

### 가정
1. 결제 기능은 포함하지 않음 (향후 확장)
2. 콘서트 등록/관리 기능은 별도 관리자 시스템에서 처리
3. 예약 확인 이메일/SMS 발송 기능은 포함하지 않음 (향후 확장)
4. 예약 시간 제한 없음 (향후 추가 고려)
5. 좌석 등급별 가격은 모든 콘서트에 동일하게 적용

## 성공 지표

### KPI
1. **예약 완료율**: (예약 완료 수 / 예약 시도 수) × 100
   - 목표: 80% 이상

2. **평균 예약 소요 시간**: 홈 진입부터 예약 완료까지 시간
   - 목표: 3분 이내

3. **좌석 판매율**: (예약된 좌석 수 / 전체 좌석 수) × 100
   - 목표: 콘서트당 70% 이상

4. **예약 취소율**: (취소된 예약 수 / 전체 예약 수) × 100
   - 목표: 10% 이하

5. **등급별 좌석 판매율**: 각 등급별 예약률
   - 목표: S등급 90% 이상, P등급 80% 이상

### 사용자 만족도
- 예약 프로세스 만족도: 4.0/5.0 이상
- 좌석 선택 편의성: 4.0/5.0 이상
- 가격 정보 명확성: 4.0/5.0 이상
