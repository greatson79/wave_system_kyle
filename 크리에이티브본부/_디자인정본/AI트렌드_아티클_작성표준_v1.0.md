## ③ 본문 구조 표준

### H1 금지 (절대)

- **본문에 `# ` H1을 쓰지 않는다.** 사유: frontmatter `title`이 레이아웃에서 페이지 제목으로 렌더되므로 본문 H1은 제목 이중 렌더가 된다.
- 실측: **10편 중 9편 H1=0**. 유일한 위반 = 2026-07-16-mcp-agent-reliability(H1 1회 — title 전문을 본문 17행에 중복). 이 1편이 곧 금지 사유의 실증 사례다. 섹션 최상위는 항상 `##`(H2)부터.

### 도입부

- **산문 도입 직행**: 10편 중 9편이 블록쿼트·메타 블록 없이 첫 단락 산문으로 시작 (ai-agent-howto "신입 직원에게 일을 맡긴다고 해보자", agent-infra "지난 한 주는 조용하지 않았습니다" 등).
- 도입 1~3단락 안에 (a) 후킹(구체 사건·수치·비유) (b) 이 글이 다룰 범위 선언이 온다 — 10/10 공통.
- 블록쿼트 메타정보(분류/기준 자료/작성일/면책) 도입 블록은 **금지** — 실측 1/10(mcp-0716)에서만 발견된 이탈 패턴 (⑧ 참조).

### 섹션 구성

- **H2 개수: 4~9개** (실측 최소 4: multi-agent·ai-tips·mcp-0716 / 최대 9: ai-agent-howto·gpt-5-6). 참고자료 H2/H3 포함 수치.
- H3는 선택 — 4/10만 사용 (ai-agent-howto 5개: "원칙 N" 하위 구조 / gpt-5-6·claude-cloud·codex-sites 각 1개: 참고자료 블록 제목).
- 번호형 H2("## 1. …")가 다수 관례: 6/10 (ai-tips "팁 N", agent-infra, 0707, claude-cloud, codex-sites 등).
- 수평선 `---` 섹션 구분: 5/10 사용 (ai-tips, agent-infra, fable-5, mcp-0716 본문 + 다수 편의 말미 면책 앞) — 선택.

### 마무리 섹션 (필수)

- **10/10 전 편이 명시적 마무리를 갖는다.** 실측 유형: "마치며 — 스스로 물어볼 세 가지"(ai-agent-howto) / "한 줄 정리"(multi-agent) / 공통 흐름 종합 단락(ai-tips) / "이번 주를 한 문장으로"(agent-infra) / "지금 당장 할 것 한 가지"(fable-5) / "> 한 줄 정리:" 인용(0707) / 전망 종합 H2(gpt-5-6) / "마무리"(claude-cloud, codex-sites) / "남는 질문"(mcp-0716).
- 표준: 마지막 H2는 **요약·행동 촉구·남는 질문 중 하나**로 닫는다. 단순 반복 요약보다 "독자가 오늘 할 한 가지" 또는 "다음에 살필 신호"가 우세 패턴.

### 면책·출처 블록 (말미)

- 말미 이탤릭 면책·작성 경위 1~2문장: 4/10 (ai-agent-howto, multi-agent, ai-tips, agent-infra — "*본 글은 … 기반으로 작성되었으며 … 정보 제공·교육 목적*").

1. **1차 출처 귀속**: 모든 핵심 주장·수치는 1차 출처(공식 문서·원논문·공식 발표)에 귀속시킨다. 2차 해석(인플루언서·블로그)은 반드시 "개인 분석"임을 명시 — 모범: agent-infra의 "⚠️ 중요 주석: … '30% 비용 증가'라는 단일 수치는 Simon Willison의 개인 분석입니다".
2. **범위한정 표현 의무**: 표본이 제한된 결과는 "이 감사 사례에서" · "검토한 이 문서 한 페이지에 없다는 것이 해당 기능이 아예 없다는 증명은 아니다"(claude-cloud §1) 식으로 범위를 문장 안에 못박는다.
3. **집계수 인용 시 출처 유효성 확인**: 오탐률·실패율·채택률 같은 집계 수치는 인용 전 출처 실재·표본·방법을 확인하고, 서로 다른 출처의 수치를 합산·평균 내지 않는다(mcp-0716 말미 면책이 모범: "각 논문 저자가 보고한 자체 실험 결과로 독립 재현이 확인된 것은 아닙니다").
4. **대표성 주장 금지**: 개별 사례·단일 감사·개인 후기를 업계 전체로 일반화하지 않는다 — 모범: claude-cloud "이 글은 한 사용자의 개인 사례를 근거로 재구성한 것이므로, 조직 전체에 그대로 일반화되는 결과는 아닙니다".
5. **불확실 항목 명시 블록**: 확인 실패 항목은 숨기지 말고 말미에 "불확실 항목 명시"로 드러낸다 (claude-cloud, codex-sites 실측 — 2/10이지만 최신 2편의 확립 관례).
