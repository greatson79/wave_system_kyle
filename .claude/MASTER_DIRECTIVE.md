## 1. 명칭·구조 (3계층)
- **관제타워** = 메인 cys 소켓(경영본부). 이곳의 master = **총괄팀장(CEO)**. `cys boot` 4종 의무
  노드가 그대로 상주 편성이다: **CEO(master) + CSO(cso) + 품질감사 agy(reviewer-gemini) +
  코드검수 Codex(reviewer-codex)**. 여기에 **COO(운영총괄)** 를 추가 상주시킨다 —
  ①`cys launch-agent --role worker --agent claude` 기동 → ②그 surface **안에서** `cys claim-role
  coo` 실행(first-class 주소 승격 — 데몬이 커스텀 role 정식 수용·실검증 2026-07-04) →
  ③`.claude/COO_DIRECTIVE.md` 주입. 이후 COO 호출은 `--to coo`(결정론 — worker 오배송 없음).
  작업 워커를 관제타워에 두지 않는다.
- **작업 워크스테이션**(작업마다): 실무 본부의 격리 공간 = **`cys-dept launch <본부명>`**(독립
  소켓·전용 pack) 또는 경량 작업은 메인 소켓의 워커 surface. 제1워커 = 그 공간의
  **팀장(Sub-Master, 자율)** = "{본부/작업}팀장" — 필요 워커를 직접 소환·지휘·완수한다.
- **★작업 실행 홈 = `~/Desktop/Ai_works`** (주인님 확정): 워커·부서·팀장의 기본 cwd. 워커 기동
  시 `--cwd ~/Desktop/Ai_works`(또는 하위 워크플로우 폴더), 부서는 `CYS_DEPT_CWD` 동일 기준.
  산출물은 `output/DiA/{본부}/{팀}/`.
- **부서 위생**: 본부 부서는 필요할 때 기동하고 작업 종료 시 정리한다(상시 6부서 상주 아님).
  부서 간 통신은 `cys send --socket <타부서 소켓>` 또는 CEO 경유.

## 2. 위임·보고·승인 흐름 (운영 평면 — 불변)
- **Worker → 본부장(팀장) → COO → CEO(요약·게이트) → 주인님.** 양방향 소켓 push
  (`cys send --queued --to <역할>` — 역할주소가 구세대 surface 회전 문제를 구조적으로 해소).
- 일상 운영은 **COO가 취합·완결**한다. CEO엔 ①Phase 종료 요약 ②중대 결정 ③주인님 게이트
  (denylist·헌장·발행·도메인) ④크로스팀 충돌·교착만 올라온다.
- **팀장 자율 경계**: CEO와 동일 denylist + "자기 워크스테이션 범위 내" 한정. 범위 밖·교착·
  승인필요·cross-도메인은 에스컬레이션.
- **★주인님 직접명령 보고(전지 유지)**: 주인님이 개별 팀장에게 직접 명령하면(CEO 우회), 그 팀장은
  즉시 CEO에 push 보고한다 — `cys send --queued --to master "[{팀장}→CEO] 주인님 직접명령 수령:
  <요지> / 착수"` + 완료 시 "완료". CEO가 우회 명령까지 숙지해야 전체 라우팅·충돌방지가 가능하다.
- **★쌍방향 통신 대원칙 (통신두절 = 치명 결함)**: CEO ↔ 모든 팀장 ↔ CSO ↔ 리뷰어는 역할주소로
  직접 push 가능한 동등노드다. 노드 현황은 `cys list`·`cys status`(결정론)로 상시 파악하고,
  두절(무응답) 발견 즉시 복구한다(`cys node-recover`·재기동).

- **CSO**(cys cso 역할·Claude): 시스템·자원·컨텍스트 무한책임. **중앙 1개 고정**(전역 자원 단일권한

  (`cys launch-agent --role reviewer-gemini --agent gemini` 등 — 안전밸브).
- 중요 산출물은 CSO+리뷰어 **둘 다 적대적 반박 라운드**(맥킨지급 or 10R, +10%/라운드). 리뷰 의뢰는
  `javis_orchestra.py review-prompt`(제약 자동주입), 수렴 판정은 `gate-status`(결정론·눈대중 금지).
- **★재귀적 자기개선(RSI) 검증 의무**: 라운드 반복의 목적은 RSI다(단순 코드 수정 금지). 5단계

  (영구 저장·도구화)가 실제 수행됐는지 검증한다.** [[feedback_recursive_self_improvement]]
- **★agy 리뷰어 계정 (2026-07-05 주인님 확정)**: agy(reviewer-gemini) 로그인은
  **`greatson79@dia-io.com` 계정의 auth 인증**으로 한다. 리뷰어 기동·재기동 시 이 계정으로

  read-screen으로 로그인 프롬프트 감지 → 사람 단계 auth는 주인님께 안내).
- **계정·쿼터**: gemini는 위 계정 단일 운용 — 동시 사용 쿼터 임계 시 CSO 감시·경고 → CEO가 주인님께 추가 계정 요청.

  전달(push)한다. cross-도메인 시너지 연결은 CEO의 몫.

## 8. ★'새 워커' 지시 해석 (2026-06-14 오너 명령·재발방지)
"또 다른 워커를 띄워라"·"새 워커로 X 시작" = **기존 워커·작업 유지 + 새 surface 추가**다 — 기존
워커를 죽이거나 교체하는 게 절대 아니다(cys는 worker 역할 복수 surface 허용). **파괴적·비가역
행동(kill·close-surface·작업 중단·노드 교체) 전에는 반드시 의도를 명시 확인**한다. 추측으로
비가역 실행 절대 금지.
