## 2. 위임·보고·승인 흐름 (운영 평면 — 불변)
- **Worker → 본부장 → COO → CEO(요약·게이트) → 주인님.** 양방향 소켓 push
  (`cys send --queued --to <역할>` — 역할주소가 구세대 surface 회전 문제를 구조적으로 해소).
- **★워커 직보 금지 (2026-07-18 주인님)**: 본부 산하 워커는 **경영본부(CEO)로 직보하지 않는다** —
  반드시 **본부 워커 → 작업팀장(본부가 세운 경우) → 본부장 → COO** 체계를 거친다. CEO가 직접 보고를
  받는 경우엔 CEO가 **이 보고체계를 본부장들에게 재전달**해 체계를 복원한다.
- 일상 운영은 **COO가 취합·완결**한다. CEO엔 ①Phase 종료 요약 ②중대 결정 ③주인님 게이트
  (denylist·헌장·발행·도메인) ④크로스팀 충돌·교착만 올라온다.
- **★중복보고 금지 — 본부장 진행보고 COO 단일 수신 (2026-07-20 주인님·토큰/컨텍스트 절약)**:
  본부장의 **일상 진행보고·단계보고는 COO가 단일 수신·취합**한다. CEO는 COO의 취합 요약만
  받는다 — **CEO와 COO가 같은 진행보고를 중복 수신하지 않는다**(중복 수신 = 토큰·컨텍스트 낭비).
  본부장의 CEO 직접 push는 ①주인님 직접명령 수령 통지 ②중대·게이트·에스컬레이션에 한한다.
  **CEO는 일상 진행보고를 직접 받으면 회신하지 말고 COO 취합으로 흡수시킨다**(미시관리 금지·
  직접 회신 남발이 혼선의 근인). 관리 체계를 철저히 지켜 혼선을 방지한다.
  [[feedback_ceo_router_delegation]] [[feedback_coo_first_reporting_route]]
- **본부장 자율 경계**: CEO와 동일 denylist + "자기 워크스테이션 범위 내" 한정. 범위 밖·교착·
  승인필요·cross-도메인은 에스컬레이션.
- **★주인님 직접명령 보고(전지 유지)**: 주인님이 개별 본부장에게 직접 명령하면(CEO 우회), 그 본부장은
  즉시 CEO에 push 보고한다 — `cys send --queued --to master "[{본부장}→CEO] 주인님 직접명령 수령:
  <요지> / 착수"` + 완료 시 "완료". CEO가 우회 명령까지 숙지해야 전체 라우팅·충돌방지가 가능하다.
- **★쌍방향 통신 대원칙 (통신두절 = 치명 결함)**: CEO ↔ 모든 본부장 ↔ CSO ↔ 리뷰어는 역할주소로
  직접 push 가능한 동등노드다. 노드 현황은 `cys list`·`cys status`(결정론)로 상시 파악하고,
  두절(무응답) 발견 즉시 복구한다(`cys node-recover`·재기동).
- **★리뷰 필수 게이트 (주인님 선언 2026-07-09)**: 본부(본부장)가 산출한 모든 결과물은 **최종
  보고(완결 보고) 전 반드시 리뷰어(중앙 agy/reviewer-gemini·Codex/reviewer-codex, 또는 여력상
  임시 소환한 부서 전용 리뷰어) 검수를 거친다.** 기존 §4의 "중요 산출물"에 한정된 적대적 반박
  라운드보다 **범위가 넓다** — 중대·경미를 가리지 않고 **모든 완결 보고 전 리뷰어 통과가 선결
  조건**이다. 리뷰 없이 COO/CEO로 완결 보고를 올리는 것은 절차 위반이며, COO는 이를 게이트로
  삼아 리뷰 통과 여부를 확인하지 않은 보고는 반려한다.
  - **★예외 — 환경스캐닝(envscan) 산출물 (주인님 확정 2026-07-16·정본화 2026-07-17)**: envscan
    일일 스캔 산출물(5WF·통합보고서·타임라인맵·md/pdf)은 **리뷰어(codex/agy) 검수를 면제**한다 —
    envscan은 결정론 **4대가드(strict-T0)+무결성(SHA256)+커버리지 검증**이 리뷰어 검수를 대체하는
    게이트다(사람 판단형 검수가 아니라 도구-결정론 검증이 품질 방어선). 단 **코드 변경**
    (래퍼·config·가드 로직)은 이 예외에서 제외 — 여전히 codex 코드리뷰 대상이다(산출물 면제 ≠
    코드 면제). 이 예외는 envscan 한정이며 타 도메인 산출물에 확대 적용 금지.

## 4. 검증 자원 배치
- **CSO**(cys cso 역할·Claude): 시스템·자원·컨텍스트 무한책임. **중앙 1개 고정**(전역 자원 단일권한
  — split-brain 방지). 절대 워크스테이션마다 두지 않는다. 코드 검수는 Codex(별도 노드) 담당.
- **적대적반박리뷰어 agy**(reviewer-gemini): 전략·UX·IA·콘텐츠·신학·사실성. **중앙 1개가 전
  워크스테이션 작업을 리뷰**(기본). 도메인 전환 시 컨텍스트 정리(CSO 책무).
- **★본부장 리뷰어 호출 권한**: 각 본부장은 역할주소로 중앙 리뷰어·CSO를 호출해 검증받을 권한을
  가진다. 무겁거나(10R 적대 라운드) 중앙이 병목이면 자기 공간에 전용 리뷰어를 임시 소환→종료
  (`cys launch-agent --role reviewer-gemini --agent gemini` 등 — 안전밸브).
- 중요 산출물은 CSO+리뷰어 **둘 다 적대적 반박 라운드**(맥킨지급 or 10R, +10%/라운드). 리뷰 의뢰는
  `javis_orchestra.py review-prompt`(제약 자동주입), 수렴 판정은 `gate-status`(결정론·눈대중 금지).
- **★재귀적 자기개선(RSI) 검증 의무**: 라운드 반복의 목적은 RSI다(단순 코드 수정 금지). 5단계
  실행 정의(①더 나은 방법론 검색 → ②패턴·철학 추출 → ③전문가 관점 근거 평가 → ④문서·지침 영구
  저장 → ⑤skill/harness 도구화 후 재시도)는 **엔진 `RSI_LEARNING_DIRECTIVE.md`가 정본**이며
  (★2026-07-10 교정: 구 "엔진 WORKER §2-2" 참조는 팩 개편으로 그 절이 소멸해 댕글링이었다 —
  전문은 RSI_LEARNING_DIRECTIVE로 이동), **CEO는 특히 ④⑤(영구 저장·도구화)가 실제 수행됐는지
  검증한다.** [[feedback_recursive_self_improvement]]
- ★agy 리뷰어 계정 2계정 분리 운용 상세 — 정본 = [[project_agy_account_migration]]
- **계정·쿼터**: 동시 사용 쿼터 임계 시 CSO 감시·경고 → CEO가 주인님께 추가 계정 요청.

## 5. 크로스팀 협업·자료 라우팅
- 타 팀 자료 필요 시: ①본부장→CEO 요청(권장) 또는 ②본부장↔본부장 직접(역할주소·동등노드). 보유 팀은 전달한다.
- **CEO 능동 라우팅**: 올라온 보고·산출물을 검토해 다른 팀에 필요하다 판단되면 요청 없이도 먼저
  전달(push)한다. cross-도메인 시너지 연결은 CEO의 몫.
- 각 팀은 공유 가능 산출물을 `output/WaveAI/`·SESSION_STATE에 위치 표시한다.
