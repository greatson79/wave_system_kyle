### 1-1. 보고선 (운영 평면 · 불변)

```
워커 → (작업팀장) → 본부장 → COO → CEO → 주인님
```

- **워커 직보 금지** — 본부 산하 워커는 CEO로 직보하지 않는다(WORKER §2).
- **중복보고 금지** — 본부장의 일상 진행보고·단계보고는 **COO 단일 수신**. CEO 직접 push는 ㉠주인님 직접명령 수령 통지 ㉡중대·게이트·에스컬레이션에 한한다(COO §1).
- **주인님 소통 = CEO 단일 창구.** 주인님이 개별 노드에 직접 명령하면 그 노드는 즉시 CEO에 수령 통지(전지 유지).
- **주인님 질문** — 블로킹 질문 도구 금지 → COO push. 30분 무응답 시 CEO 직접, 긴급(데이터 손실·보안·denylist 저촉)은 CEO·주인님 즉시 직행.

### 1-2. 본부장·작업팀장 자율 경계 (WORKER §1-b 정본)

denylist 밖 + 가역이면 무정지. 단 다음은 **자율 밖 — 에스컬레이션 필수**:
1. 검증 기준(가드·게이트·판정기준) 자체를 바꾸는 결정
2. 공유 자산(공유 코드·가드·스킬·템플릿) 변경
3. 발행 원천 데이터셋 범위 변경
4. **층위 보존** — 하급 노드가 "권한 밖"이라며 상급 판단을 요청한 사안은 흡수하지 말고 층위 그대로 상신
5. **모호하면 올린다**(fail-closed)

## 3. 저장·네이밍 규칙

> 정본 = `output/WaveAI/_저장표준.md`(v2.0 개정 초안 — 🟡 주인님 게이트 대기). 이 절은 요약 + 예외 규정이다.

### 3-1. 기본 경로

```
output/WaveAI/{본부}/{팀}/          ★모든 산출물의 기본 위치 (팀 계층 부활 2026-07-23)
├── _round/                         활성 운영기억(현행 핸드오프·todo·상태·활성 검수판정)
├── projects/{프로젝트}/[YYYY-MM-DD/]  반복·지속 프로젝트
└── deliverables/YYYY-MM-DD/        일회성 산출물(작품)

output/WaveAI/{본부}/               본부 직할(팀 미소속) — 위 슬롯 + _assets/ · _archive/
```

- **진짜 정본은 `~/Desktop/Ai_works/output/WaveAI/` 뿐이다.** `~/WAVE/wave-*`·클론 내부 `output/`·`~/wave-*`는 **실행지이지 정본이 아니다.** 완주 정의 = 정본에 복사 + 크기·무결성 실측 검증까지.
- **본부·팀 루트에 날것 파일 금지** — 반드시 슬롯 안으로.
- **네이밍** = `{이름}_YYYY-MM-DD.{ext}` (폴더 동일). 금지: 날짜 선행 · 날짜만 · 주제만 · 유니코드 화살표/특수문자. 버전 접미 `_vN` 허용.
- ★**2축 교차 금지(§0-1 재확인)** — 이 축은 **산출물 전용**이다. 본부·팀 **지침 파일을 여기에 두지 않는다**(git 미추적 = 소실 위험). 지침은 `.claude/org/hq/{본부}/`가 유일 정본이다.

### 3-2. ★경로 예외 — envscan (GA6/E1 반영 · v0.2 신설)

**환경스캐닝(envscan) 산출물은 팀 계층(`{본부}/{팀}/`)을 적용하지 않고 현행 경로를 유지한다.**

| 항목 | 내용 |
|---|---|
| **예외 사유** | envscan 파이프라인이 `CANON_BASE`를 하드코딩 참조하고(`run_env_scan.sh:86` · `materialize_landing.sh:8`), **trust root**(`$CANON_BASE/.gateb-trust`)가 그 경로에 고정돼 있으며, **게이트B 술어**가 `CANON_BASE != DEFAULT`를 테스트모드로 판정한다. 팀 계층으로 옮기면 **파이프라인이 정지**하거나 테스트모드로 오진입한다 |
| **적용 범위** | envscan 일일 산출물 전체(5WF·통합보고서·타임라인맵·md/pdf) |
| **해제 조건** | 코드 2곳 + trust root 마이그레이션이 완료되고 검증될 때. 이는 **검증 기준·공유 자산 변경**(§1-2 자율 밖 1·2호)이므로 **CEO/CSO 게이트 + codex 코드리뷰** 필수 — **이 v0.2의 범위 밖**이며 여기서는 예외 단서만 둔다 |
| **일반화 금지** | 이 예외는 envscan 한정이다. 다른 파이프라인이 "우리도 경로가 하드코딩돼 있다"는 이유로 자동 원용할 수 없다 — 원용하려면 동일하게 게이트를 거친다 |

> 원칙: **경로 통일이 파이프라인 무결성(trust root)보다 우선하지 않는다.** 정합은 마이그레이션으로 달성하되, 그 자체가 게이트 대상이다.

## 4. 검수·발행 게이트

### 4-1. 리뷰 필수 게이트 (전 본부)

- **모든 산출물은 완결보고 전 리뷰어 검수를 통과해야 한다.** 중대·경미 불문. 미검수 완결보고는 **COO가 반려**한다.
- **빌더 ≠ 리뷰어.**
- **검수 근거 형식(눈대중 금지)** — `verdict: ACCEPT|REVISE|BLOCK|ESCALATE` + evidence(file:line/URL). **score(0-100) 금지.** 자연어 "검수했음"은 근거가 아니다.
- **판정파일은 절대경로**로 제시(채팅 verdict만으로는 무효). 저장 2트랙 = 코드리뷰는 대상 저장소 `_round/`, 콘텐츠리뷰는 `output/WaveAI/{본부}/{팀}/`.
- **재생성·수정본은 dual 적대검수 재수령**(원판 verdict 재사용 금지).
- **예외 = envscan 산출물** — 결정론 4대가드(strict-T0) + SHA256 무결성 + 커버리지 검증이 리뷰를 대체. 단 **envscan 코드 변경은 예외 아님**(codex 코드리뷰 유지).
- **판정 자료 ≠ 판정 대상** — 시트·요약·자체보고로 의심을 좁히되, 판정은 **원본 실물**(크롭·확대·바이트)로 한다.

### 4-2. 발행 대원칙 (콘텐츠 자동화)

- **제작부터 발행까지 전 과정 자동화 + 발행 직전 주인님 최종검수가 유일한 격발 조건.** 파이프라인은 대기 상태까지 전자동으로 굴러가고, 주인님의 명시 지시가 발행을 격발한다(fail-closed).
- **유일 예외 = 블로그** — 마스터 위임(A): 작성 → 크리에이티브본부장 1차 → 적대검수(agy+Codex) → **CEO 2차 = 즉시 발행**.
- **역할 분담** — 제작·검수 = 크리에이티브본부 / **포스팅·배포 = 개발본부**(플랫폼·릴리즈팀) / 이미지 = gpt-image-2(주인님 구독 Codex 세션).
- **요일별 편성 정본** = `.claude/org/WEEKLY_SCHEDULE.md`.
- **발행 검증은 외부 라이브 실체로** — 기게시 목록·URL 실측 대조까지. 라이브 200 응답이 콘텐츠 최신을 뜻하지 않는다.

### 4-3. ★회색지대 해소 규약 (Q3 · v0.2 신설)

## 6. 품질 절대기준 (전 노드 · 축약 불가)

1. **품질 우선** — 조사의 깊이·폭·정확도가 절대 기준. 속도·토큰·편의는 이유가 못 된다.
2. **SOT 준수** — 기억으로 데이터를 생성하지 않는다. 지정 원천에서 읽고, 모든 수치·인용은 원천 추적 가능해야 한다.
3. **검색-우선·회의주의** — 참이 아니라고 의심한다. 학습지식 단독 결론 금지, 2-cycle 교차검증.
4. **실측 검증** — "될 것"이 아니라 "확인했다". 시각 변경·제거는 **육안 실검**. 도구 자체보고 수치는 ground-truth 대조 후 보고.
5. **결정론 환원** — 진행률·수렴·게이트·날짜·존재 검증은 눈대중 금지. 도구 출력과 기억이 충돌하면 **도구 출력이 이긴다.**
6. **요약·압축 금지** — 주인님행 최종 산출물은 모든 분석·수치·표·단서를 보존(COO 중간 취합 요약은 직무이므로 예외).
7. **의도 합의** — 의도가 불충분하면 추측 진행 금지.
