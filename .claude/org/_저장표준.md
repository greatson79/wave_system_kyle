## 2. ★본부 내부 4-슬롯 표준 (축 통일)
```
output/WaveAI/{본부}/{팀}/   ★팀 계층 부활(2026-07-23) — 팀 소속 산출물은 팀 폴더 하위
output/WaveAI/{본부}/        본부 직할(팀 미소속) — 아래 슬롯 동일 적용
├── _round/            # ★활성(현재) 운영기억만: 현행 핸드오프·todo·상태·활성 라운드 검수판정
├── _assets/           # 재사용 자산: 캐릭터소스·웹디자인·템플릿·로고작업 (기존 _캐릭터소스·_웹디자인 통합)
├── _archive/          # ★역사적 구본·비활성 운영 부산물: 구 핸드오프·구 todo·과거 리뷰·감사·이사/복구 기록
├── projects/          # 지속·반복 프로젝트 (환경스캐닝·AI트렌드·투자분석·ebook 등)
│   └── {프로젝트명}/
│       ├── YYYY-MM-DD/{산출물}_YYYY-MM-DD.{ext}   # 날짜 회차가 있는 프로젝트
│       └── {산출물}_YYYY-MM-DD.{ext}              # 단발 프로젝트 산출
└── deliverables/      # 일회성 산출물 (날짜 축)
    └── YYYY-MM-DD/
        └── {이름}_YYYY-MM-DD.{ext}
```

### 슬롯 판정 규칙 (어디에 저장할지 결정)
| 산출물 성격 | 저장 위치 |
|-----------|----------|
| **활성(현재)** 운영 상태·현행 핸드오프·todo·활성 검수판정 | `_round/` |
| **역사적 구본·운영 부산물**(구 핸드오프·구 todo·과거 리뷰·감사·이사/복구 기록) | `_archive/` |
| **일회성 산출물(작품)** 보고서·분석·검수판정·카드 등 만들어 낸 결과물(나이 무관) | `deliverables/{날짜}/` |
| 재사용 자산(이미지 소스·템플릿·디자인 정본) | `_assets/` |
| **반복·지속 프로젝트**의 산출(매주/매일/시리즈) | `projects/{프로젝트}/[YYYY-MM-DD/]` |
| **1회성** 보고서·분석·검수·산출물 | `deliverables/YYYY-MM-DD/` |

- **★팀 계층 부활 (2026-07-23 주인님 — v1.0 팀폴더 폐지 대체)**: 산출물 축은 `{본부}/{팀}/` 팀 계층을 둔다. 팀 소속 산출물은 그 팀 폴더 하위 슬롯에, 본부 직할(팀 미소속)은 `{본부}/` 하위 슬롯에 저장한다.
  - ★**작업 자산 축(`.claude`·repo 도구)은 팀 분리하지 않는다(평면)** — 도구는 팀 경계를 넘나들어 팀 재편마다 참조가 깨진다. 축의 성격 차이(산출물축=팀부활 / 작업자산축=평면)는 모순이 아니다(계획안 D4·7of7 §1).
- **검수판정 파일**: 대상 산출물과 **같은 폴더에 병치**(추적성) 또는 라운드성이면 `_round/`.
  절대경로 제시 원칙 유지([[feedback_review_ticket_absolute_path]]).
- **★`_round` = 활성만 (2026-07-15 주인님 확정)**: `_round/`는 **지금 복원·운영에 쓰는 활성
  운영기억**만 담는다(현행 핸드오프·todo·상태·스윕원장·게이트큐·활성 검수판정). **이름이
  "핸드오프·리뷰"여도 시점이 지난 구본**(구 핸드오프·구 todo·과거 리뷰)이면 `_round`가 아니라
  **`deliverables/{날짜}/`** 로 간다. 활성 운영기억에 역사적 아카이브를 섞지 않는다(복원 앵커
  희석 방지). 판정 키 = **성격(운영/리뷰)이 아니라 시점(활성/구본)**.
- **★`deliverables` vs `_archive` (2026-07-15 주인님 확정)**: `deliverables`는 **"old 자료"가
  아니라 "만들어 낸 산출물(작품)"**이다 — 나이 무관(오늘 것도 지난달 것도 산출물이면 여기).
  판정 키 = **"만들어 낸 결과물(작품)인가, 운영하다 남은 구본·부산물인가?"** ㉠결과물(보고서·
  분석·카드·검수판정·설계·계획) → `deliverables/{날짜}/` ㉡운영 부산물의 구본(구 핸드오프·구
  todo·과거 리뷰·kill 감사·렌더검증·이사/복구 기록) → `_archive/`. deliverables를 구본 보관함처럼
  쓰지 않는다.

## 3. 네이밍 규칙
- 형식: **`{이름}_YYYY-MM-DD.{ext}`** (예: `시대통찰_2026-07-15.md`).
- 버전은 접미 `_vN` 허용(예: `review_codex_클라우드세션_2026-07-15_v2.md`)이나 최종본은 `_final` 또는 버전없음.
- 폴더도 동일: `{프로젝트/이름}_YYYY-MM-DD` (예: `ebook_claude완전정복_2026-07-15`).
- 금지: `2026-07-09_아티팩트카드뉴스`(날짜선행)·`2026-07-01`(날짜만·내용불명)·유니코드 화살표/특수문자.
