# 모델 티어 자율조정권 — 운영 정본

> **근거**: 주인님 직접지시 (2026-07-25) — "agy 기본값은 3.1 Pro로 일단 하고, 워커들에게도
> 고난도의 작업을 진행하거나 더 효과적으로 작업할 수 있게 티어 변경**에 대한 권한을 주자**"
> **발효**: 즉시 (운영 정본). 헌장 `MASTER §7` 본문 반영은 문구안 상신 후 주인님 승인 시.
> **소관**: CEO 제정 · COO 집행감독 · CSO 자원·게이팅 연동 감시.

---

## 1. 무엇이 바뀌는가

**기존**: 모델 티어는 역할로 **고정**됐다(본부장=상위·워커=하위). 워커는 어려운 일을 만나도
하위 티어로 버텨야 했고, 쉬운 일에도 배정된 티어를 그대로 썼다.

**변경**: **작업 난이도에 따라 자기 세션의 모델 티어를 스스로 올리고 내릴 권한**을 본부장과
워커에게 위임한다. 역할이 아니라 **일**이 티어를 정한다.

|---|---|---|

| CEO | 주인님 배정 | 자율조정 대상 아님 |

## 2-b. ★조정 방법 — 에이전트는 자기 티어를 스스로 바꿀 수 없다

> **실측 교정 (2026-07-25 · 리서치본부장 사례)**: 이 정책의 최초 문안은 "워커가 스스로 티어를
> 조정한다"고 썼으나 **실행 불가능한 전제**였다. `/model`은 세션 슬래시 명령이라 **에이전트가
> 자기 자신에게 실행할 수 없다**(COO 에스컬레이션으로 발견). 권한은 실행 경로가 있어야 권한이다.

따라서 이 권한의 실체는 **"스스로 바꾸는 권한"이 아니라
「판단해서 요청할 권한」 + 「상급자가 지체 없이 집행할 의무」** 다.

| 계열 | 집행 경로 |
|---|---|
| **Claude** | 노드가 상급자(본부장→COO→CEO)에 **사유와 함께 요청** → **pane 운용자가 집행**:<br>`cmux send --workspace <ws> --surface <sf> '/model <tier>'` → **enter 전 `read-screen`으로 입력줄 정확매치 확인**(슬래시 자동완성 오입력 방지) → `send-key enter`.<br>대상이 작업 중이면 **큐잉**되어 현재 턴 종료 후 적용된다(중단 사유 아님 — 계속 진행시켜라). |
| **Codex** | 세션 중 변경 불가 → **재기동 시 `--model` 지정**. 진행 중 작업이 있으면 완결 후 fresh 재소환(작업 유실 금지). |
| **agy** | Gemini 3.1 Pro **고정**(주인님 확정 — 변경 없음). |
| **예하 워커 소환** | 본부장이 **소환 시점에 `--model`로 직접 지정** — ★가장 확실한 경로다. 사후 변경보다 소환 시 배정을 우선하라. |

**상급자의 의무**: §3 기준을 충족하는 요청은 **지체 없이 집행**한다. 거부하려면 사유를 회신한다.
**요청을 방치하는 것은 권한 위임의 무력화**다.

## 3. 상향 기준 — 언제 올리는가

아래에 해당하면 **올려라**. 망설이지 마라 — 품질 절대우선이 자원 절약에 앞선다.

1. **오판 비용이 큰 작업** — 보안·가드·검증기·인증/권한·발행물·투자분석·신학 판정.
   되돌릴 수 없거나 외부로 나가는 산출물.
2. **장문 추론·설계** — 아키텍처 결정, 다단계 의존이 얽힌 구현, 대규모 리팩터링.
3. **크로스도메인 종합** — 여러 본부·도메인의 정보를 하나의 판단으로 묶어야 할 때.
4. **★실패 후 재시도** — 같은 티어로 다시 하면 같은 실패가 난다. 재시도 전에 올려라.
5. **리뷰·검수 국면** — 판정은 산출물의 최종 방어선이다.

## 3-b. 하향 기준 — 언제 내리는가

1. 단순·반복·기계적 작업(파일 이동, 포맷 정리, 정형 변환).
2. 경량 병렬 서브에이전트 — Haiku 4.5 유지가 기본.
3. **★사용량 게이팅** — CSO가 92%+ 선언하면 **자율상향권은 정지**되고 하향이 의무다.
   97%+면 graceful-stop(자동재개 금지).

## 4. ★남용 방지 (권한에 붙는 조건)

권한은 무제한이 아니다. 아래를 어기면 권한 오남용으로 본다.

1. **상향 사유 1줄 기록 의무** — 산출물 상태파일 또는 완결보고에
   `모델 티어: Sonnet 5 -> Opus 5 (사유: 가드 코드 설계 — 오판 비용 큼)` 형식으로 남긴다.
   스킬 발동기록(WORKER §3-A-2)과 같은 원리다. **기록 없는 상향은 미승인 상향으로 본다.**
2. **상시 최상위 고정 금지** — "일단 올려두고 계속 쓴다"는 금지. 고난도 구간이 끝나면 내린다.
   자원은 공유 자산이다.
3. **게이팅 우선** — CSO 게이팅 선언이 자율권보다 항상 상위다.
4. **본부장 배정 책임** — 예하 워커에게 상위 티어를 배정했으면 그 사유도 본부장이 기록한다.
