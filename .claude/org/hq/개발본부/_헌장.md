## 5. SOP (고유)
- 신규 웹/앱 = `appbuild`(+plan/tasks/supervisor)·`tdd-workflow`·`code-review`·`security-review`·`deployment-patterns`
- ★웹페이지·UI/UX 제작 시 **디자인 스킬 발동 의무**(`design-review`·`design-html`·`frontend-design`·`brand-guidelines` — 상위 §2 WORKER §3-A-3-b)
- 코드 검증·가드 = **codex 라인**(빌더≠리뷰어) · 이미지(홈페이지) = gpt-image-2
- **★wave-homepage 배포 = main push가 곧 production auto-deploy** (2026-07-27 실측 확정:
  `.vercel/project.json` GitHub 연동 + 배포이력 4건 `target=production`·`githubDeployment=1`).
  ⇒ **main push 전 반드시 CEO 승인 + 주인님 인지**를 거친다. 로컬 커밋·main 통합까지는 자율,
  **push부터가 라이브 반영**이다. 블로그 저장소는 별개 경로.
- **★커밋은 논리 단위로 쪼갠다** — stage 시 `git diff --cached --name-only`로 **파일 목록을 전량
  열거**해 무관 파일이 딸려 들어가지 않았는지 확인한다(요약 금지). 실사고: 히어로 커밋에 게이트
  대기 중이던 `VirtualLab.astro`(A-트림 §10 잉크블록)가 섞일 뻔했다.
- **★가드 정합은 2층위로 분리한다**: ①**stale guard 정합**(코드가 이미 의도 제거한 요소를 가드가
  계속 요구하는 불정합) = 정본 개정과 무관하므로 **즉시 수정** ②**새 계약 추가** = 정본 확정 후.
  ①을 ②에 묶으면 파이프라인이 무기한 막힌다. **가드 변경은 코드이므로 codex 리뷰 필수**이고,
  **고의 위반본을 넣어 RED가 뜨는지 확인**해 형해화되지 않았음을 증명한다.
- **★clean 검증 시 cwd를 확인하라** — `git worktree add`로 새 워크트리를 만든 뒤 **cwd를 옮기지
  않고** 원래 dirty 워킹트리에서 빌드를 돌려 오귀속한 실사고(2026-07-27)가 있다. detached
  checkout은 추적 파일의 미커밋 변경을 자동으로 되돌리지 않는다.
