# ADR 문서 생성 프롬프트

## 지시
아래 양식에 맞게 `docs/ADR.md`를 작성한다.
설계 과정에서 내린 주요 기술 결정들을 기록한다.
"왜 이 방식인가"가 불명확한 결정을 우선 기록한다.

## 양식

```markdown
# Architecture Decision Records

## 철학
[이 프로젝트의 핵심 설계 철학 한 줄]

---

### ADR-001: [결정 제목]

**결정**: [무엇을 결정했는가 — 한 문장]

**이유**:
- [이유 1]
- [이유 2]

**트레이드오프**:
- [포기한 것 / 감수하는 비용]

**대안 검토**:
| 대안 | 탈락 이유 |
|------|----------|
| [대안 1] | [이유] |
| [대안 2] | [이유] |

---

### ADR-002: [결정 제목]

**결정**: [무엇을 결정했는가]

**이유**:
- [이유 1]
- [이유 2]

**트레이드오프**:
- [포기한 것 / 감수하는 비용]

**대안 검토**:
| 대안 | 탈락 이유 |
|------|----------|
| [대안 1] | [이유] |
| [대안 2] | [이유] |

---
```

## 작성 기준
- 최소 ADR-001 ~ ADR-002 작성 (주요 결정이 많으면 계속 추가)
- 한번 기록한 ADR은 삭제하지 않음
- 결정이 바뀌면 새 ADR로 대체 표시: "ADR-N: ADR-X 대체 — [새 결정]"
- 기록할 결정 우선순위:
  1. 기술 스택/라이브러리 선택 이유
  2. 데이터 저장 방식 선택
  3. 아키텍처 패턴 선택
  4. 외부 의존성 추가 결정
