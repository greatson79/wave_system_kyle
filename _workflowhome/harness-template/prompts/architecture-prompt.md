# ARCHITECTURE 문서 생성 프롬프트

## 지시
아래 양식에 맞게 `docs/ARCHITECTURE.md`를 작성한다.
기획서(docs/skill-brief.md)와 CLAUDE.md의 기술 스택을 기반으로 채운다.
`[...]` 자리에 실제 내용을 작성한다.

## 양식

```markdown
# 아키텍처: [프로젝트명]

## 설계 철학
[핵심 설계 원칙 한 줄]

## 기술 스택
| 레이어 | 기술 | 비고 |
|--------|------|------|
| 런타임 | [기술] | [제한사항] |
| 프론트엔드 | [기술] | [비고] |
| 데이터 저장 | [기술] | [비고] |
| 호스팅 | [기술] | [비고] |
| 인증 | [기술] | [비고] |

## 디렉토리 구조
\`\`\`
[프로젝트명]/
├── src/
│   ├── [모듈명]/
│   │   ├── [파일명].[확장자]    # [역할]
│   │   └── ...
│   └── [설정파일]
├── docs/
├── phases/
└── output/
\`\`\`

## 데이터 모델

### [엔티티 1]
| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| id | String | ✅ | 고유 ID |
| [필드] | [타입] | ✅ | [설명] |
| [필드] | [타입] | ⬜ | [설명] |

### [엔티티 2]
| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| id | String | ✅ | 고유 ID |
| [필드] | [타입] | ✅ | [설명] |

## 데이터 흐름

### [흐름 1 — 예: 사용자 입력 처리]
\`\`\`
[입력]
    │
    ▼ [처리 모듈]
[중간 결과]
    │
    ▼ [다음 모듈]
[최종 결과]
\`\`\`

### [흐름 2]
\`\`\`
[입력]
    │
    ▼ [처리 모듈]
[결과]
\`\`\`

## 에러 처리 아키텍처

| 심각도 | 처리 방식 | 예시 |
|--------|----------|------|
| CRITICAL | 즉시 중단 + 사용자 알림 | [예시] |
| HIGH | 해당 작업 중단 + 로그 | [예시] |
| MEDIUM | 항목 스킵 + 경고 | [예시] |
| LOW | 로그만 기록 | [예시] |

## 제한사항 대응

| 제한 | 값 | 대응 전략 |
|------|-----|----------|
| [제한] | [값] | [대응] |
```

## 작성 기준
- 디렉토리 구조는 실제 구현할 파일 기준으로 구체적으로 작성
- 데이터 흐름은 PRD의 각 기능(F1, F2...)과 1:1 대응
- 에러 처리 예시는 이 프로젝트에서 실제 발생 가능한 것으로 작성
- 레이어 중 해당 없는 항목(인증 없음 등)은 행 삭제
