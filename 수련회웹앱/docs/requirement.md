# 팀빌딩 성경 미션 게임 웹앱 요구사항

## 1. 문서 목적

이 문서는 수련회, 성경학교, 여름행사 등 교회 교육 현장에서 사용할 수 있는 팀빌딩형 웹앱 게임의 최소 구현 요구사항을 정의한다. 목표는 로그인이나 개인정보 수집 없이, 팀 구성부터 미션 진행, 소감 제출까지 한 번의 행사 흐름 안에서 사용할 수 있는 간단한 웹앱을 구현하는 것이다.

## 2. 서비스 개요

### 2.1 목적

- 참가자들이 협력하여 미션을 해결하도록 유도한다.
- 간단한 성향 질문을 통해 팀을 구성하고, 이후 성경 기반 미션을 단계별로 진행한다.
- 진행자는 전체 게임 흐름을 쉽게 안내하고, 참가자는 현재 단계와 남은 단계를 직관적으로 확인할 수 있어야 한다.
- 마지막에는 팀별 소감을 작성하고 MVP에서는 이미지로 저장해 진행자에게 제출할 수 있어야 한다.

### 2.2 대상 사용자

- 진행자: 수련회, 성경학교, 여름행사 담당 교역자 또는 교사
- 참가자: 초등 고학년, 중고등부, 청년부 등 교회 공동체 참가자

### 2.3 사용 환경

- 모바일 브라우저 우선 지원
- 태블릿 및 데스크톱 브라우저 지원
- 별도 회원가입, 로그인, 서버 계정 없이 사용 가능

## 3. 핵심 사용자 흐름

1. 진행자가 게임 시작 화면에서 전체 인원 수와 원하는 팀 수를 입력한다.
2. 참가자 또는 진행자가 팀 이름을 입력한다.
3. 1단계에서 참가자들이 간단한 성향 질문에 답하고, 웹앱이 팀 구성을 제안한다.
4. 2단계 시작 전 전체 게임 주제 키워드를 확인한다.
5. 2단계에서 사다리타기 또는 랜덤 선택 방식으로 팀별 힌트와 도구 아이템을 획득한다.
6. 3단계에서 성경 기반 협업 퀴즈 또는 미션을 해결한다.
7. 4단계에서 최종 성경 미션을 해결하고 팀별 결과를 정리한다.
8. 마지막 화면에서 팀별 소감을 작성한다.
9. 작성한 소감과 결과를 MVP에서는 이미지로 다운로드하여 진행자에게 제출한다.

## 4. 단계별 게임 요구사항

### 4.1 공통 단계 UI

- 전체 진행은 4개 스테이지로 표시한다.
- 현재 단계, 완료 단계, 남은 단계를 구분해서 보여준다.
- 각 단계는 다음 정보를 포함한다.
  - 단계 번호
  - 단계 제목
  - 간단한 설명
  - 진행 상태
  - 다음 단계 이동 버튼

### 4.2 1단계: 팀 구성

#### 목적

전문 성향검사가 아닌 간단한 질문을 통해 참가자의 활동 성향을 파악하고, 팀이 한쪽 성향으로 치우치지 않도록 팀 구성을 제안한다.

#### 입력 항목

- 전체 참가 인원 수
- 원하는 팀 수
- 팀 이름
- 참가자별 닉네임 또는 번호
  - 개인정보 수집을 피하기 위해 실명 입력은 권장하지 않는다.
  - 최소 구현에서는 참가자 1, 참가자 2와 같은 자동 이름을 허용한다.

#### 성향 질문 예시

- 새로운 활동을 시작할 때 나는 먼저 아이디어를 내는 편이다.
- 문제를 풀 때 나는 조용히 정리하고 분석하는 편이다.
- 팀 활동에서 나는 사람들을 격려하는 역할을 자주 한다.
- 시간이 부족할 때 나는 빠르게 결정하고 실행하는 편이다.
- 모르는 내용이 나오면 나는 질문을 많이 하는 편이다.

#### 성향 분류 예시

- 아이디어형
- 분석형
- 실행형
- 격려형

#### 팀 구성 규칙

- 각 참가자의 질문 응답을 점수화한다.
- 팀별로 성향이 최대한 섞이도록 자동 배정한다.
- 팀 수와 인원이 맞지 않는 경우 일부 팀의 인원이 1명 많을 수 있다.
- 진행자가 필요하면 팀 배정을 수동으로 조정할 수 있는 기능은 선택 기능으로 둔다.

### 4.3 2단계: 주제 키워드와 힌트/도구 획득

#### 목적

전체 게임의 주제를 제시하고, 이후 미션 해결에 사용할 힌트와 도구를 팀별로 획득하게 한다.

#### 주제 키워드

- 진행자가 직접 입력하거나 기본 예시 중 선택할 수 있다.
- 예시:
  - 믿음
  - 순종
  - 사랑
  - 공동체
  - 섬김
  - 회복

#### 게임 방식

- 최소 구현은 사다리타기 또는 랜덤 매칭 중 하나로 구현한다.
- 팀 이름과 아이템 목록을 입력하면 팀별 결과가 자동으로 매칭된다.
- 결과는 한 번에 공개하거나 팀별로 순차 공개할 수 있다.

#### 아이템 예시

- 성경구절 힌트
- 키워드 카드
- 한 번 더 생각하기 카드
- 정답 후보 제거권
- 다른 팀과 협력 요청권

### 4.4 3단계: 성경 기반 협업 미션

#### 목적

팀원들이 함께 성경 내용을 떠올리고 토론하며 문제를 해결하도록 한다.

#### 미션 유형

- 성경 퀴즈
- 말씀 빈칸 채우기
- 인물과 사건 연결하기
- 주제 키워드에 맞는 말씀 찾기
- 팀별 토론 후 한 문장 고백 작성하기

#### 문제 구성 기준

- 수련회 또는 성경학교 주제와 연결되어야 한다.
- 연령대에 맞게 난이도를 조절할 수 있어야 한다.
- 단순 암기보다 팀원 간 상의가 필요한 문제를 포함한다.

#### 예시 문제

- "서로 사랑하라"는 말씀과 가장 관련 있는 성경 본문을 고르세요.
- 예수님이 제자들의 발을 씻기신 사건이 보여주는 태도는 무엇인가요?
- 오늘의 주제 키워드와 연결되는 성경 인물 한 명을 고르고 이유를 작성하세요.

### 4.5 4단계: 최종 미션

#### 목적

앞 단계에서 얻은 힌트와 도구를 활용하여 팀별 최종 답변 또는 결과물을 완성한다.

#### 미션 유형

- 최종 암호 또는 키워드 맞히기
- 말씀을 바탕으로 팀 선언문 만들기
- 주제에 맞는 짧은 상황극 대사 만들기
- 배운 내용을 바탕으로 공동체 실천 약속 작성하기

#### 완료 조건

- 팀별 최종 답변을 입력한다.
- 진행자가 정답 또는 완료 여부를 확인할 수 있다.
- 점수 경쟁보다 협력과 나눔을 우선하도록 설계한다.

## 5. 종료 및 소감 작성 요구사항

### 5.1 팀별 소감 작성

- 각 팀은 마지막 화면에서 소감을 작성한다.
- 입력 항목:
  - 팀 이름
  - 오늘 기억에 남는 말씀 또는 키워드
  - 팀이 함께 해결한 것
  - 감사한 점
  - 앞으로 실천하고 싶은 것

### 5.2 결과물 다운로드

- 작성한 소감은 MVP에서 이미지로 변환해 다운로드할 수 있어야 한다.
- PDF 다운로드는 MVP 이후 확장 기능으로 분리한다.
- 결과물에는 다음 내용이 포함되어야 한다.
  - 행사명 또는 게임 제목
  - 팀 이름
  - 주제 키워드
  - 팀별 소감
  - 완료한 미션 요약

## 6. 기능 요구사항

### 6.1 필수 기능

- 게임 시작 설정
  - 전체 인원 수 입력
  - 팀 수 입력
  - 팀 이름 입력
- 4단계 스테이지 진행 표시
- 1단계 간이 성향 질문
- 성향 기반 팀 자동 구성
- 2단계 주제 키워드 표시
- 2단계 힌트/도구 아이템 랜덤 배정
- 3단계 성경 기반 협업 퀴즈
- 4단계 최종 미션
- 팀별 소감 작성
- 이미지 다운로드

### 6.2 선택 기능

- 진행자용 미션 편집 화면

- 문제 난이도 선택
- 연령대 선택
- 팀별 점수 기록
- 결과 공유용 QR 코드 생성
- 로컬 저장소를 활용한 임시 저장

### 6.3 제외 기능

- 회원가입
- 로그인
- 실명 기반 개인정보 입력
- 서버 기반 참가자 데이터 저장
- 온라인 랭킹
- 결제 기능
- 채팅 기능

## 7. 콘텐츠 요구사항

### 7.1 기본 콘텐츠 세트

최소 구현에는 바로 실행 가능한 기본 콘텐츠 세트를 포함한다.

- 기본 주제: 공동체
- 기본 대상: 중고등부
- 기본 팀 수: 2~6팀
- 기본 단계 수: 4단계
- 기본 문제 수:
  - 1단계 성향 질문 5개
  - 2단계 아이템 6개
  - 3단계 퀴즈 5개
  - 4단계 최종 미션 1개

### 7.2 콘텐츠 커스터마이징

- 진행자가 주제 키워드, 성경 본문, 퀴즈 문항, 아이템명을 수정할 수 있으면 좋다.
- 최소 구현에서는 코드 또는 설정 파일에 기본 데이터를 분리해두고, 추후 관리자 화면으로 확장할 수 있게 한다.

## 8. 데이터 요구사항

### 8.1 저장 데이터

서버 저장은 하지 않는다. 브라우저 상태 또는 로컬 저장소에만 임시 저장한다.

저장 가능한 데이터:

- 게임 설정
- 팀 이름
- 참가자별 임시 이름 또는 번호
- 성향 질문 응답
- 팀 배정 결과
- 팀별 아이템
- 팀별 미션 답변
- 팀별 소감

### 8.2 개인정보 원칙

- 실명, 전화번호, 생년월일, 이메일을 입력받지 않는다.
- 참가자 식별은 번호, 별칭, 팀명 중심으로 처리한다.
- 결과물에도 개인정보가 포함되지 않도록 안내 문구를 제공한다.

## 9. 화면 요구사항

### 9.1 화면 목록

- 시작/설정 화면
- 팀 이름 입력 화면
- 1단계 성향 질문 화면
- 팀 구성 결과 화면
- 2단계 주제 및 아이템 획득 화면
- 3단계 성경 협업 미션 화면
- 4단계 최종 미션 화면
- 팀별 소감 작성 화면
- 결과물 미리보기 및 다운로드 화면

### 9.2 UI 원칙

- 모바일에서 한 손으로 진행하기 쉬운 레이아웃을 우선한다.
- 현재 단계와 다음 행동이 명확해야 한다.
- 진행자와 참가자가 함께 보는 화면이므로 글자는 충분히 크게 표시한다.
- 게임 분위기는 밝고 활동적이되, 교회 교육 현장에 맞게 과도하게 자극적인 표현은 피한다.

## 10. 모듈 구조 요구사항

최소 구현이라도 기능을 모듈 단위로 나눈다.

### 10.1 권장 모듈

- `gameConfig`
  - 게임 제목, 주제, 단계 정의, 기본 콘텐츠 관리
- `teamBuilder`
  - 성향 질문 점수화 및 팀 자동 배정
- `stageManager`
  - 현재 단계, 완료 상태, 다음 단계 이동 관리
- `itemMatcher`
  - 사다리타기 또는 랜덤 아이템 배정
- `missionEngine`
  - 퀴즈, 미션, 정답 또는 완료 조건 관리
- `reflectionManager`
  - 팀별 소감 입력 및 검증
- `exporter`
  - MVP 결과물 이미지 변환 및 다운로드
  - PDF 변환은 MVP 이후 확장 기능으로 분리
- `storage`
  - 브라우저 로컬 저장소 기반 임시 저장

### 10.2 모듈 설계 원칙

- 콘텐츠 데이터와 화면 로직을 분리한다.
- 팀 배정, 아이템 배정, 미션 판정 로직은 독립적으로 테스트 가능해야 한다.
- 추후 서버 저장이나 관리자 화면을 붙일 수 있도록 데이터 구조를 명확히 둔다.

## 11. 비기능 요구사항

### 11.1 성능

- 일반적인 모바일 브라우저에서 빠르게 로드되어야 한다.
- 외부 API 없이 동작하는 것을 기본으로 한다.
- 이미지 변환 시에도 참가자가 체감할 정도의 긴 대기 시간이 없어야 한다.

### 11.2 접근성

- 버튼과 입력창은 충분한 크기로 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- 주요 안내 문구는 짧고 명확하게 작성한다.

### 11.3 안정성

- 새로고침 시 진행 중인 데이터가 사라지지 않도록 로컬 저장소 임시 저장을 고려한다.
- 다운로드 실패 시 다시 시도할 수 있어야 한다.
- 필수 입력값이 누락되면 다음 단계로 넘어가지 않도록 한다.

## 12. MVP 범위

### 12.1 MVP에 반드시 포함할 것

- 4단계 스테이지 진행
- 인원 수와 팀 수 입력
- 팀 이름 입력
- 간이 성향 질문 기반 팀 자동 배정
- 주제 키워드 표시
- 팀별 아이템 랜덤 배정
- 성경 기반 협업 퀴즈
- 최종 미션
- 팀별 소감 작성
- 이미지 다운로드

### 12.2 MVP 이후로 미룰 것

- PDF 다운로드
- 관리자용 콘텐츠 편집 화면
- 팀 배정 드래그 앤 드롭 수정
- 점수판
- QR 코드 공유
- 다중 기기 실시간 동기화

## 13. 성공 기준

- 진행자가 별도 교육 없이 게임을 시작하고 끝까지 진행할 수 있다.
- 참가자 개인정보 없이 팀 구성과 미션 진행이 가능하다.
- 팀별로 협업이 필요한 질문과 활동이 포함되어 있다.
- 마지막 소감 결과물을 파일로 저장해 제출할 수 있다.
- 기능이 최소 범위로 구현되어도 실제 수련회 또는 성경학교 현장에서 사용할 수 있다.

## 14. 구현 전 확정 사항

다음 항목은 MVP 구현 기준으로 확정한다.

- 주 대상 연령대: 중고등부
- 기본 성경학교 또는 수련회 주제: 공동체
- 기본 성경 본문: 요한복음 13장 34-35절, 고린도전서 12장 12-27절, 전도서 4장 9-10절을 기본 콘텐츠 후보로 사용한다.
- 진행 방식: MVP는 한 기기에서 진행자가 조작하고 참가자가 함께 보는 방식으로 구현한다.
- 결과물 형식 우선순위: MVP는 이미지 다운로드만 구현하고, PDF 다운로드는 MVP 이후로 미룬다.
