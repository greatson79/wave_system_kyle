# 팀빌딩 성경 미션 게임 웹앱 유저플로우

## 1. 문서 목적

이 문서는 팀빌딩 성경 미션 게임 웹앱의 기능 단위 사용자 흐름을 정의한다. 각 흐름은 사용자의 입력, 시스템 처리, 사용자에게 제공되는 출력 및 사이드이펙트로 구분한다. 구체적인 화면 문구는 이 문서에서 다루지 않는다.

## 2. 전제

- 사용자는 로그인하지 않는다.
- 실명, 전화번호, 이메일 등 개인정보를 입력하지 않는다.
- 진행 데이터는 서버에 저장하지 않고 브라우저 상태 또는 로컬 저장소에 임시 저장한다.
- MVP 기준 결과물 다운로드는 이미지 생성을 우선한다.
- 기본 진행 방식은 한 기기에서 진행자가 조작하고 참가자가 함께 보는 형태를 우선한다.

## 3. 전체 진행 흐름

### 입력

- 진행자가 게임 설정을 입력한다.
- 진행자가 팀 이름을 입력한다.
- 진행자 또는 참가자가 참가자별 성향 질문 응답을 입력한다.
- 진행자가 각 단계의 시작, 결과 확인, 다음 단계 이동을 실행한다.
- 팀별로 미션 답변과 소감을 입력한다.
- 진행자가 결과물 다운로드를 실행한다.

### 처리

1. 시스템은 게임 설정을 검증하고 초기 게임 상태를 생성한다.
2. 시스템은 입력된 팀 이름과 참가자 수를 기준으로 팀 구성을 준비한다.
3. 시스템은 성향 질문 응답을 점수화하고 팀별 성향 균형을 고려해 참가자를 배정한다.
4. 시스템은 현재 스테이지, 완료 스테이지, 남은 스테이지를 관리한다.
5. 시스템은 2단계에서 주제 키워드와 팀별 아이템을 배정한다.
6. 시스템은 3단계와 4단계에서 미션 답변을 수집하고 완료 여부를 관리한다.
7. 시스템은 마지막 단계에서 팀별 소감과 미션 요약을 결과물 데이터로 구성한다.
8. 시스템은 결과물 미리보기와 다운로드 파일을 생성한다.

### 출력

- 현재 진행 단계와 완료 상태가 표시된다.
- 팀 구성 결과가 표시된다.
- 팀별 아이템 획득 결과가 표시된다.
- 미션 진행 상태와 팀별 답변 상태가 표시된다.
- 팀별 소감 결과물이 미리보기로 표시된다.
- 이미지 파일 다운로드가 실행된다.

### 엣지케이스

- 새로고침이 발생하면 로컬 저장소에 저장된 진행 상태를 복구한다.
- 저장된 진행 상태가 손상되었거나 버전이 맞지 않으면 새 게임 시작이 가능해야 한다.
- 사용자가 필수 입력을 누락한 경우 다음 단계로 진행하지 않는다.
- 브라우저가 로컬 저장소를 사용할 수 없는 경우 현재 세션 상태만 유지한다.
- 같은 기기에서 새 게임을 시작할 경우 기존 진행 데이터를 덮어쓸지 확인하는 흐름이 필요하다.

## 4. 게임 시작 및 기본 설정

### 입력

- 전체 참가 인원 수
- 원하는 팀 수
- 선택 가능한 경우 행사명 또는 게임 제목
- 선택 가능한 경우 주제 키워드
- 선택 가능한 경우 대상 연령대 또는 난이도

### 처리

1. 시스템은 전체 참가 인원 수가 허용 범위인지 검증한다.
2. 시스템은 팀 수가 2개 이상이고 전체 참가 인원 수를 초과하지 않는지 검증한다.
3. 시스템은 팀별 최소 인원과 최대 인원을 계산한다.
4. 시스템은 입력된 설정값을 게임 상태에 저장한다.
5. 선택 입력이 없는 항목은 기본 콘텐츠 세트의 값을 적용한다.
6. 시스템은 다음 입력 흐름으로 이동 가능한 상태를 만든다.

### 출력

- 설정값의 유효성 상태가 표시된다.
- 다음 단계로 이동 가능한 상태가 표시된다.
- 설정 완료 후 팀 이름 입력 흐름으로 이동한다.

### 엣지케이스

- 참가 인원 수가 0명 또는 음수이면 진행하지 않는다.
- 팀 수가 참가 인원 수보다 많으면 진행하지 않는다.
- 숫자 입력에 문자가 포함되면 유효한 숫자로 처리할 수 없음을 표시한다.
- 참가 인원 수와 팀 수 조합상 일부 팀 인원이 달라지는 경우 허용 가능한 차이를 반영한다.
- 필수 설정을 변경하면 이후 단계에서 생성된 팀 구성과 미션 데이터가 초기화될 수 있다.

## 5. 팀 이름 입력

### 입력

- 원하는 팀 수만큼의 팀 이름
- 팀 이름 자동 생성 실행
- 팀 이름 수정

### 처리

1. 시스템은 설정된 팀 수만큼 팀 입력 슬롯을 생성한다.
2. 시스템은 팀 이름의 비어 있음과 중복 여부를 검증한다.
3. 자동 생성이 실행되면 기본 팀 이름을 팀 수만큼 생성한다.
4. 유효한 팀 이름을 팀 데이터에 저장한다.
5. 이후 단계에서 팀 이름을 참조할 수 있도록 게임 상태에 반영한다.

### 출력

- 팀 이름 입력 상태가 표시된다.
- 팀 이름 중복 또는 누락 상태가 표시된다.
- 유효한 팀 이름이 모두 입력되면 다음 흐름으로 이동 가능해진다.

### 엣지케이스

- 팀 이름이 공백만 포함된 경우 비어 있는 이름으로 처리한다.
- 같은 이름이 여러 번 입력되면 진행하지 않는다.
- 팀 이름이 지나치게 긴 경우 표시 영역에 맞게 제한하거나 축약한다.
- 팀 수가 변경되면 기존 팀 이름을 가능한 범위에서 유지하고 초과 항목은 제거한다.
- 개인정보로 보이는 값 입력을 시스템이 완전히 판별할 수 없으므로, 개인정보 입력을 피하도록 안내 영역을 제공한다.

## 6. 참가자 식별자 준비

### 입력

- 참가자별 임시 이름 또는 번호
- 참가자 식별자 자동 생성 실행
- 참가자 식별자 수정

### 처리

1. 시스템은 전체 참가 인원 수만큼 참가자 항목을 생성한다.
2. 자동 생성이 실행되면 참가자 번호 기반 식별자를 생성한다.
3. 사용자가 수정한 식별자는 개인정보가 아닌 별칭으로 취급한다.
4. 시스템은 참가자 식별자 목록을 성향 질문 응답 흐름과 팀 배정 로직에 전달한다.

### 출력

- 참가자 식별자 목록이 표시된다.
- 참가자별 성향 응답 입력 가능 상태가 표시된다.

### 엣지케이스

- 참가자 식별자가 비어 있으면 자동 생성값으로 대체할 수 있다.
- 참가자 식별자가 중복되면 내부 식별자는 별도로 유지하고 화면 표시명만 중복될 수 있음을 고려한다.
- 참가자 수가 변경되면 기존 응답 데이터와 식별자 데이터의 유지 가능 범위를 재계산한다.

## 7. 1단계 성향 질문 응답

### 입력

- 참가자별 성향 질문 응답
- 응답 수정
- 응답 완료 실행

### 처리

1. 시스템은 기본 성향 질문 세트를 불러온다.
2. 시스템은 각 질문 응답을 성향 점수로 변환한다.
3. 참가자별로 아이디어형, 분석형, 실행형, 격려형 등 성향 점수를 계산한다.
4. 시스템은 모든 필수 응답이 완료되었는지 확인한다.
5. 응답이 완료되면 팀 자동 배정 로직을 실행할 수 있는 상태로 전환한다.

### 출력

- 참가자별 응답 진행 상태가 표시된다.
- 전체 응답 완료 여부가 표시된다.
- 응답 완료 후 팀 구성 결과 생성 흐름으로 이동한다.

### 엣지케이스

- 일부 참가자의 응답이 누락되면 팀 배정을 실행하지 않는다.
- 응답을 완료한 뒤 참가자 수가 변경되면 기존 응답과 배정 결과를 재검토한다.
- 모든 응답이 동일한 성향으로 치우치면 팀별 균형 배정의 한계를 감안해 가능한 균등 인원 배정을 우선한다.
- 질문 데이터가 비어 있거나 불러오기 실패하면 기본 내장 질문 세트를 사용한다.

## 8. 1단계 팀 자동 구성 결과

### 입력

- 팀 구성 생성 실행
- 선택 기능으로 팀 배정 수동 조정
- 팀 구성 확정 실행

### 처리

1. 시스템은 참가자별 대표 성향과 보조 성향을 계산한다.
2. 시스템은 팀별 인원 수가 최대한 균등하도록 목표 인원을 정한다.
3. 시스템은 같은 성향이 한 팀에 몰리지 않도록 참가자를 분산 배정한다.
4. 남는 인원은 팀별 인원 차이가 최소가 되도록 배정한다.
5. 선택 기능이 활성화된 경우 수동 조정 결과를 검증한다.
6. 팀 구성이 확정되면 1단계를 완료 상태로 저장한다.

### 출력

- 팀별 참가자 목록이 표시된다.
- 팀별 성향 분포가 표시된다.
- 1단계 완료 상태가 진행 표시 영역에 반영된다.
- 2단계로 이동 가능한 상태가 표시된다.

### 엣지케이스

- 참가자 수가 팀 수로 나누어떨어지지 않으면 일부 팀에 1명을 더 배정한다.
- 특정 성향 참가자가 부족하면 성향 균형보다 팀별 인원 균형을 우선한다.
- 수동 조정으로 빈 팀이 생기면 확정하지 않는다.
- 팀 구성 확정 후 성향 응답을 수정하면 기존 팀 구성 결과를 다시 생성해야 한다.

## 9. 스테이지 진행 표시 및 이동

### 입력

- 다음 단계 이동 실행
- 이전 단계 확인 실행
- 완료된 단계 재확인 실행
- 새 게임 시작 실행

### 처리

1. 시스템은 현재 단계의 완료 조건을 확인한다.
2. 완료 조건이 충족된 경우 다음 단계로 이동한다.
3. 완료된 단계는 완료 상태로 표시한다.
4. 아직 진행할 수 없는 단계는 접근을 제한한다.
5. 단계 이동 시 현재 게임 상태를 임시 저장한다.

### 출력

- 현재 단계, 완료 단계, 남은 단계가 구분되어 표시된다.
- 이동 가능한 단계와 제한된 단계가 구분되어 표시된다.
- 단계 이동 후 해당 단계의 입력 화면 또는 결과 화면이 표시된다.

### 엣지케이스

- 사용자가 브라우저 뒤로 가기를 실행해도 게임 상태와 현재 단계가 일관되게 유지되어야 한다.
- 완료 조건이 충족되지 않은 상태에서 다음 단계 이동을 시도하면 이동하지 않는다.
- 완료된 단계의 데이터를 수정하면 이후 단계 데이터가 영향을 받을 수 있음을 반영한다.
- 새 게임 시작 시 기존 임시 저장 데이터를 초기화하는 흐름이 필요하다.

## 10. 2단계 주제 키워드 확인

### 입력

- 기본 주제 키워드 사용
- 주제 키워드 선택 또는 수정
- 2단계 시작 실행

### 처리

1. 시스템은 게임 설정에 저장된 주제 키워드를 확인한다.
2. 주제 키워드가 없으면 기본 콘텐츠 세트의 주제를 적용한다.
3. 주제 키워드를 이후 미션, 결과물, 소감 데이터에서 참조할 수 있도록 저장한다.
4. 2단계 아이템 획득 흐름을 준비한다.

### 출력

- 현재 게임의 주제 키워드가 표시된다.
- 2단계 진행 가능 상태가 표시된다.

### 엣지케이스

- 주제 키워드가 비어 있으면 기본 주제를 사용한다.
- 주제 키워드가 지나치게 긴 경우 화면 표시와 결과물 표시에서 줄바꿈 또는 축약 처리가 필요하다.
- 주제 변경 시 이미 생성된 3단계, 4단계 답변 및 결과물 데이터와의 관계를 재확인한다.

## 11. 2단계 힌트 및 도구 아이템 획득

### 입력

- 아이템 목록 확인
- 아이템 배정 방식 실행
- 팀별 결과 공개 실행
- 필요 시 아이템 재배정 실행

### 처리

1. 시스템은 팀 목록과 아이템 목록을 불러온다.
2. 시스템은 랜덤 매칭 또는 사다리타기 방식으로 팀별 아이템을 배정한다.
3. 아이템 수가 팀 수보다 많으면 일부 아이템은 사용되지 않거나 중복 없이 선택된다.
4. 아이템 수가 팀 수보다 적으면 재사용 가능 여부에 따라 중복 배정 또는 기본 아이템을 적용한다.
5. 배정 결과를 팀별 상태에 저장한다.
6. 결과 공개 방식에 따라 전체 공개 또는 순차 공개 상태를 관리한다.
7. 결과가 확정되면 2단계를 완료 상태로 저장한다.

### 출력

- 팀별 획득 아이템이 표시된다.
- 아이템의 미션 활용 가능 상태가 표시된다.
- 2단계 완료 상태가 진행 표시 영역에 반영된다.
- 3단계로 이동 가능한 상태가 표시된다.

### 엣지케이스

- 팀 데이터가 없으면 아이템 배정을 실행하지 않는다.
- 아이템 목록이 비어 있으면 기본 아이템 세트를 사용한다.
- 재배정이 실행되면 기존 아이템 결과를 덮어쓴다.
- 결과 공개 도중 새로고침이 발생하면 공개 상태를 복구하거나 전체 결과를 표시한다.
- 랜덤 결과의 재현성이 필요한 경우 현재 게임 세션의 배정 결과를 저장한다.

## 12. 3단계 성경 기반 협업 미션

### 입력

- 팀별 미션 답변
- 선택형 퀴즈 답안 선택
- 서술형 답변 작성
- 아이템 사용 실행
- 답변 제출 실행

### 처리

1. 시스템은 주제 키워드와 기본 콘텐츠 세트에 맞는 미션 목록을 불러온다.
2. 시스템은 문제 유형에 따라 입력 방식을 결정한다.
3. 팀별 답변을 임시 저장한다.
4. 선택형 문제는 정답 기준으로 채점하거나 완료 여부를 판단한다.
5. 서술형 문제는 입력 여부와 진행자 확인을 기준으로 완료 여부를 판단한다.
6. 팀이 획득한 아이템을 사용할 경우 해당 아이템의 사용 상태를 저장한다.
7. 모든 필수 미션 조건이 충족되면 3단계를 완료 상태로 저장한다.

### 출력

- 미션 목록 또는 현재 미션이 표시된다.
- 팀별 답변 입력 상태가 표시된다.
- 아이템 사용 가능 여부와 사용 상태가 표시된다.
- 미션 완료 여부가 표시된다.
- 3단계 완료 상태가 진행 표시 영역에 반영된다.

### 엣지케이스

- 팀별 답변이 비어 있으면 제출하지 않는다.
- 서술형 답변이 지나치게 긴 경우 저장 및 결과물 표시 제한을 적용한다.
- 아이템을 중복 사용할 수 없는 경우 이미 사용된 아이템은 다시 사용할 수 없도록 처리한다.
- 정답 데이터가 없는 미션은 진행자 확인 또는 입력 완료 기준으로 처리한다.
- 성경 본문이나 주제 데이터가 누락되면 기본 미션 세트를 사용한다.

## 13. 4단계 최종 미션

### 입력

- 팀별 최종 답변
- 앞 단계에서 획득한 힌트 또는 도구 사용
- 진행자 완료 확인
- 최종 미션 제출 실행

### 처리

1. 시스템은 최종 미션 데이터를 불러온다.
2. 시스템은 팀별 2단계 아이템과 3단계 답변을 참조 가능한 상태로 제공한다.
3. 팀별 최종 답변을 임시 저장한다.
4. 정답형 미션은 정답 기준으로 완료 여부를 판단한다.
5. 선언문, 실천 약속 등 결과물형 미션은 입력 완료와 진행자 확인을 기준으로 완료 여부를 판단한다.
6. 모든 팀의 최종 미션 상태를 저장한다.
7. 4단계를 완료 상태로 저장하고 소감 작성 흐름으로 이동 가능하게 한다.

### 출력

- 최종 미션 입력 상태가 표시된다.
- 팀별 완료 여부가 표시된다.
- 사용한 힌트와 도구 상태가 표시된다.
- 4단계 완료 상태가 진행 표시 영역에 반영된다.
- 소감 작성 흐름으로 이동 가능한 상태가 표시된다.

### 엣지케이스

- 일부 팀만 완료한 경우 전체 완료 처리 기준을 진행자가 판단할 수 있어야 한다.
- 최종 답변이 비어 있으면 해당 팀은 완료 처리하지 않는다.
- 정답형 미션에서 오답이 발생해도 재시도 가능 여부를 콘텐츠 설정에 따라 처리한다.
- 2단계 아이템 데이터가 없으면 아이템 없이 최종 미션을 진행할 수 있어야 한다.

## 14. 팀별 소감 작성

### 입력

- 팀별 기억에 남는 말씀 또는 키워드
- 팀이 함께 해결한 내용
- 감사한 점
- 앞으로 실천하고 싶은 내용
- 소감 저장 실행

### 처리

1. 시스템은 확정된 팀 목록을 기준으로 소감 입력 영역을 생성한다.
2. 시스템은 팀별 소감 입력값을 검증한다.
3. 시스템은 입력값을 팀별 소감 데이터로 저장한다.
4. 저장된 소감 데이터는 결과물 미리보기 생성에 사용된다.
5. 모든 필수 소감 항목이 입력되면 다운로드 준비 상태로 전환한다.

### 출력

- 팀별 소감 입력 상태가 표시된다.
- 필수 항목 완료 여부가 표시된다.
- 결과물 미리보기로 이동 가능한 상태가 표시된다.

### 엣지케이스

- 일부 팀의 소감이 누락되면 해당 팀을 표시하고 다운로드 준비 상태를 제한한다.
- 긴 텍스트는 결과물 레이아웃에서 줄바꿈 또는 영역 제한을 적용한다.
- 개인정보가 입력될 수 있으므로 결과물 생성 전 입력 내용을 검토할 수 있어야 한다.
- 팀 목록이 변경되면 소감 데이터와 팀 데이터의 연결 상태를 재확인한다.

## 15. 결과물 미리보기 및 이미지 다운로드

### 입력

- 결과물 미리보기 확인
- 팀별 결과물 선택
- 전체 결과물 다운로드 실행
- 개별 팀 결과물 다운로드 실행
- 다운로드 재시도 실행

### 처리

1. 시스템은 행사명 또는 게임 제목, 팀 이름, 주제 키워드, 완료 미션 요약, 팀별 소감을 결과물 데이터로 구성한다.
2. 시스템은 결과물 미리보기 영역을 생성한다.
3. 시스템은 미리보기 영역을 이미지로 변환한다.
4. 시스템은 팀별 또는 전체 결과물 파일명을 생성한다.
5. 이미지 생성이 완료되면 브라우저 다운로드를 실행한다.
6. 다운로드 성공 여부를 사용자가 확인할 수 있는 상태로 전환한다.

### 출력

- 결과물 미리보기가 표시된다.
- 다운로드 가능한 상태가 표시된다.
- 다운로드 실행 후 파일 생성 결과가 표시된다.

### 엣지케이스

- 이미지 변환 라이브러리 실행에 실패하면 재시도할 수 있어야 한다.
- 미리보기 영역에 긴 텍스트가 포함되면 이미지에서 잘리지 않도록 레이아웃을 조정한다.
- 모바일 브라우저에서 자동 다운로드가 제한될 경우 새 창 열기 또는 길게 저장 가능한 대체 흐름을 고려한다.
- 결과물 데이터가 누락되면 누락 항목을 표시하고 다운로드를 제한한다.
- PDF 다운로드는 MVP 이후 기능으로 분리하되, 데이터 구조는 확장 가능하게 유지한다.

## 16. 임시 저장 및 복구

### 입력

- 자동 저장 대상 데이터 변경
- 저장된 게임 이어하기 실행
- 저장된 게임 삭제 실행
- 새 게임 시작 실행

### 처리

1. 시스템은 게임 설정, 팀 데이터, 응답 데이터, 미션 데이터, 소감 데이터를 변경 시점에 임시 저장한다.
2. 앱 시작 시 로컬 저장소에 저장된 게임 상태를 확인한다.
3. 저장된 상태가 있으면 이어하기 가능 상태를 제공한다.
4. 저장된 상태가 없으면 새 게임 시작 상태를 제공한다.
5. 삭제 또는 새 게임 시작이 실행되면 기존 저장 데이터를 초기화한다.

### 출력

- 저장된 진행 상태 존재 여부가 표시된다.
- 이어하기 또는 새 게임 시작 가능 상태가 표시된다.
- 저장 데이터 삭제 결과가 표시된다.

### 엣지케이스

- 로컬 저장소 용량 초과가 발생하면 현재 세션 상태를 유지하고 저장 실패 상태를 표시한다.
- 저장 데이터의 구조가 현재 앱 버전과 맞지 않으면 복구 가능한 항목만 사용하거나 새 게임 시작을 유도한다.
- 여러 탭에서 같은 게임을 열면 마지막 저장 데이터가 우선될 수 있으므로 충돌 가능성을 고려한다.
- 비공개 브라우징 환경에서는 저장이 유지되지 않을 수 있다.

## 17. 콘텐츠 데이터 사용

### 입력

- 기본 콘텐츠 사용
- 선택 가능한 경우 주제, 난이도, 연령대 선택
- 선택 가능한 경우 콘텐츠 설정 변경

### 처리

1. 시스템은 기본 주제, 성향 질문, 아이템, 3단계 미션, 4단계 미션 데이터를 불러온다.
2. 선택값이 있으면 해당 조건에 맞는 콘텐츠를 우선 적용한다.
3. 조건에 맞는 콘텐츠가 없으면 기본 콘텐츠 세트를 적용한다.
4. 콘텐츠 데이터는 화면 로직과 분리된 설정 데이터로 관리한다.

### 출력

- 현재 적용된 주제와 콘텐츠 조건이 표시된다.
- 각 단계에서 필요한 콘텐츠가 표시된다.

### 엣지케이스

- 콘텐츠 데이터가 일부 누락되면 해당 단계의 기본값으로 보완한다.
- 연령대나 난이도 선택이 MVP에서 제공되지 않는 경우 기본 콘텐츠만 사용한다.
- 추후 관리자 편집 기능이 추가되더라도 기존 기본 콘텐츠 데이터와 호환되어야 한다.

## 18. 개인정보 비수집 흐름

### 입력

- 팀 이름
- 참가자 임시 이름 또는 번호
- 팀별 답변과 소감

### 처리

1. 시스템은 로그인과 계정 생성을 요구하지 않는다.
2. 시스템은 실명, 전화번호, 이메일 등 개인정보 전용 입력 필드를 제공하지 않는다.
3. 참가자 식별은 번호 또는 별칭 중심으로 처리한다.
4. 결과물 데이터에는 팀 활동 결과 중심의 정보만 포함한다.

### 출력

- 개인정보 없이 진행 가능한 입력 구조가 제공된다.
- 결과물에는 팀 이름, 주제, 소감, 미션 요약 중심의 데이터가 표시된다.

### 엣지케이스

- 사용자가 자유 입력란에 개인정보를 직접 입력할 가능성이 있으므로 결과물 생성 전 검토 흐름을 제공한다.
- 브라우저 로컬 저장소에 남은 데이터는 사용자가 삭제할 수 있어야 한다.
- 여러 행사에서 같은 기기를 사용하는 경우 이전 행사 데이터가 노출되지 않도록 새 게임 시작과 데이터 삭제 흐름이 필요하다.
