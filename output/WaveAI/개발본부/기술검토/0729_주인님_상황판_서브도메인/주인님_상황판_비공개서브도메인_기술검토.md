## 1. 결론

**현재 DNS·호스팅 계보를 유지한다는 전제의 권고 1안은 `board.waveainetworks.com`을 별도 Vercel 프로젝트로 배포하고, production Deployment Protection + Function + 원격 DB + 로컬 puller를 두는 방식이다.**

가비아 DNS를 유지하면서 해당 서브도메인만 Vercel에 연결할 수 있고, 기존 `wave-homepage`의 divergence·push HOLD와도 프로젝트를 분리할 수 있다. 주인님은 휴대폰 브라우저에서 인증하며, 클릭은 원격 DB에 먼저 저장된 뒤 CEO Mac이 outbound pull로 받아 `_수신함.jsonl`에 기록한다.

이 권고는 다음 게이트를 전제로 한다.

- 현재 Vercel 팀이 production custom domain 보호가 가능한 Pro 또는 Enterprise인지 확인한다. Hobby의 production domain은 Vercel Authentication으로 보호되지 않는다.
- Vercel Authentication을 쓸 경우 주인님을 허용된 팀 사용자로 구성한다. 공유 비밀번호를 쓰려면 Pro의 월 $150 Advanced Deployment Protection add-on 또는 Enterprise가 필요하다.
- 내부 화면과 응답이 Vercel·DB 공급자에 저장되는 외부 처리 경계를 주인님이 승인한다.

Cloudflare Access + Tunnel은 외부 응답 DB 없이 현행 로컬 수신기에 직접 연결한다는 점에서 개인정보 측면이 더 낫다. 그러나 현재 가비아 DNS를 유지한 partial CNAME setup은 Business/Enterprise, 서브도메인 위임 setup은 Enterprise 전용이다. Free/Pro의 일반 경로는 `waveainetworks.com` 전체 authoritative DNS를 Cloudflare로 이전하고 기존 Vercel 레코드를 함께 이관해야 하므로, 별도 인프라 변경 승인 없이는 1순위로 두지 않는다.

맞춤 서브도메인을 포기할 수 있다면 Tailscale Serve가 가장 사적이고 단순한 대안이지만, 주소가 `*.ts.net`이고 주인님 휴대폰에 Tailscale 앱·로그인이 필요하므로 원 지시의 1순위에는 두지 않는다.

## 3. 3개 방식 비교

| 비교축 | Vercel 서브도메인 + 인증 + Function/DB | Cloudflare Access + Tunnel 또는 Workers/D1 | Tailscale Serve |
|---|---|---|---|
| 맞춤 서브도메인 | **충족** — 가비아에서 서브도메인 연결 | **조건부** — 전체 NS 이전 또는 상위 유료 setup 필요 | **불충족** — `*.ts.net` |
| 주인님 휴대폰 편의 | **좋음** — 브라우저 | **매우 좋음** — 브라우저·이메일 OTP | **조건부** — Tailscale 앱·로그인 필요 |
| 1인 인증 강도 | Vercel 팀 계정 또는 별도 미들웨어 인증. 공유 비밀번호는 관리 위험 | 정확한 이메일 1개 Allow + OTP. 이메일 계정 MFA 권장 | tailnet identity + 기기 승인 + ACL로 가장 강함 |
| 클릭의 CEO 도달 | Function → 원격 DB → 로컬 puller가 필수 | Tunnel은 로컬로 직접 전달. Workers/D1은 로컬 puller 필요 | 로컬 서버로 직접 전달 |
| CEO Mac이 꺼진 동안 접수 | 원격 DB 사용 시 가능 | Tunnel은 불가, Workers/D1은 가능 | 불가 |
| 전달 신뢰성 | event ID·원격 저장·ACK·재시도 설계 시 높음 | Tunnel은 연결 중 단순·직접적. D1형은 dedupe·ACK 설계 시 높음 | 연결 중 직접적. 현재 서버 중복방지는 보완 필요 |
| 내부 정보 외부 저장 | 정적 화면·응답·Function 로그·DB가 외부에 남음 | Tunnel형은 외부 영구 DB 없음. 단 트래픽과 접근 메타데이터는 Cloudflare 경유·기록. D1형은 응답도 외부 저장 | 화면·응답은 로컬 유지. Tailscale 관리 메타데이터는 외부 |
| 예상 구축시간 | **1~2일 이상** — 별도 project·auth·Function·DB·puller | **Tunnel형 0.5~1일**, D1형 1~2일 이상 | **2~4시간** — 계정·기기 준비 상태에 좌우 |
| 예상비용 | production 보호는 Pro/Enterprise 필요. Password Protection은 Pro add-on 월 $150 또는 Enterprise | 전체 NS 이전 경로는 Free 가능. 가비아 유지 partial setup은 Business/Enterprise, 서브도메인 위임은 Enterprise. Workers 유료는 최소 월 $5 | 조직용 Standard는 사용자당 월 $8 기준; 실제 플랜 확인 필요 |
| 운영 복잡도 | 높음 — 인증·저장소·poller·비밀값 | Tunnel형 중간, D1형 높음 | 낮음 |
| 원 지시 적합도 | **현재 계보 기준 1순위** | **DNS 전환 승인 시 개인정보 우선안** | **맞춤 도메인 포기 시 대체안** |

시간·비용은 공식 기능과 현재 구조를 기준으로 한 개발본부 추정치이며 실제 계정·플랜·DNS 상태에 따라 달라질 수 있다.

## 4. 권고 구조

### 4.1 현재 계보의 1순위: Vercel 별도 프로젝트 + 원격 수신

```text
주인님 휴대폰
  → https://board.waveainetworks.com
  → Vercel production Deployment Protection
  → Function POST {event_id, decision, memo}
  → 원격 SQL/Redis 계열 저장소
  → CEO Mac outbound poller
  → _수신함.jsonl append + fsync
  → 원격 delivered ACK
```

Vercel Authentication은 production custom domain 보호가 가능한 Pro/Enterprise에서 주인님 계정을 허용하는 방식으로 쓴다. 현재 플랜과 팀 사용자 구성이 확인되지 않았으므로 비용을 0원으로 가정하지 않는다. Password Protection을 선택하면 월 $150 add-on 또는 Enterprise가 필요하다.

상황판은 기존 `wave-homepage`에 합치지 않고 별도 프로젝트로 둔다. 응답 저장은 event ID 유일성, 수신·전달 상태, 정렬 조회가 가능한 저장소를 사용한다. Vercel Blob과 GitHub 커밋은 버튼 응답 대기열의 기본 저장소로 사용하지 않는다.

### 4.2 개인정보 우선 조건부안: Cloudflare Access + Tunnel

```text
주인님 휴대폰
  → https://board.waveainetworks.com
  → Cloudflare Access
     (허용 이메일 1개 + OTP, 짧은 세션)
  → Cloudflare Tunnel
  → CEO Mac 127.0.0.1:8788
  → serve_board.py
  → _수신함.jsonl append + fsync
```

인증 정책은 `Emails = <주인님 이메일>`처럼 정확한 주소 한 개로 제한한다. `Login Methods = One-time PIN`만 허용하면 OTP를 받을 수 있는 다른 이메일도 통과할 수 있으므로 사용하지 않는다. 이메일 계정 자체에 MFA와 안전한 복구수단을 적용해야 인증 강도가 완성된다.

응답은 현행 로컬 수신기로 직접 도달한다. CEO Mac이나 터널이 꺼져 있으면 제출이 실패하므로 UI가 “전달 완료”로 오인하지 않고 재시도를 안내해야 한다. **오프라인 접수 기능은 이 안의 범위에 포함하지 않는다.**

현행 UI와 서버에는 event ID·서버 중복제거·영속화 receipt 검증이 없다. 승인 후 구현 시 브라우저가 `event_id`를 보내고, 서버가 append+`fsync` 후 `{persisted: true, event_id}`를 반환하며, UI는 이 응답을 확인한 뒤에만 “전달 완료”를 표시해야 한다.

Cloudflare Free/Pro로 이 구조를 쓰려면 도메인 전체 NS 이전과 기존 Vercel DNS 레코드의 이관·무중단 검증이 선행된다. 가비아 DNS 유지가 필수라면 partial CNAME 또는 서브도메인 setup의 상위 플랜 비용을 먼저 확인한다.

### 4.3 Cloudflare에서 오프라인 접수가 필요할 때: Workers + D1 + 로컬 puller

```text
주인님 휴대폰
  → Access 인증
  → Worker POST {event_id, decision, memo}
  → D1 저장 (event_id UNIQUE, received_at, delivered_at)
  → CEO Mac outbound poller
  → _수신함.jsonl append + fsync
  → D1 delivered ACK
```

전달 보장은 “정확히 한 번”이 아니라 **중복 제거를 갖춘 at-least-once**로 설계한다.

- 휴대폰이 생성한 UUID `event_id`를 D1의 UNIQUE 키로 사용한다.
- CEO Mac은 미전달 건을 반복 조회한다.
- JSONL append와 `fsync`가 끝난 뒤에만 전달 완료 ACK를 보낸다.
- append 후 ACK 전에 Mac이 종료되는 경우를 위해 로컬도 `event_id`를 기록해 중복 append를 차단한다.

KV는 단순 상태·캐시에는 적합하지만 append 대기열, 유일성, 전달 상태를 다루기에는 D1보다 불리하다. Vercel Blob이나 GitHub 커밋도 버튼 응답 큐의 기본 저장소로 권고하지 않는다.

## 5. 다른 후보 판단

### 5.1 Tailscale Serve

CEO Mac과 주인님 휴대폰을 같은 tailnet에 넣고 ACL을 주인님 identity로 제한하면 화면과 응답이 로컬에만 남는다. 외부 DB와 응답 브리지가 필요 없어 가장 단순하고 강한 사설 접근이다.

단점은 주인님 휴대폰에 앱 설치·로그인이 필요하고 URL이 `board.waveainetworks.com`이 아니라 `device.tailnet.ts.net`이라는 점이다. Tailscale Funnel은 인터넷 공개 기능이므로 주인님 전용 인증 대안으로 사용하지 않는다.

## 6. 개인정보·운영 위험

상황판에는 내부 조직 현황과 의사결정 정보가 포함된다. 어느 외부 방식을 쓰더라도 다음 위험을 승인 전에 받아들여야 한다.

- Cloudflare Tunnel도 트래픽이 Cloudflare를 경유하고 접근·감사 메타데이터가 공급자에 남을 수 있다.
- Vercel 정적 배포와 Function은 배포 자산, 요청 로그, 원격 저장소라는 외부 보관 지점을 만든다.
- D1형은 전달 전 응답 원문이 외부 DB에 저장되므로 보유기간과 자동 삭제가 필요하다.
- 캐시·검색 노출 방지를 위해 인증된 HTML/API에는 `Cache-Control: private, no-store`, 검색 차단 헤더·robots 정책을 함께 검증해야 한다. robots만으로 접근통제를 대신할 수 없다.
- 원본 HTML 또는 `_수신함.jsonl`을 GitHub 저장소에 커밋하는 방식을 응답 전달 경로로 쓰지 않는다.

## 7. 승인 후 시험 기준

아직 실행하지 않은 시험 목록이다.

1. 비허용 이메일과 로그아웃 브라우저가 모두 차단되는지 확인한다.
2. 주인님 휴대폰에서 로그인부터 상황판 열기까지 1분 이내인지 확인한다.
3. 클릭 1건이 `_수신함.jsonl`에 정확히 한 번 기록되고 `/inbox`에 나타나는지 확인한다.
4. 더블 탭, 네트워크 단절, CEO Mac 재시작 후 중복·유실 동작을 확인한다.
5. CEO Mac이 꺼진 상태에서 Tunnel형은 명시적 실패를, D1형은 재기동 후 미전달 재처리를 보이는지 확인한다.
6. HTML·API가 CDN 공유 캐시에 남지 않고 검색엔진과 비허용 사용자가 읽지 못하는지 확인한다.
7. Access 세션 만료, 허용 이메일 철회, 분실 휴대폰·기기 해제 절차를 시험한다.
