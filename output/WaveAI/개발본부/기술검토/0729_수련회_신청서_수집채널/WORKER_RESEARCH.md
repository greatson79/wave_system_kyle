## 1. 결론 초안

**D-4 내 개설이 필요하다면 Google Forms를 1순위로 검토하되, 본 문안 그대로 한 개의 폼에 넣어서는 ‘담임목사만 보는 기도제목’의 분리보관 요건을 충족하지 못한다.**

Google Forms는 공개 링크·체크박스/장문 응답·실시간 요약/연결 Sheets·응답 삭제를 공식 기능으로 제공한다. 단, 폼 편집자에게는 연결 응답 스프레드시트 접근이 자동 부여되며, 같은 폼 응답 안의 특정 문항만 다른 보관소/다른 열람자로 보내는 기능은 이번 공식 문서 조사에서 확인하지 못했다. 따라서 현 정본 문안을 바꾸지 않는 한 **‘담임목사만’은 담임목사 단독 소유/단독 편집/단독 응답 열람이라는 운영 접근통제로만 달성**된다. 이 경우 일반 운영자는 원응답을 보지 않고 담임목사가 필요한 집계만 별도로 전달해야 한다.

‘기도제목 비공개’ 선택이 실제로 **기도제목 텍스트의 별도 보관과 일반 운영자 차단**까지 뜻한다면, 후보 1~3의 단일 폼만으로는 PASS를 줄 수 없다. 별도 데이터 저장소와 필드 단위 권한을 설계·검증할 자체 수신 백엔드가 필요하지만, 현재 `wave-homepage`는 순수 정적 Astro(`output: 'static'`)이고 수신 엔드포인트·DB·인증 구성도 없다. D-4 및 “구축 금지” 제약에서는 자체 페이지는 채택하지 않는다.

## 2. 공식 근거 메모

### Google Forms

1. [Google Forms 소개](https://www.about.google/forms/about/?hl=en_uk) — 무료 시작, 링크/웹 공유, 실시간 응답 차트를 공식 안내한다. **확인: 2026-07-29 / High**.
2. [폼 게시·응답자 공유](https://support.google.com/docs/answer/2839588?hl=en) — 응답자 접근/공유 설정과 응답 요약 공개 위험을 설명한다. 이번 조사 시 원문 열기는 HTTP 429였으므로 검색색인으로만 문구를 대조했다. 실제 개설 직전에 UI에서 공개 링크와 응답자용 요약 공개 여부를 다시 점검해야 한다. **확인: 2026-07-29 / Medium**.
3. [편집자 공유](https://support.google.com/docs/answer/2917111?hl=en) — 연결 응답 스프레드시트를 새로 만들면 폼 공동작업자에게 자동 접근이 부여된다고 명시한다. **확인: 2026-07-29 / High**.
4. [폼 편집](https://support.google.com/docs/answer/2839737?hl=en) — 질문 유형을 선택할 수 있고 checkbox 질문을 지원한다. 장문 응답은 문항 유형 선택 화면에서 실제로 설정하여 시연해야 한다. **확인: 2026-07-29 / High (checkbox), Medium (장문 UI 재확인 필요)**.
5. [응답 저장 위치와 삭제](https://support.google.com/docs/answer/2917686?hl=en-GB) — 폼 요약 또는 연결 Google Sheet에 응답 저장, 폼/스프레드시트는 별도 파일, 폼에서 삭제한 응답은 복구 불가라고 명시한다. **확인: 2026-07-29 / High**.
6. [2026년 자동 응답 마감 공지](https://support.google.com/docs/thread/404224928/google-forms-automatically-stop-accepting-responses-based-on-date-and-time-or-response-count?hl=en) — 개인 Google 계정 및 Workspace에 응답 마감일/건수 자동 종료가 제공된다고 Google 직원이 공지했다. **확인: 2026-07-29 / High**.

### Notion Forms

1. [Notion Forms 도움말](https://www.notion.com/help/forms) — 모든 플랜에서 폼을 만들고 쓸 수 있으며, 폼 문항은 연결 데이터베이스 속성이고 응답은 같은 DB의 `Responses` Table view에 저장된다. **확인: 2026-07-29 / High**.
2. 같은 공식 문서 — 공개 링크(`Anyone on the web with link`)는 Notion 계정/워크스페이스 소속이 아닌 사람도 작성할 수 있다. 다만 공개 링크 응답자는 자동 익명이며, 응답 열람에는 연결 DB의 `Can view` 이상 권한이 필요하다. **확인: 2026-07-29 / High**.
3. 같은 공식 문서 — multi-select에 응답당 최대 선택 수, 장문 답변, 필수 문항을 지원한다. 조건부 로직은 Business/Enterprise 플랜 전용이다. **확인: 2026-07-29 / High**.
4. [Notion Forms 제품 안내](https://www.notion.com/product/forms) — 무제한 폼/응답을 무료로 안내한다. **확인: 2026-07-29 / High**.
5. 해석: 응답자에게 DB 열람권한을 주지 않고 공개 폼으로 받는 것은 가능하나, 일반 운영자에게 DB `Can view`를 주면 공식 문서상 DB 응답을 보는 권한이다. **한 DB 안에서 기도제목 속성만 담임목사에게 보이게 하는 필드 단위 ACL은 이번 공식 문서에서 확인되지 않았다.** 따라서 그런 분리는 PASS로 주장하지 않는다. **확인: 2026-07-29 / Medium (문서 부재에 근거한 보수 판정)**.

### Kakao 비즈니스폼 / 카카오톡 채널 연계

1. [카카오비즈니스 비즈니스폼](https://business.kakao.com/info/talkbizform/) — 응모·설문·신청/예약을 카카오톡 안에서 받으며, 설문 문항·개인정보처리 설정·실시간 결과 확인을 지원한다고 안내한다. **확인: 2026-07-29 / High**.
2. 같은 공식 문서 — 관리자 권한관리와 일자별/영역별 통계 열람을 제공하며, 결과·통계는 권한 있는 관리자가 진행 중/종료 후에도 확인할 수 있다고 명시한다. **확인: 2026-07-29 / High**.
3. 같은 공식 문서 — 카카오모먼트·메시지·애드뷰·비즈보드 및 카카오톡 채널 메시지에 연계하는 흐름을 제시한다. 따라서 작성자는 카카오톡 환경을 이용해야 하며, ‘로그인/앱 설치 요구 없음’이라는 정본 요건에는 맞지 않는다. **확인: 2026-07-29 / High (카카오톡 내 참여), Medium (실제 진입 UI는 계정별 재시연 필요)**.
4. 공식 페이지에는 관리자 권한은 있으나 기도제목 문항만 별도 저장/별도 권한으로 분리하는 기능은 확인되지 않았다. 채널/비즈니스 관리자 권한을 추가하는 방식은 전체 결과 권한을 넓힐 위험이 있어 채택 전 실제 권한 화면의 시연이 필수다. **확인: 2026-07-29 / Medium**.

### 자체 페이지 / 별도 수신 백엔드

1. 로컬 실측: `wave-homepage/package.json`은 자신을 “정적 Astro 원페이지”로 명시하고, `wave-homepage/astro.config.mjs`는 `output: 'static'` 및 “서버 0”을 선언한다. `src` 및 설정 파일에서 폼 제출 API/수신 DB/인증·권한 구현은 발견하지 못했다. **확인: 2026-07-29 / High (로컬 파일 실측)**.
2. 따라서 기도제목 전용 저장소·담임목사 전용 권한·보유기간 자동 파기·감사기록은 새 백엔드/DB/인증/배포 설계와 보안 검증이 필요한 미구축 기능이다. 본 과업의 구축 금지 및 D-4에는 부적합하다. **확인: 2026-07-29 / High (위 실측으로부터의 추론)**.

### 권고: Google Forms, 단독 소유 모델 (조건부)

1. **새 폼**으로만 만든다. 기존 Notion 시연용 빈 자산은 사용하지 않는다.
2. 폼 소유자·편집자·연결 응답 Sheet 접근자는 **담임목사 한 명만** 둔다. 공동작업자 추가와 공유 Drive/공유 Sheet 저장은 금지한다. 이것이 현재 후보 중 ‘담임목사만’ 접근통제를 구현할 수 있는 최소 운영 방식이다.
3. 일반 운영에는 원응답을 공유하지 않는다. 인원·일정의 필요한 **집계값만** 담임목사가 전달한다. 이때 기도제목·건강 특이사항·연락처는 집계본에 포함하지 않는다.
4. 응답자 링크는 로그인 불요 공개 설정인지, 응답 요약 공개가 꺼졌는지, 응답자에게 다른 응답이 보이지 않는지 **로그아웃/시크릿 모바일 실기기**로 1회 확인한다. 이번 조사는 계정 변경/폼 생성 금지이므로 이 검증은 아직 미수행이다.
5. 개인정보 동의에는 목적·항목·보유기간·거부권/불이익을 명시한다. 건강 특이사항은 민감정보이므로 **일반 개인정보 동의와 별도**로 받고, 미성년 중 만 14세 미만은 법정대리인 동의와 확인 절차를 둔다. ‘응급처치/병원 이송 동의’는 개인정보 동의와 법적 성격이 다르므로 하나의 체크박스로 대체하지 않는다.
6. 보유기간은 주인님 확정 후 고지한다. 행사 종료 및 필요한 사후 조치 종료 시점에 Forms 응답과 연결 Sheets(있다면)를 모두 파기했는지, 내보낸 CSV/복사본이 없는지 체크리스트로 확인한다. Google에서 폼/스프레드시트는 별도 파일이므로 한쪽 삭제만으로 파기 완료라 할 수 없다.

### 채택 보류 조건

아래 중 하나라도 필요하면 Google Forms 단일 폼을 채택 보류한다.

- ‘담임목사만’이 단순한 권한 최소화가 아니라 **기도제목 원문만 별도 저장소로 물리·논리 분리**되어야 한다.
- 일반 운영자가 개별 신청서의 이름·일정·비상연락처는 봐야 하지만, 기도제목/건강 특이사항은 절대로 보지 않아야 한다.
- 법정대리인 동의의 실제 확인을 플랫폼만으로 자동화해야 한다.

이 경우 현 후보 중 즉시 PASS인 해법은 없으며, 별도 설계 승인과 개인정보·보안 검토가 선행돼야 한다. D-4/구축 금지 범위에서는 현장 간이 접수와 수기 관리 규율을 포함한 비디지털 보완안을 목회사역본부가 결정해야 한다.

## 5. 개설 직전 검증 체크리스트 (아직 실행하지 않음)

- [ ] 새 소유 계정이 담임목사 개인/전용 계정인지 확인
- [ ] 편집자 0명, 연결 응답 Sheet 접근자=담임목사만인지 확인
- [ ] 공개 링크를 로그아웃/시크릿 모바일에서 열어 로그인·앱 설치 없이 제출 가능한지 확인
- [ ] 응답자가 응답 요약/타인 응답을 볼 수 없음을 확인
- [ ] 일정 3개 선택지, 장문 3종, 미성년 조건부 블록을 정본 문안 그대로 대조
- [ ] 일반 개인정보 동의와 건강정보 별도 동의, 만 14세 미만 법정대리인 동의/확인 문안을 법률 검토 후 반영
- [ ] 보유기간·파기 책임자·파기일·Forms/Sheets/CSV 복사본 점검표 확정
- [ ] 실제 응답 1건으로 담임목사만 열람·집계하고, 일반 운영자에게는 비식별 집계만 전달되는지 시연

## 6. 검증 기록

- 공식 자료만 채택: Google, Notion, 카카오비즈니스, 국가법령정보센터, 개인정보보호위원회.
- Google Help 원문 2건은 조사 시 429여서 검색색인에만 의존한 부분을 Medium으로 낮췄다. 개설 직전 UI 실기기 검증이 필수다.
- 후보 서비스의 현재 계정 보유 상태, 관리자 권한 구성, 실제 공개 링크 설정, 요금제는 본 과업에서 계정 접근/변경을 금지하므로 확인하지 않았다.
- 발동 스킬: `agent-reach`(공식 웹 자료 탐색; 설치 모듈 누락으로 공식 도메인 검색으로 대체) · `hallucination-guard`(원출처·근거 적합성·미검증 한계 표기).
