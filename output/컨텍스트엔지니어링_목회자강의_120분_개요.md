## PART 0 — 왜 지금 목회자에게 컨텍스트 엔지니어링인가

**⏱ 10분 | 오프닝 · 강의 목적지 선언**

### 0-1. 오프닝 질문

> "목사님, AI에게 '주일 설교문 써줘'라고 해보신 적 있으십니까?
> 결과물이 어떠셨습니까?"

**예상 반응:**
- "신학적으로 얕다"
- "누구한테나 해당되는 뻔한 적용"
- "내 설교 스타일이 아니다"
- "성도들의 상황을 모른다"

→ 이것이 바로 **컨텍스트 부재**의 결과입니다.

### 0-2. 목회자의 AI 사용 3단계

| 단계 | 설명 | 현재 상태 |
|------|------|-----------|
| 1단계 AI 사용자 | "설교문 써줘" — 매번 처음부터, 결과가 매번 다름 | ← 대부분 여기 |
| 2단계 AI 설계자 | 한 번 설계하면 반복 적용, AI가 내 신학 언어로 씀 | ← **오늘 목표** |
| 3단계 AI 시스템 운영자 | 본문 입력만 하면 묵상·주보·셀나눔지가 자동 생성 | ← 다음 단계 |

### 0-3. 강의 핵심 전제

> **"AI에게 설교를 맡기는 것이 아니라,
> 내가 설계한 신학적 환경 안에서 AI가 조립하게 한다."**

**목회자에게 중요한 원칙:**
- AI는 새로운 진리나 영적 통찰을 만들어내는 주체가 아니다
- 목회자가 성경을 묵상하고, FCF(타락한 상태의 초점)를 발견하고, 적용점을 고민하는 과정은 여전히 목회자의 몫
- AI는 그 결과물을 대상과 형식에 맞게 가공·조립하는 도구

## PART 1 — 컨텍스트 엔지니어링 개념과 정의

**⏱ 15분 | 세 개념의 관계 · 표준 구조 · CO-STAR · 5레이어 연결**

### 1-1. 세 개념의 관계 (비유: 교회 건축)

| 개념 | 비유 | 설명 |
|------|------|------|
| **컨텍스트 엔지니어링** | 교회 전체 설계 | AI에게 주어지는 정보 환경 전체를 설계하는 기술 |
| **컨텍스트 관리** | 건물 유지보수 | 설계한 정보가 대화 중 사라지지 않게 유지·갱신 |
| **프롬프트 엔지니어링** | 벽돌 쌓는 기술 | 컨텍스트 엔지니어링을 실행하는 핵심 기술 |

> "프롬프트 엔지니어링은 질문 하나를 잘 쓰는 기술입니다.
> 컨텍스트 엔지니어링은 AI가 일할 정보 환경 전체를 설계하는 기술입니다."

**목회 적용:**
- 프롬프트 엔지니어링 = "설교문 써줘"
- 컨텍스트 엔지니어링 = 나의 신학적 관점, 성도들의 상황, 설교 문체, 본문 해석, 출력 형식까지 **모두 설계한 환경**에서 AI가 조립

### 1-2. 왜 컨텍스트가 중요한가

> "AI는 컨텍스트만큼만 쓴다." — Andrej Karpathy

| 입력 | 결과 |
|------|------|
| 빈약한 컨텍스트 | 인터넷 평균의 뻔한 글 — 누구에게도 닿지 않는 결과물 |
| 풍부하고 정밀한 컨텍스트 | 특정 성도의 마음에 닿는 결과물 |

**기술적 배경 (간략):**
- LLM은 무상태(Stateless) — 과거 대화를 기억하지 못함
- 컨텍스트 창에 넣은 정보만큼만 활용
- 정보가 많다고 좋은 것이 아님 → "적절한 정보를, 올바른 형식으로, 올바른 위치에"

### 1-3. CO-STAR와 5레이어 연결

| CO-STAR (범용) | 5레이어 (콘텐츠 최적화) | 목회 콘텐츠에서의 의미 |
|----------------|------------------------|----------------------|
| Context (맥락) | **Layer 4: 지식** | 성경 본문·신학적 해석·FCF·적용점 |
| Objective (목적) | **Layer 1: 목적** | 이 콘텐츠로 성도의 상태를 어떻게 변화시킬 것인가 |
| Style + Tone | **Layer 3: 보이스** | 설교 문체·금지어·신학 용어 수위 |
| Audience (독자) | **Layer 2: 독자** | 어떤 성도를 위한 것인가 (연령·신앙 단계·현재 상황) |
| Response (출력) | **Layer 5: 구조** | 설교문·카드뉴스·셀나눔지·주보 칼럼 등 형식 |

## PART 2 — 컨텍스트 관리: 맥락 제공·유지

**⏱ 10분 | 설계한 것이 무너지지 않게 유지하는 법**

### 2-1. 핵심 질문

> "5레이어를 완벽하게 설계해도, 대화가 길어지면 왜 AI가 처음 설정을 잊는가?"

### 2-2. 컨텍스트 관리 5가지 영역

| 영역 | 핵심 행동 | 목회 실전 예시 |
|------|----------|---------------|
| 맥락 제공 | 처음에 충분히 넣기 | 5레이어를 시스템 프롬프트에 넣고 시작 |
| 맥락 유지 | 핵심이 사라지지 않게 | "우리의 독자는 신앙 3년차 30대 직장인 부부" 재확인 |
| 맥락 갱신 | 방향 바뀔 때 명시 | "이제 같은 본문으로 청소년 버전을 만들자" 선언 |
| 맥락 압축 | 새 창으로 이어갈 때 | 이전 대화 핵심 설계를 한 문단으로 요약 전달 |
| 맥락 분리 | 주제 다르면 새 창 | 설교문 작업과 셀나눔지 작업을 같은 창에서 섞지 않기 |

### 2-3. 실전 루틴 (목회자용)

```
새 콘텐츠 시작 → 5레이어를 먼저 채워서 AI에게 전달
대화 중반     → "우리의 방향은 [목적], [독자], [보이스]입니다" 재확인
다른 형식     → 새 창에서 새 5레이어 (같은 본문이라도 형식이 다르면 분리)
다음 주 설교  → 새 창에서 새 5레이어 시작
```

> **핵심 경고:**
> "5레이어 설계 = 집을 잘 짓는 것
> 컨텍스트 관리 = 지은 집이 무너지지 않게 유지하는 것
> 둘 다 있어야 컨텍스트 엔지니어링이 완성됩니다."

## PART 3 — 5레이어 프레임워크 (목회 콘텐츠 최적화)

**⏱ 15분 | 콘텐츠 제작 컨텍스트 설계 도구**

### 3-1. 5레이어 전체 구조

| 레이어 | 핵심 질문 | 목회자의 실전 작성법 |
|--------|----------|---------------------|
| **L1 목적** | 왜 이 콘텐츠를 만드는가? | 이 글을 읽은 성도가 [현재 상태]에서 [변화된 상태]로 이동 |
| **L2 독자** | 누구를 위한 콘텐츠인가? | 연령·신앙 단계·현재 삶의 상황·감정 상태까지 |
| **L3 보이스** | 어떤 말투와 문체로? | 설교 어조·금지어 목록·신학 용어 수위·참고 문체 |
| **L4 지식** | 무슨 내용을 넣는가? | **가장 중요** — 본문 해석·FCF·적용점을 목회자가 직접 제공 |
| **L5 구조** | 어떤 형식으로? | 설교문·카드뉴스·셀나눔지·주보칼럼·SNS 등 |

### 3-2. Layer 4(지식)가 가장 중요한 이유

> "AI는 내가 제공한 원재료만큼만 씁니다.
> 원재료를 AI에게 맡기면 AI는 인터넷 평균을 씁니다."

**목회 콘텐츠에서 이것이 의미하는 것:**
- 성경 본문의 신학적 해석 → **목회자가 직접 제공**
- FCF(타락한 상태의 초점) 발견 → **목회자가 직접 고민**
- 성도들의 구체적 아픔/상황 → **목회자만 아는 현장의 지식**
- AI에게 이것을 맡기면 = 인터넷에 떠도는 모호한 종교적 글

> **"설교의 핵심은 목회자의 묵상에서 나옵니다.
> AI는 그 묵상을 다양한 형식으로 조립하는 도구입니다."**

### 3-3. 목회 콘텐츠별 5레이어 적용 매트릭스

| 콘텐츠 | L1 목적 | L2 독자 | L3 보이스 | L4 지식 | L5 구조 |
|--------|---------|---------|-----------|---------|---------|
| 주일설교 | 말씀을 통한 삶의 변화 | 전교인 | 격식체·따뜻한 권면 | 본문해석+FCF+적용 | 서론-본론(3P)-결론 |
| 매일묵상 | 하루를 말씀으로 시작 | 장년부 성도 | 친근한 묵상체 | 본문+묵상질문+기도문 | 짧은 묵상+질문 2개 |
| 청소년QT | 말씀이 내 삶에 닿음 | 중고등학생 | 구어체·질문형 | 같은 본문+청소년 눈높이 | 카드 5장 형식 |
| 셀나눔지 | 삶으로 이어지는 나눔 | 셀모임원 | 대화 유도형 | 설교 요약+나눔질문 | 요약+질문 4개 |
| 주보칼럼 | 한 주의 방향 제시 | 전교인 | 간결·핵심 | 시즌메시지 | 300자 이내 |
| SNS 카드 | 비신자 접점 확대 | 비신자 포함 | 공감형·일상어 | 핵심 한 문장 | 카드뉴스 3장 |

### 3-4. 에이전틱 시스템 복선

> "지금 배우는 5레이어가 미래의 목회 AI 시스템에서 어떤 역할을 하는지 기억해두십시오."

| 5레이어 | 에이전틱 시스템에서의 역할 |
|---------|------------------------|
| 목적 | 시스템의 작동 조건 — 매주 어떤 콘텐츠를 생성할 것인가 |
| 독자 | 시스템의 입력 조건 — 장년부/청소년/셀모임 자동 분기 |
| 보이스 | 시스템의 페르소나 — 목회자의 설교 문체를 학습 |
| 지식 | 시스템에 연결할 데이터 — 주석·설교 아카이브·성도 정보 |
| 구조 | 시스템의 출력 명세 — 설교문·카드뉴스·나눔지 자동 변환 |

## PART 4 — 목회 사례 해부: 공식 추출

**⏱ 10분 | 고난주간 묵상 5레이어를 해부하고, 내 것으로 이식한다**

### 4-1. 비포: "고난주간 묵상 글 써줘"

**AI 결과 (예상):**
- 신학적 요약 나열
- 교과서적 적용 ("고난을 통해 성장합시다")
- 누구를 위한 글인지 모호
- 어디서나 볼 수 있는 뻔한 종교 언어

### 4-2. 애프터: 5레이어 정밀 설계

본문: 마가복음 15:33-39 | FCF: 버려진다는 두려움, 혼자라는 느낌

| 레이어 | 설계 내용 |
|--------|----------|
| **L1 목적** | 고난이 의례처럼 느껴지는 청년이 "이게 나의 이야기다"를 발견하게 한다 |
| **L2 독자** | 20-30대 교회 청년 / 신앙 있으나 고난에 무감각 / 바쁘고 피곤한 일상 |
| **L3 보이스** | 짧고 직접적 / 종교 용어 최소화 / 질문형 시작 / **금지: "더 열심히"** |
| **L4 지식** | 막 15:34 버림받음의 외침 / FCF: 혼자라는 느낌 / 예수님이 먼저 버림받으셨다 |
| **L5 구조** | 카드 5장 / 장당 1-2문장 / 1장: 질문 시작 / 5장: 위로 또는 초청 |

### 4-3. 추출된 목회 콘텐츠 공식

> **"성도의 구체적 아픔(FCF)" + "성경이 그 아픔에 말하는 것(지식)" + "성도가 익숙한 언어(보이스)"**

**이 공식의 확장:**
- 같은 본문 → 독자만 바꾸면 → 장년용/청소년용 자동 분기
- 같은 설계 → 구조만 바꾸면 → 설교문/카드뉴스/셀나눔지 자동 변환
- 이것이 반복되면 → 목회 콘텐츠 자동화 시스템의 기반

## 실습 A — 설교/묵상 콘텐츠 5레이어 설계

**⏱ 20분 | 강사 시범 → 수강생 실습 → 비포/애프터 비교**

### A-1. 실습 소재 선택

| 소재 옵션 | 활용 |
|----------|------|
| 이번 주일 설교 본문 | 가장 실전적 |
| 교회력 시즌 (고난주간·부활절·추수감사·성탄) | 시즌 콘텐츠 |
| 현재 교회 이슈 (개강·수련회·선교) | 즉시 활용 |

### A-2. 실습 순서

**① 비포 (3분)**
```
프롬프트: "[본문] 설교문 써줘" → 결과 확인 및 저장
```

**② 5레이어 설계 (10분) — 워크시트 작성**
```
Layer 1 목적:  이 설교를 들은 성도가 [   ]에서 [   ]로 변화
Layer 2 독자:  누구 / 신앙 단계 / 현재 삶의 상황 / 감정
Layer 3 보이스: 설교 어조 / 금지 표현 / 신학 용어 수위
Layer 4 지식:  본문 해석 / FCF / 핵심 적용점 (직접 제공)
Layer 5 구조:  설교문 / 카드뉴스 / 묵상문 등 형식 지정
```

**③ AI 실행 + 결과 비교 (5분)**
→ "무엇이 달라졌는가? 어떤 레이어가 가장 큰 차이를 만들었는가?"

**④ 발표 (2분)**
→ 자원자 1명이 비포/애프터 차이 공유

### A-3. 핵심 발견 포인트

- 같은 본문인데 **독자가 달라지면** 콘텐츠가 완전히 달라진다
- **Layer 4(지식)를 내가 직접 제공했을 때**와 안 했을 때의 신학적 깊이 차이
- "써줘" vs "5레이어 설계 후 써줘"의 격차

## 실습 B — 교회 소통 콘텐츠 5레이어 설계

**⏱ 20분 | 같은 메시지를 다른 형식으로 — 구조가 보이스를 바꾼다**

### B-1. 실습 목표

> 실습 A에서 설계한 **같은 지식(Layer 4)**을 가지고,
> **구조(Layer 5)만 바꿔서** 교회 소통 콘텐츠를 만든다.

**결과물 2종:**
1. 교회 SNS 카드뉴스 3장
2. 셀모임 나눔지 (또는 주보 칼럼)

### B-2. 결과물 1 — SNS 카드뉴스

| 레이어 | 설계 |
|--------|------|
| L1 목적 | 스크롤 중인 비신자/주변부 성도가 "이게 나의 이야기다" 느끼고 멈추기 |
| L2 독자 | 교회 SNS를 팔로우하는 20-40대 / 신앙 약하거나 비신자 포함 |
| L3 보이스 | 공감형 / 일상 언어 / **금지: 교회 전문 용어, 훈계, "은혜"** |
| L4 지식 | 실습 A와 동일한 핵심 메시지 (목회자가 이미 제공한 것) |
| L5 구조 | 카드 3장 / 1장: 공감 질문(15자) / 2장: 핵심(30자) / 3장: 초대(20자) |

**카드뉴스 예시 (고난주간 기준):**
```
1장 (훅):    "혼자라는 느낌, 언제 마지막이었나요?"
2장 (핵심):  그 느낌을 먼저 겪으신 분이 있습니다
             — 십자가 위에서
3장 (초대):  이번 주일, 그 이야기를 함께 들어보세요 → [교회 위치/링크]
```

### B-3. 결과물 2 — 셀모임 나눔지

| 레이어 | 설계 |
|--------|------|
| L1 목적 | 설교 메시지가 삶의 나눔으로 이어지게 한다 |
| L2 독자 | 셀모임원 / 설교를 들은 직후 / 자기 이야기를 꺼내야 하는 상황 |
| L3 보이스 | 대화 유도형 / 열린 질문 / **금지: 정답이 정해진 질문** |
| L4 지식 | 설교 핵심 요약 + 적용 질문 소재 |
| L5 구조 | 설교 요약(3문장) + 나눔 질문 4개 + 기도제목 1개 |

### B-4. 핵심 발견 포인트

> **"Layer 5(구조)가 달라지면 Layer 3(보이스)도 자동으로 달라진다"**

- 같은 본문, 같은 메시지인데 → 설교문 / 카드뉴스 / 셀나눔지가 전혀 다른 글
- **이것이 목회 콘텐츠 자동화의 핵심 원리:**
  한 번의 5레이어 설계 → 구조만 바꿔서 다양한 형식으로 자동 파생

## 마무리 — 정리 + 목회 AI 시스템 로드맵

**⏱ 15분**

### 마무리 1 — 세 개념 관계 재확인 (3분)

```
컨텍스트 엔지니어링  ⊃  컨텍스트 관리  ⊃  프롬프트 엔지니어링
```

- 프롬프트 엔지니어링은 컨텍스트 엔지니어링을 실행하는 핵심 기술
- 5레이어는 CO-STAR의 실용 버전 — 목회 콘텐츠에 최적화된 설계 도구
- **구조화가 장황한 설명을 이긴다**

### 마무리 2 — 오늘 만든 것의 의미 (5분)

| 오늘 배운 것 | 목회 AI 시스템에서의 역할 |
|-------------|------------------------|
| 5레이어 설계 경험 | → 시스템 프롬프트 설계 능력의 기반 |
| 컨텍스트 관리 루틴 | → 주간 콘텐츠 생산 파이프라인의 기초 |
| 비포/애프터 비교 | → 시스템 반복 개선 루틴의 출발점 |
| 실습 A·B 결과물 | → 나만의 목회 AI 시스템의 첫 번째 부품 |

### 마무리 3 — 목회 AI 시스템 로드맵 (5분)

> "오늘이 여러분의 목회 AI 시스템 설계 첫날입니다."

**나만의 목회 콘텐츠 자동화 시스템 — 비전:**

```
주일 본문 입력
    → 본문 해석 + FCF 발견 (목회자)
    → 5레이어 자동 적용
    → 설교문 초안 생성
    → 매일묵상 5일치 자동 파생
    → 청소년 QT 자동 변환
    → 셀나눔지 자동 생성
    → SNS 카드뉴스 자동 변환
    → 주보 칼럼 자동 축약
```

**이 시스템이 작동하려면:**
1. 각 단계마다 AI에게 넘겨지는 컨텍스트가 정밀하게 설계되어야 한다 (오늘 배운 것)
2. 맥락이 단계 간에 정확하게 전달되어야 한다 (PART 2에서 배운 것)
3. 결과물이 반복 개선될 수 있는 구조여야 한다 (비포/애프터 경험)

### 마무리 4 — 클로징 (2분)

> **"AI에게 설교를 맡기는 것이 아니라,
> 내가 설계한 신학적 환경 안에서 AI가 조립하게 한다."**
>
> 오늘 여러분이 만든 실습 결과물 하나가
> 나만의 목회 AI 시스템의 첫 번째 부품이 되었습니다.
>
> **목회자의 묵상이 깊어질수록, AI의 결과물도 깊어집니다.**
