# write-question — 질문형 칼럼 쓰기 (신문 칼럼 전용)

주제를 질문으로 분해해 논지를 잡고, 소제목 없는 1,000~1,200자 신문 칼럼 한 편으로 완성한다.

## 보조 파일 안내

이 스킬은 질문형 칼럼 워크플로우를 제공하며, 공통 집필 규칙은 보조 파일에서 참조한다. 두 파일은 write-content 등 다른 글쓰기 스킬과 공유하는 공통 자산이며, 갱신 시 함께 반영한다.

| 보조 파일 | 내용 | 참조 시점 |
|----------|------|----------|
| `references/writing-principles.md` | 공통 집필 원칙, 금지어 규칙, 분량 통제, 단어 선택 기준 | Phase 3 집필 전, Phase 4 피드백 전 |
| `references/hongstyle.md` | 홍작가 어조·리듬·논리 전개·종결어미·핵심 규칙 5가지 | Phase 3 집필 전, Phase 4 문체 점검 시 |

**읽기 규칙:** 해당 Phase 진입 시 보조 파일을 읽는다. 이미 같은 대화에서 읽은 파일은 다시 읽지 않는다.

## 언제 사용하나

- 관점·논증을 담은 칼럼·오피니언을 쓸 때
- 신문 칼럼처럼 소제목 없이 흐르는 산문 한 편이 필요할 때

## 언제 사용하지 않나

- 소제목·목차형 블로그 글 → write-blog
- 페이스북 롱폼 → write-facebook
- 일반 문서·보고서 → write-content
- 자료 조사만 → research-topic
- 부분 수정 → edit-quick

## 입력 변수

| 변수 | 필수 | 기본값 |
|------|------|--------|
| 주제 | ✓ | — |
| 독자 | 선택 | 일반 독자 |
| 분량 | 고정 | 1,000~1,200자 (±5%) |

---

## 진행 방식 (단계별 확인)

각 Phase를 한 번에 이어 붙이지 않는다. 한 Phase를 마치면 결과를 제시하고, 다음 Phase로 넘어가기 전에 수정·요청 사항을 확인한다. 확인 직후 다음 단계에서 무엇을 할지 한 줄로 예고한다.

| 전환 | 확인 사항 | 다음 단계 예고 |
|------|----------|---------------|
| Phase 1 → 2 | 질문표·선별 수정 여부 | "선별 질문을 상세 답변으로 펼칩니다" |
| Phase 2 → 3 | 답변 보강·교체 여부 | "선별 답변을 칼럼 한 편으로 집필합니다" |
| Phase 3 → 4 | 초안 방향 수정 여부 | "5항목 검토 후 다듬어 재작성합니다" |

- "한 번에 해줘"·"끝까지 진행해줘" 요청 시에만 확인 없이 연속 진행한다.
- 확인 질문은 Phase당 1개로 묶는다. 매 단락마다 묻지 않는다.

### 단계별 안내 문구 (각 Phase 종료 시 출력)

각 Phase 끝에 아래 톤으로 확인·요청을 출력한다. 문구는 상황에 맞게 다듬되, 굵게 표시한 요청은 빠뜨리지 않는다.

```
[Phase 1 종료]
선별 질문을 바꾸거나 추가할 부분이 있으면 알려주세요.
없으면 다음으로 9개 질문 전체를 상세 답변으로 펼칩니다.

[Phase 2 종료]  ※ 본인 경험 요청 필수
각 질문 답변에 직접 겪은 경험을 한 줄씩 넣어 주시면 칼럼에 반영합니다.
경험이 들어가면 평균적인 설명에서 벗어나 글이 살아납니다.
보강하거나 선별을 바꿀 부분이 있으면 알려주세요.
없으면 선별 답변을 칼럼 한 편으로 집필합니다.

[Phase 3 종료]  ※ 제목 5개 제시
제목 후보 5개를 함께 올렸습니다. 쓰실 제목을 골라 주시거나 직접 알려주세요.
초안 방향을 바꿀 부분이 있으면 알려주세요.
없으면 5항목을 검토해 다듬어 재작성합니다.

[Phase 4 종료]
네 단계를 마쳤습니다. 이 칼럼이 최종본입니다.
파일(.docx 등) 저장이 필요하면 알려주세요.
```

---

## Phase 0. 입력 수집

- 주제를 확인한다. 독자가 없으면 일반 독자로 두고, 적용값을 한 줄로 안내한다.
- 분량은 1,000~1,200자로 고정한다.

## Phase 1. 질문 도출 & 선별 (내부 뼈대)

세 프레임으로 질문을 만들어 논지를 잡는다. 이 단계의 질문은 칼럼의 설계도일 뿐, 본문 표면에는 드러내지 않는다.

- **무엇(What)**: 주제의 핵심 개념·범위
- **왜(Why)**: 중요한 이유·배경
- **어떻게(How)**: 방법·실행

각 프레임 3개씩, 총 9개를 표로 만든다.

| 프레임 | 질문 | 한 줄 의견 | 내 경험 메모 |
|--------|------|-----------|--------------|

선택 프레임(주장·논쟁 칼럼이면 사용 가능): 쟁점 → 근거 → 예상 반론 → 제언.

규칙:
- 9개 중 **핵심 2~3개를 선별**한다(1,000~1,200자에는 논거 2~3개가 적당). 독자 기준으로 추천하고 사용자가 조정한다.
- 선별 질문을 칼럼의 전개 단락 뼈대로 삼되, 질문 문장이나 소제목으로 노출하지 않는다.

## Phase 2. 질문 상세 답변 (선택)

질문의 답을 칼럼으로 압축하기 전에 답변 카드로 펼친다. 다음 신호가 있을 때만 실행하고, 신호가 없으면 건너뛰고 Phase 3으로 간다.

**실행 신호**: "상세 답변", "질문 답변 펼쳐줘", "답변 카드", "Phase 2 진행", "내용 먼저 보고" 또는 글 처음 쓰는 독자 대상 교육용 요청.

### 두 가지 모드

| 모드 | 대상 | 분량 | 성격 | 본문 분량 제약 |
|------|------|------|------|---------------|
| **압축** (기본) | 선별 3개 | 카드당 200~300자 | 칼럼 집필 재료 | 본문보다 짧게 유지 |
| **상세** (요청·교육용) | **9개 전체** | 질문당 400~600자 | 독자 이해용 해설 | 제약에서 분리 |

- 글 처음 쓰는 청년 등 교육용 요청이면 **상세 모드를 자동 적용**한다.
- 상세 모드는 Phase 1의 9개 질문을 하나도 빠뜨리지 않고 9개 모두 카드로 구분해 출력한다. 선별된 3개는 카드에 "칼럼 반영: O"로 표시하고, 나머지 6개는 "보류"로 표시한다.
- 상세 모드는 산출물 자체가 목적이라 본문 분량과 분리하되, 질문당 600자 상한으로 길어지지 않게 막는다.

### 출력 형식 (질문당 1블록)

```
[질문] (질문 그대로) [What/Why/How]

핵심 답변  : (한 문장 결론)
근거·사례  : (수치·사례·비유)
본인 경험  : (넣을 경험 메모, 없으면 "없음")
칼럼 반영  : O / 보류
```

### 분량 가드레일

- 압축 모드: 카드당 200~300자. 선별 3개 합계 900자 이내.
- 상세 모드: 카드당 400~600자. 9개 전체이므로 카드별 상한(600자)을 반드시 지킨다.
- 근거·사례는 핵심을 떠받치는 것만 적는다. 자료 나열은 하지 않는다.

### 연결

- 선별(칼럼 반영: O) 카드의 핵심 답변·근거가 Phase 3 전개 단락의 입력이 된다.
- "보류" 카드는 집필에서 제외하되, 9개를 본 뒤 선별을 바꾸고 싶으면 이 단계에서 조정한다.
- 채택 카드 수가 2개 미만이면 선별을 보강한다.

### 본인 경험 요청 (종료 시 필수)

답변 카드의 "본인 경험"이 비어 있으면(없음), 9개 제시 후 사용자에게 경험을 넣어 달라고 요청한다. AI가 만든 평균적 설명은 매끄럽지만 비어 보인다. 글쓴이가 직접 겪은 한 장면이 들어가야 칼럼이 살아난다. 경험을 받으면 해당 카드에 반영하고, 받지 못하면 Phase 3에서 일반론으로 집필하되 경험 자리를 비워 두지 않는다.

## Phase 3. 칼럼 집필

> **이 단계 진입 시** `references/writing-principles.md`와 `references/hongstyle.md`를 읽는다.

선별 질문의 답(또는 Phase 2 채택 카드)을 신문 칼럼 형식으로 쓴다.

**형식**
- 제목 후보 5개를 제시하고 사용자가 고른다. 칼럼 본문 위에 함께 올린다. 다섯 개는 서로 다른 각도(은유형·선언형·대비형·질문형·핵심어형)를 섞고, 각 제목은 관점이 담긴 한 줄로 둔다.
- 소제목·목차·번호·볼드는 쓰지 않는다.
- 단락 구성: 도입 1단락 → 전개 2~3단락 → 마무리 1단락. 단락 사이를 자연스럽게 잇는다.
- '서론'·'본론'·'결론'이라는 단어를 본문에 쓰지 않는다. 구분은 흐름으로만 둔다.

**제목 5개 생성 기준**

1. **본문 완성 후 제목을 뽑는다.** 제목을 먼저 발명하지 않는다. 좋은 칼럼 제목은 본문 안에 이미 있으며, 가장 강한 문장·대비·이미지를 끌어올린다.
2. **품질 체크 5항목** — 후보를 만든 직후 점검한다.
   - 본문에서 길어올렸는가 (본문과 따로 노는 제목 금지)
   - 긴장이 있는가 (두 개념의 대비·반전)
   - 추상명사를 뺐는가 (동사·장면 중심, "~의 중요성" 금지)
   - 마무리와 호응하는가 (제목이 칼럼의 관점 재정렬을 가리킴)
   - 소리 내 읽었을 때 리듬이 있는가 (대구·반복·두운, 낚시·과장 금지)
3. **5각도 분배** — 은유형·선언형·대비형·질문형·핵심어형을 섞고, 표현만 바꾼 중복은 제외한다.
4. **공통 제약** — 15자 내외, 과장형 형용사 금지, 본문 톤과 일치.

**제목 출력 형식**
- 후보 5개 각각에 강점·노리는 독자 반응을 한 줄로 붙인다.
- 5개 중 1개를 ★로 추천하고, 추천 이유를 한 줄로 적는다.

```
제목 후보 (★ 추천)
1. (제목)        ← (강점·노리는 반응 한 줄)
2. (제목)   ★    ← (강점·노리는 반응 한 줄)
3. (제목)        ← ...
4. (제목)        ← ...
5. (제목)        ← ...

추천: 2번. (선택 이유 한 줄)
```

**도입 (인트로)**

첫 단락이 독자를 붙드는 지점이다. 추상 진술이 아니라 구체 장면이나 독자의 문제 상황에서 출발한다(hongstyle 서술 전략).

- **훅 유형 5종 중 1개 선택** — 글 성격에 맞게 고른다.

| 유형 | 첫 문장 방식 | 적합한 글 |
|------|-------------|----------|
| 장면형 | 독자가 처한 구체 순간을 묘사 | 경험·일상 밀착 주제 |
| 통념 뒤집기형 | 다들 믿는 전제를 먼저 제시하고 흔든다 | 관점 전환 주제 |
| 질문형 | 독자가 속으로 답하게 되는 물음 | 판단을 요구하는 주제 |
| 대비형 | 두 상황·두 입장을 나란히 세운다 | 선택·갈등 주제 |
| 현장 사실형 | 구체 수치·사례 한 줄로 시작 | 근거가 분명한 주제 |

- **도입 금지 패턴** — 사전적 정의로 시작("AI란 ~이다"), 일반론("기술이 세상을 바꾸고 있다"), "최근 ~가 화제다" 식 진부한 도입, 기능·현상 나열.
- **논점은 비추기만 한다** — 도입에서 결론을 다 말하지 않는다. 마지막 문장에서 다룰 논점을 슬쩍 비춰 긴장을 남긴다.

도입 자가점검 3항목: 첫 문장이 구체 장면·독자 상황인가 / 일반론으로 시작하지 않았는가 / 제목과 호응하는가.

**전개**
- 선별 질문 하나를 한 단락에서 다룬다. 단락마다 주장 + 근거(사례·수치)를 함께 담는다.
- 출처는 별도 표기 대신 문장 안에 녹인다(예: "고용노동부 조사에 따르면").

**마무리**
- 논점을 한 단락으로 모으고, 한 문장으로 메시지를 남긴다.

**분량**
- 1,000~1,200자(±5%)를 지킨다. 초과 시 수식·중복을 덜어내고, 미달 시 사례를 보강한다.

## Phase 4. 피드백 & 재작성

> **이 단계 진입 시** `references/writing-principles.md`의 금지어·리라이팅 원칙과 `references/hongstyle.md`의 문체 기준으로 점검한다. (Phase 3에서 이미 읽었다면 다시 읽지 않는다.)

칼럼을 5항목으로 검토하고, 개선을 반영해 전체를 다시 쓴다.

**검토 항목**
1. 내용: 논지가 분명한가
2. 구조: 도입 → 전개 → 마무리 흐름이 끊기지 않는가
3. 표현: 간결하고 칼럼다운가(군더더기·상투어 없음)
4. 사실·출처: 수치·이름·인용에 오류나 출처 누락이 없는가
5. 문체: 톤이 일관되고 소제목 없이 흐르는가

**출력 형식**
- 상단에 변경 요약 3줄(무엇을 왜 고쳤는지)을 분리해 적는다.
- 본문은 깔끔한 산문으로 재작성한다(볼드·소제목 없음). 분량 1,000~1,200자 유지.

## 출력 예시(형태 참고)

```
제목 후보 (★ 추천)
1. (은유형)        ← (강점 한 줄)
2. (선언형)        ← (강점 한 줄)
3. (대비형)   ★    ← (강점 한 줄)
4. (질문형)        ← (강점 한 줄)
5. (핵심어형)      ← (강점 한 줄)
추천: 3번. (이유 한 줄)

본문 (제목 확정 전에는 추천 후보 임시 표기)

(도입 단락) … 훅 유형 1개로 첫 문장 …
(전개 단락 1) … 선별 질문 1의 답 + 근거 …
(전개 단락 2) … 선별 질문 2의 답 + 근거 …
(마무리 단락) … 논점 정리 + 한 문장 …
```

## 가드레일 (하네스)

- 금지어 0건: 혁신적인, 획기적인, 완벽한, 매우, 쉽게, 빠르게, "~할 수 있습니다 + 추상명사 중심문장" (상세 규칙은 `references/writing-principles.md`)
- 서술형 산문, ~합니다체, 축약형 금지, 소제목·볼드·목차 금지
- 한국어 산출물은 한국어로 작성
- 완성 후 완성 조건·분량(1,000~1,200자) 점검 → 미달 시 수정 후 재점검(최대 2회)

## 연계 스킬

- 입력(선택): research-topic — 자료·근거 보강
- 출력(선택): write-blog(소제목형 블로그 전환) / write-facebook(페북 전환)
- 부분 수정: edit-quick

## 산출물

- 대화창: 질문표(선별) → [선택] 답변 카드(본인 경험 요청) → 칼럼 초안(제목 5개 + 산문) → 피드백·재작성본
- 파일 저장은 사용자가 요청할 때만

## 실행 원칙

- 각 Phase를 마치면 멈춰 확인하고, 다음 단계를 한 줄로 예고한다. "한 번에 해줘" 요청 시에만 연속 진행한다.
- Phase 1 선별을 건너뛰지 않되, 질문을 본문 표면에 드러내지 않는다.
- Phase 2(상세 답변)는 실행 신호가 있을 때만 진행한다. 압축 모드는 선별 3개·카드당 200~300자, 상세 모드는 9개 전체·카드당 400~600자로 둔다.
- 소제목을 만들지 않는다. 칼럼은 단락 흐름으로만 구분한다.
- 분량 1,000~1,200자를 넘기지 않는다.
