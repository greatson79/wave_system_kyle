# Wave Content Studio 사용자 참여형 루프 설계

## 목표

Wave Content Studio의 자동 연쇄 실행을 사용자 참여형 단계 루프로 바꾼다. 각 전문 스킬은 실행 전에 사용자의 방향 결정을 받고, 결과를 프로젝트의 `workspace/`에 저장한 뒤 사용자 확인을 기다린다. 명확한 승인 전에는 다음 스킬로 이동하지 않는다.

## 범위

다음 스킬과 공통 계약을 수정한다.

- `content-studio-orchestrator`
- `content-topic-strategist`
- `content-researcher`
- `source-validator`
- `blog-article-writer`
- `article-editor`
- `sites-blog-publisher`
- 단계 판정 스크립트, 공통 정책, 실행 보고서, 계약 테스트

외부 게시의 고정 승인 문구와 Sites 프로젝트는 변경하지 않는다.

## 상호작용 계약

각 단계는 다음 상태 전이를 따른다.

```text
단계 진입
→ 현재 입력·산출물·제약 요약
→ 단계별 방향 질문
→ 사용자 입력 기록
→ 스킬 실행 및 결과 파일 저장
→ 결과·경로·검토 항목 보고
→ 사용자 확인 대기
   ├─ 명확한 승인 → 다음 단계의 사전 질문
   ├─ 수정 요청 → 같은 단계 수정 후 다시 확인
   └─ 모호한 응답 → 승인 또는 수정 여부 확인
```

자연스러운 승인 표현을 허용한다. 예: `좋아`, `다음으로`, `이대로 진행해`, `수정 없이 진행해`. 단, 수정 요청이 함께 있거나 승인 여부가 모호하면 승인으로 처리하지 않는다.

사용자 응답 없이 시간 경과, 파일 생성 성공, 테스트 통과만으로 다음 단계에 자동 진입하지 않는다.

## 단계별 사용자 결정

### 기획

실행 전 주제, 독자, 목적을 필수로 확인한다. 이미 확정된 값은 다시 묻지 않는다. 톤, 범위, 분량, CTA 등 미확정 선택지 중 결과에 가장 큰 영향을 주는 항목을 한 번에 이해하기 쉬운 형태로 제시한다.

결과 저장 후 `content-brief.md`의 주제, 독자, 목적, 핵심 주장, 범위와 제외 사항을 요약해 확인받는다.

### 리서치

실행 전 조사 질문, 조사 범위, 선호하거나 제외할 출처 유형을 확인한다. 외부 접근이 필요한 경우 이 질문과 기존 외부 리서치 승인 게이트를 하나의 명확한 요청으로 결합한다.

결과 저장 후 수집한 출처 수, 핵심 주장 후보, 미해결 항목과 두 결과 파일을 보고하고 확인받는다.

### 출처 검증

실행 전 최신성 기준, 보수성, 반드시 재확인할 주장이나 출처를 확인한다.

결과 저장 후 승인·거절·추가 검토 출처 및 연결 수, 집필 가능 범위와 검증 문서 경로를 보고하고 확인받는다.

### 작성

실행 전 구조, 문체, 분량, CTA와 반드시 유지하거나 피할 요소를 확인한다. 기획서에 이미 확정된 항목은 기본값으로 제시한다.

결과 저장 후 제목, 구조, 분량, 사용 근거와 확인 필요 사항을 요약하고 초안 경로를 보고한 뒤 확인받는다.

### 편집

실행 전 편집 강도와 반드시 유지할 표현·구조를 확인한다.

결과 저장 후 주요 수정, 삭제·약화한 주장, 분량, 판정과 두 결과 파일을 보고하고 확인받는다.

### 게시

게시 전에는 기존대로 정확한 문구 `승인 포스팅해줘`만 승인으로 인정한다. 자연어 승인 규칙은 로컬 콘텐츠 단계에만 적용한다.

## 상태 기록

`workspace/pipeline-run-report.md`에 각 단계별로 다음을 기록한다.

- 실행 전 사용자 방향
- 생성·변경한 결과 파일
- 결과 요약
- 사용자 확인 상태: `AWAITING_USER_REVIEW`, `REVISION_REQUESTED`, `APPROVED`
- 승인 또는 수정 요청의 원문 요약
- 다음 허용 단계

각 전문 산출물의 기존 도메인 상태는 유지한다. 사용자 확인 상태는 별도 워크플로 상태로 기록하여 `VALIDATION_COMPLETE`, `PASS` 같은 품질 판정과 혼합하지 않는다.

## 재개 규칙

오케스트레이터는 파일 존재와 내부 품질 상태뿐 아니라 마지막 사용자 확인 상태도 검사한다.

- 결과 파일이 있고 확인 상태가 `AWAITING_USER_REVIEW`이면 해당 단계 결과를 다시 제시하고 기다린다.
- `REVISION_REQUESTED`이면 같은 전문 스킬을 수정 지시와 함께 다시 실행한다.
- `APPROVED`일 때만 다음 단계의 사전 질문으로 이동한다.
- 선행 파일이 사용자 또는 도구에 의해 바뀌면 해당 파일을 직접 소비하는 첫 후속 단계의 승인을 무효화한다.
- 완성된 편집 결과가 승인되었으면 게시 승인 대기로 이동한다.
- 게시 완료 보고서가 유효하면 `PUBLISHED`로 판정한다.

## 오류 처리

- 사용자 방향이 부족하면 결과에 가장 큰 영향을 주는 질문 하나만 한다.
- 사용자 응답이 승인인지 수정인지 불분명하면 추정하지 않고 한 번 확인한다.
- 결과 파일 저장에 실패하면 확인 단계로 이동하지 않는다.
- 같은 단계가 두 번 연속 실패하면 자동 재시도를 멈춘다.
- 기존 결과를 수정할 때는 영향을 받는 파일을 알리고 덮어쓰기 승인을 받는다.

## 테스트 설계

기존 계약 테스트에 다음 회귀 테스트를 먼저 추가한다.

- 단계 결과 생성 후 자동으로 다음 단계로 넘어가지 않고 `AWAITING_USER_REVIEW`가 된다.
- 명확한 자연어 승인 후에만 다음 단계가 선택된다.
- 수정 요청은 같은 단계의 `REVISION_REQUESTED`가 된다.
- 모호한 응답은 승인으로 처리되지 않는다.
- 로컬 단계의 자연어 승인이 Sites 게시 승인으로 재사용되지 않는다.
- 완성 상태가 `COMPLETE` 또는 게시 승인 대기로 정상 판정된다.
- 게시 완료 상태가 `PUBLISHED`로 판정된다.
- 선행 산출물 변경 시 후속 승인 상태가 무효화된다.

플러그인 검증, 7개 스킬 검증, 셸 문법 검사, Python 문법 검사와 전체 계약 테스트를 최종 게이트로 실행한다.

## 비목표

- UI 폼이나 별도 웹 애플리케이션 제작
- 백그라운드 자동화
- 게시 대상 Sites 프로젝트 변경
- 이미지·카드뉴스·영상 제작 기능 추가
- 기존 출처 이중 승인 정책 완화
