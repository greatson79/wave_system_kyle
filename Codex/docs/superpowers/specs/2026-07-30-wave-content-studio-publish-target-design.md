# Wave Content Studio 게시 대상 선택 설계

## 목표

편집 결과가 승인된 뒤 고정 Sites 프로젝트를 전제하지 않고 사용자가 게시 여부와 대상을 직접 선택하게 한다. 기존 개인 블로그에는 연결 가능한 수단으로 업로드하고, 새 Sites 블로그를 원하면 생성 후 게시하며, 게시를 원하지 않으면 최종 원고만 제공하고 종료한다.

## 게시 대상 선택

편집 결과의 품질 판정이 `PASS`이고 사용자가 편집 결과를 승인하면 다음 선택을 요청한다.

1. 기존 개인 블로그에 게시
2. 새 Sites 블로그를 생성해 게시
3. 게시하지 않고 최종 원고만 받고 종료

선택 전에는 블로그 계정 조회, 사이트 생성, 업로드 같은 외부 작업을 수행하지 않는다.

## 상태 흐름

```text
EDITING APPROVED
→ PUBLISH_TARGET_REQUIRED
   ├─ PERSONAL_BLOG
   │   → 대상·플랫폼 확인
   │   → 연결 가능성 검사
   │   ├─ 가능: PUBLISH_TARGET_READY
   │   │        → 게시 미리보기
   │   │        → 명시적 승인
   │   │        → 게시
   │   └─ 불가·실패: PUBLISH_FAILED_AWAITING_DECISION
   │                ├─ 연결 보완 후 재시도
   │                ├─ NEW_SITES
   │                └─ COMPLETE_NO_PUBLISH
   ├─ NEW_SITES
   │   → 사이트 이름·주소·공개 범위 확인
   │   → 생성 및 게시 미리보기
   │   → 명시적 승인
   │   → 사이트 생성·게시
   └─ NO_PUBLISH
       → 최종 원고·게시 메타데이터 제공
       → COMPLETE_NO_PUBLISH
```

## 개인 블로그

### 입력

- 플랫폼
- 대상 블로그 이름 또는 URL
- 필요한 경우 사용자가 선택한 계정·사이트
- 제목, slug 또는 permalink, 카테고리·태그, 공개 상태

### 연결 가능성 확인

현재 환경에서 실제로 사용할 수 있는 연결, 앱, MCP, 공식 API 또는 사용자 제공 배포 경로만 사용한다. 존재하지 않는 도구나 권한을 가정하지 않는다.

연결 수단이 있으면 읽기 전용 확인으로 대상 블로그와 게시 기능을 검증한다. 여러 계정이나 블로그가 발견되면 사용자가 정확한 대상을 선택할 때까지 게시하지 않는다.

연결 수단이 없거나 인증·권한·API 제약으로 게시할 수 없으면 해당 플랫폼에 붙여넣기 좋은 최종 원고와 게시 메타데이터를 제공할 수 있다.

### 게시 승인

실제 업로드 전에 다음 미리보기를 보여주고 명시적 승인을 받는다.

- 플랫폼과 대상 블로그
- 제목과 예상 URL
- 공개 상태
- 카테고리·태그
- 최종 원고 지문
- 생성·수정될 외부 항목

로컬 단계의 자연어 승인을 게시 승인으로 재사용하지 않는다.

## 새 Sites 블로그

사용자가 새 Sites 블로그를 선택하면 다음을 확인한다.

- 사이트 이름
- 원하는 주소 또는 slug
- 공개 범위
- 기본 설명과 브랜딩 입력

사이트 생성과 첫 글 게시는 외부 변경이므로 생성·게시 미리보기를 먼저 보여주고 명시적으로 승인받는다. 기존 고정 Project ID는 신규 Sites 분기에서 사용하지 않는다. 생성 결과로 받은 실제 Project ID와 URL을 게시 요청에 기록한다.

## 게시하지 않음

사용자가 게시하지 않기를 선택하면 다음을 제공하고 `COMPLETE_NO_PUBLISH`로 종료한다.

- `workspace/final-article.md`
- 제목, 요약, slug 제안, 카테고리·태그
- 사용한 검증 근거
- 플랫폼 독립적인 Markdown 원고

외부 계정 조회, 사이트 생성 또는 게시 요청 파일 생성은 수행하지 않는다.

## 실패 후 재결정

개인 블로그 또는 Sites 작업이 실패하면 자동 재시도·자동 Sites 우회·자동 종료를 하지 않는다. 실패 지점, 원인, 외부 변경 발생 여부와 보존된 결과를 보고하고 `PUBLISH_FAILED_AWAITING_DECISION`에서 사용자에게 다음 행동을 묻는다.

- 연결이나 입력을 보완해 같은 대상으로 재시도
- 새 Sites 블로그 생성으로 전환
- 최종 원고만 받고 `COMPLETE_NO_PUBLISH`로 종료

사용자가 선택한 행동만 실행한다.

## 게시 요청 계약

`workspace/publication-request.json`은 고정 Sites 전용 구조에서 대상 독립 구조로 확장한다.

- `target.mode`: `PERSONAL_BLOG` 또는 `NEW_SITES`
- `target.platform`
- `target.site_name`
- `target.site_url`
- `target.project_id`: Sites 생성 후에만 기록
- `target.visibility`
- 원고와 게시 메타데이터 지문
- 게시 승인 상태와 승인 문구 또는 승인 응답 요약

대상, 공개 범위, 원고 또는 게시 메타데이터가 바뀌면 기존 승인을 무효화한다.

`NO_PUBLISH` 선택에서는 게시 요청을 만들지 않는다.

## 스킬 구조

- `content-studio-orchestrator`: 편집 승인 후 게시 대상 선택과 실패 후 재결정을 관리한다.
- `sites-blog-publisher`: 고정 프로젝트 전제를 제거하고, 선택된 기존 Sites 또는 새로 생성한 Sites에만 게시한다.
- 신규 `personal-blog-publisher`: 현재 제공된 연결 수단으로 개인 블로그 게시 가능성을 확인하고, 미리보기·승인·업로드·실패 보고를 담당한다.
- 공통 게시 정책: 대상 선택, 외부 쓰기 승인, 실패 후 재결정, 무게시 종료를 정의한다.

특정 플랫폼 전용 API가 실제로 없으면 신규 게시 스킬이 성공을 가장하지 않고 `PUBLISH_FAILED_AWAITING_DECISION`과 최종 원고 제공 경로를 반환한다.

## 테스트

- 편집 승인 후 `PUBLISH_TARGET_REQUIRED`
- 개인 블로그 선택 시 대상 정보 누락 차단
- 복수 대상의 사용자 선택 요구
- 연결 불가 시 외부 쓰기 없이 실패 후 재결정
- 게시 미리보기 승인 전 업로드 차단
- 새 Sites 선택 시 생성 정보와 별도 승인 요구
- Sites 생성 실패 후 재결정
- 무게시 선택 시 `COMPLETE_NO_PUBLISH`
- 실패 후 사용자가 고른 분기만 실행
- 대상·공개 범위·원고 변경 시 승인 무효화
- 로컬 단계 자연어 승인의 게시 승인 재사용 차단

## 비목표

- 모든 블로그 플랫폼에 대한 비공식 자동화 제공
- 사용자 승인 없는 계정 탐색이나 외부 게시
- 실패 시 자동 우회
- 예약 게시
- 기존 글의 삭제 또는 덮어쓰기
