# 강사용 강의안

# Codex로 개인/이벤트 랜딩페이지 자동 제작하기

부제: 기획서 한 장에서 배포 링크, QR, OG 이미지, 검증 자동화까지

## 1. 강의 포지셔닝

이 강의는 HTML/CSS 문법 수업이 아니다. 수강생이 Codex를 "코드를 대신 써주는 도구"가 아니라 "요구사항을 읽고, 파일을 만들고, 검증하고, 배포까지 반복하는 실행형 AI 에이전트"로 사용하는 법을 익히는 수업이다.

핵심 산출물은 개인 또는 이벤트 랜딩페이지다. 수강생은 자기 브리프를 바탕으로 페이지를 만들고, CTA와 공유 이미지, 검증 스크립트, Vercel 배포 주소까지 완성한다.

## 2. 사전 설치와 준비물

### 필수 준비

| 항목 | 목적 | 확인 방법 |
|---|---|---|
| Codex Desktop 또는 Codex CLI | 에이전트 작업 실행 | Codex에서 작업 폴더 열기 |
| Node.js | 로컬 검증과 정적 서버 실행 | `node -v` |
| npm | 스크립트 실행 | `npm -v` |
| Vercel CLI | 배포 | `vercel --version` |
| Vercel 로그인 | 프로덕션 배포 | `vercel whoami` |
| Git 기본 사용 환경 | 변경 이력 확인 | `git status` |
| 브라우저 | 로컬/배포 확인 | localhost 또는 file URL 열기 |

Vercel이 없다면 강의 전 설치:

```bash
npm i -g vercel
vercel login
```

## 3. 수강생 도착점

강의가 끝나면 수강생은 다음을 갖는다.

- 개인/이벤트 랜딩페이지 HTML
- CTA 버튼과 신청/문의/후원 링크
- 카카오톡 공유용 OG 이미지
- 필수 문구와 금지 문구를 확인하는 검증 스크립트
- Vercel 배포 주소
- 다음 프로젝트에 재사용할 자동화 프롬프트

## 4. 강의 구조: 2시간 실습형

| 시간 | 세션 | 강사 목표 | 수강생 산출물 |
|---:|---|---|---|
| 0:00-0:10 | 오프닝 | Codex를 실행형 에이전트로 소개 | 작업 폴더 열기 |
| 0:10-0:25 | 준비물 점검 | 설치/로그인/폴더 구조 확인 | `vercel`, `node`, `npm` 확인 |
| 0:25-0:40 | 브리프 작성 | 랜딩페이지 요구사항 카드 작성 | 랜딩페이지 브리프 |
| 0:40-1:05 | MVP 제작 | Codex에게 구조 설계 후 구현 지시 | 첫 HTML/CSS 버전 |
| 1:05-1:25 | 실전 요소 추가 | CTA, QR, footer, OG 이미지 추가 | 공유 가능한 페이지 |

## 5. 강사 진행 대본

### 오프닝

말할 것:

> 오늘은 코딩을 배우는 시간이 아니라, Codex에게 실제 일을 맡기는 방법을 배웁니다. 목표는 예쁜 화면 하나가 아닙니다. 기획, 제작, 검증, 배포, 공유 문제 해결까지 이어지는 전체 흐름입니다.

보여줄 것:

- 완성된 랜딩페이지
- 카카오톡 공유 카드
- `npm run verify` 결과
- Vercel 배포 주소

강조:

- 프롬프트는 명령문이 아니라 작업 계약서다.
- 좋은 에이전트 작업은 "만들어줘"보다 "읽고, 계획하고, 작게 고치고, 검증해줘"가 강하다.

### 준비물 점검

진행:

```bash
node -v
npm -v
vercel --version
vercel whoami
```

문제가 생기면:

- Node/npm 없음: 데모를 따라 보게 하고 실습은 페어로 진행
- Vercel 로그인 안 됨: 로컬 완성까지만 진행하고 배포는 강사 데모로 대체
- Codex 권한 문제: 작업 폴더를 단순 경로로 이동

### 브리프 작성

수강생에게 작성하게 할 입력:

```markdown
# 랜딩페이지 제작 브리프

종류:
페이지 제목:
부제:
대상:
핵심 메시지:
일시/장소:
주요 CTA:
연결할 링크:
연락처:
대표 이미지 방향:
꼭 들어갈 문구:
절대 들어가면 안 되는 문구:
배포 희망 경로:
```

강사 팁:

- 브리프가 길어도 괜찮지만, CTA는 하나만 먼저 고르게 한다.
- 초보자는 개인 프로필보다 이벤트 페이지가 쉽다. 일정, 대상, CTA가 명확하기 때문이다.

### MVP 제작

핵심 프롬프트:

```text
이 브리프를 바탕으로 랜딩페이지 MVP를 만들어줘.

먼저 할 일:
1. 현재 폴더 구조를 읽어라.
2. 어떤 파일을 만들지 계획해라.
3. 구현 전에 페이지 섹션 구조를 제안해라.

구현 조건:
- 정적 HTML/CSS/JS로 충분하면 프레임워크를 추가하지 마라.
- 첫 화면에 제목, 부제, 핵심 CTA가 보여야 한다.
- 모바일 대응을 포함해라.
- 완료 후 검증 방법을 알려줘.

브리프:
[여기에 브리프 붙여넣기]
```

강사 멘트:

> 여기서 중요한 것은 바로 만들게 하지 않는 것입니다. 먼저 읽고, 계획하고, 구조를 제안하게 해야 합니다. 그래야 Codex가 작업 공간을 이해한 뒤 움직입니다.

### CTA, QR, OG 이미지 추가

핵심 프롬프트:

```text
랜딩페이지에 실제 공유와 신청에 필요한 요소를 추가해줘.

추가할 것:
- CTA 버튼
- 신청/문의/후원 링크
- QR 이미지 영역
- footer 정보
- 개인정보 문의 문구
- 카카오톡 공유용 og:title, og:description, og:image

주의:
- QR 이미지가 대표 og:image로 잡히면 안 된다.
- og:image는 별도 대표 이미지로 지정한다.
- 배포 주소 기준 절대 URL을 사용한다.
```

강사 팁:

- 카카오톡 미리보기 문제는 좋은 교육 소재다.
- "페이지 안에 있는 이미지"와 "공유 대표 이미지"가 다르다는 것을 설명한다.

### 검증 자동화

핵심 프롬프트:

```text
이 랜딩페이지 요구사항을 검증하는 스크립트를 만들어줘.

검증해야 할 것:
- 필수 문구가 모두 있는지
- CTA 링크가 있는지
- footer 정보가 있는지
- og:image가 QR 이미지가 아닌 대표 이미지인지
- 금지 문구가 없는지
- 배포용 공유 경로가 있는지

요구:
- package.json의 npm run verify로 실행되게 해라.
- 가능하면 먼저 실패하는 검증 조건을 만들고, 수정해서 통과시켜라.
```

강사 멘트:

> AI 작업에서 제일 위험한 말은 "아마 됐을 겁니다"입니다. 검증 스크립트는 Codex가 놓친 것을 잡아주는 안전벨트입니다.

### Vercel 배포

핵심 프롬프트:

```text
검증이 통과하면 Vercel에 프로덕션 배포해줘.

순서:
1. npm run verify 실행
2. vercel --prod --yes 실행
3. 배포 URL 확인
4. curl로 배포된 HTML의 og:image 확인
5. 최종 공유 URL을 알려줘

주의:
- 검증 실패가 있으면 배포하지 마라.
- 카카오톡 캐시 문제가 생길 수 있으므로 캐시 우회용 공유 URL도 제안해라.
```

## 6. 실습 운영 방식

권장 방식:

1. 강사가 전체 흐름을 1회 데모한다.
2. 수강생은 자기 브리프로 같은 흐름을 반복한다.
3. 막힌 사람은 "현재 상태를 읽고 문제를 진단해줘" 프롬프트부터 사용하게 한다.
4. 마지막 10분은 서로 배포 URL을 공유한다.

수강생이 막히는 지점:

- 브리프가 너무 추상적임
- CTA가 여러 개라 우선순위가 흐림
- Vercel 로그인을 못함
- OG 이미지가 카카오톡에서 바로 안 바뀜
- Codex가 너무 많은 파일을 만들려고 함

강사 대응:

- 브리프를 줄인다.
- CTA를 하나로 줄인다.
- 배포가 막히면 로컬 완성까지 성공으로 인정한다.
- 카카오 캐시는 새 경로 또는 쿼리스트링으로 우회한다.
- Codex가 과하게 움직이면 "수정 범위를 이 파일 하나로 제한해"라고 지시한다.

## 7. 마지막 자동화 설계

수강생에게 보여줄 최종 목표:

```text
다음 브리프를 바탕으로 개인/이벤트 랜딩페이지를 끝까지 제작해줘.

자동으로 수행할 것:
1. 요구사항 분석
2. 페이지 구조 설계
3. MVP 구현
4. CTA/QR/OG/footer 추가
5. 검증 스크립트 작성
6. npm run verify 통과
7. Vercel 배포
8. 배포 URL과 카카오톡 공유용 URL 보고

브리프:
[여기에 브리프 붙여넣기]
```

확장 설명:

- Prompt: 한 번 쓰는 지시문
- Skill: 반복 가능한 작업 매뉴얼
- Plugin: 여러 도구와 외부 서비스를 묶은 실행 환경

이 강의의 다음 단계는 위 마스터 프롬프트를 `landing-page-factory` 스킬로 만드는 것이다.

## 8. 강사 체크리스트

강의 전:

- Vercel 로그인 확인
- 데모용 브리프 준비
- 대표 이미지 1장 준비
- QR 또는 신청 링크 준비
- 네트워크 안 될 때 사용할 로컬 완성 예시 준비

강의 중:

- Codex가 읽기 전에 만들지 않게 한다.
- 작업 범위를 매번 좁힌다.
- 검증 없이 완료라고 말하지 않게 한다.
- 배포 후 실제 URL을 열어본다.

강의 후:

- 수강생에게 프롬프트 팩 배포
- 배포 URL 제출 받기
- 다음 단계로 Skill화 과제 제안
