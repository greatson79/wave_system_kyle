Codex로 개인/이벤트 랜딩페이지 자동 제작하기

기획서 한 장에서 배포 링크, QR, OG 이미지, 검증 자동화까지

1. 강의 포지셔닝

이 강의는 HTML/CSS 문법 수업이 아니다. 수강생이 Codex를 "코드를 대신 써주는 도구"가 아니라 "요구사항을 읽고, 파일을 만들고, 검증하고, 배포까지 반복하는 실행형 AI 에이전트"로 사용하는 법을 익히는 수업이다.

핵심 산출물은 개인 또는 이벤트 랜딩페이지다. 수강생은 자기 브리프를 바탕으로 페이지를 만들고, CTA와 공유 이미지, 검증 스크립트, Vercel 배포 주소까지 완성한다.

3. 수강생 도착점

  • 개인/이벤트 랜딩페이지 HTML
  • CTA 버튼과 신청/문의/후원 링크
  • 카카오톡 공유용 OG 이미지

  • 다음 프로젝트에 재사용할 자동화 프롬프트

5. 강사 진행 대본

오프닝

오늘은 코딩을 배우는 시간이 아니라, Codex에게 실제 일을 맡기는 방법을 배웁니다. 목표는 예쁜 화면 하나가 아닙니다. 기획, 제작, 검증, 배포, 공유 문제 해결까지 이어지는 전체 흐름입니다.

보여줄 것: 완성된 랜딩페이지, 카카오톡 공유 카드, npm run verify 결과, Vercel 배포 주소.

강조할 것: 프롬프트는 명령문이 아니라 작업 계약서다. 좋은 에이전트 작업은 "만들어줘"보다 "읽고, 계획하고, 작게 고치고, 검증해줘"가 강하다.

준비물 점검

node -v
npm -v
vercel --version
vercel whoami

검증 자동화 프롬프트

이 랜딩페이지 요구사항을 검증하는 스크립트를 만들어줘.

검증해야 할 것:
- 필수 문구가 모두 있는지
- CTA 링크가 있는지
- footer 정보가 있는지
- og:image가 QR 이미지가 아닌 대표 이미지인지
- 금지 문구가 없는지
- 배포용 공유 경로가 있는지

요구:
- package.json의 npm run verify로 실행되게 해라.
- 가능하면 먼저 실패하는 검증 조건을 만들고, 수정해서 통과시켜라.

6. 실습 운영 방식

  1. 강사가 전체 흐름을 1회 데모한다.
  2. 수강생은 자기 브리프로 같은 흐름을 반복한다.
  3. 막힌 사람은 "현재 상태를 읽고 문제를 진단해줘" 프롬프트부터 사용하게 한다.
  4. 마지막 10분은 서로 배포 URL을 공유한다.
강사 팁: 카카오톡 미리보기 문제는 좋은 교육 소재다. "페이지 안에 있는 이미지"와 "공유 대표 이미지"가 다르다는 것을 설명한다.

8. 강사 체크리스트

강의 전

  • Vercel 로그인 확인
  • 데모용 브리프 준비
  • 대표 이미지 1장 준비
  • QR 또는 신청 링크 준비
  • 네트워크 안 될 때 사용할 로컬 완성 예시 준비

강의 중

  • Codex가 읽기 전에 만들지 않게 한다.
  • 작업 범위를 매번 좁힌다.
  • 검증 없이 완료라고 말하지 않게 한다.
  • 배포 후 실제 URL을 열어본다.

강의 후

  • 수강생에게 프롬프트 팩 배포
  • 배포 URL 제출 받기
  • 다음 단계로 Skill화 과제 제안
