# 수강생 프롬프트 팩

# Codex로 개인/이벤트 랜딩페이지 자동 제작하기

이 문서는 수업 중 Codex에 바로 붙여 넣어 사용할 수 있는 프롬프트 모음입니다. 순서대로 사용하면 기획, 제작, 검증, 배포까지 한 흐름으로 진행할 수 있습니다.

## 0. 시작 전 준비

확인할 것:

```bash
node -v
npm -v
vercel --version
vercel whoami
```

폴더 이름 예시:

```text
my-event-landing
my-profile-landing
church-seminar-landing
```

## 1. 랜딩페이지 브리프 템플릿

먼저 아래를 채우세요.

```markdown
# 랜딩페이지 제작 브리프

종류: 개인 / 이벤트 / 강의 / 후원 / 신청 / 제품
페이지 제목:
부제:
대상:
핵심 메시지:
일시/장소:
주요 CTA:
연결할 링크:
연락처:
대표 이미지 방향:
꼭 들어갈 문구:
절대 들어가면 안 되는 문구:
배포 희망 경로:
```

작성 예시:

```markdown
# 랜딩페이지 제작 브리프

종류: 이벤트
페이지 제목: AI Collaboration Summer Class
부제: 일상과 콘텐츠, 협업의 흐름을 바꾸는 5주 특강
대상: AI를 실무와 사역에 적용하고 싶은 입문자
핵심 메시지: AI를 혼자 쓰는 도구가 아니라 함께 일하는 파트너로 경험한다.
일시/장소: 2026년 7월 14일 - 8월 18일, 매주 화요일 저녁 8시, Zoom
주요 CTA: 신청하기
연결할 링크: 구글폼 신청 링크
연락처: 이메일 또는 전화번호
대표 이미지 방향: 밝고 시원한 여름 강의 분위기
꼭 들어갈 문구: 무료 Zoom 강의, 자율 후원
절대 들어가면 안 되는 문구: 유료 필수 결제
배포 희망 경로: /event/
```

## 2. 프롬프트 카드

### 카드 1. 현재 폴더 읽기

```text
현재 폴더 구조를 먼저 읽고, 이 프로젝트가 어떤 방식으로 구성되어 있는지 설명해줘.

확인할 것:
- 파일 구조
- package.json 여부
- 실행/검증 가능한 명령
- 이미 있는 HTML/CSS/JS 파일
- 배포 설정 파일

아직 파일을 수정하지 말고, 작업에 필요한 맥락만 정리해줘.
```

### 카드 2. 브리프 기반 설계

```text
아래 브리프를 바탕으로 개인/이벤트 랜딩페이지를 설계해줘.

아직 구현하지 말고 먼저 설계만 해줘.

출력 형식:
1. 페이지 목적
2. 대상 사용자
3. 첫 화면 메시지
4. 섹션 구성
5. CTA 구조
6. 필요한 이미지/QR/링크
7. 검증 기준
8. 배포 방식

브리프:
[여기에 브리프 붙여넣기]
```

### 카드 3. MVP 구현

```text
위 설계를 기준으로 랜딩페이지 MVP를 만들어줘.

조건:
- 현재 프로젝트 구조를 따라가라.
- 정적 HTML/CSS/JS로 충분하면 프레임워크를 추가하지 마라.
- 첫 화면에 제목, 부제, 핵심 CTA가 보여야 한다.
- 모바일에서도 읽기 좋아야 한다.
- 디자인은 과하게 화려하지 않게, 정보가 잘 보이게 구성해라.
- 파일 변경 전 어떤 파일을 만들거나 수정할지 먼저 말해라.
- 완료 후 확인 방법을 알려줘.
```

### 카드 4. 콘텐츠 다듬기

```text
랜딩페이지 문구를 더 선명하게 다듬어줘.

기준:
- 첫 화면에서 무엇을 제공하는지 5초 안에 이해되어야 한다.
- CTA는 하나가 가장 중요하게 보여야 한다.
- 설명 문장은 짧고 구체적으로 만든다.
- 과장된 표현은 줄인다.
- 대상 사용자가 자기 이야기로 느끼게 한다.

수정 후 어떤 문구를 왜 바꿨는지 요약해줘.
```

### 카드 5. CTA와 신청 링크 추가

```text
랜딩페이지에 실제 신청/문의 CTA를 추가해줘.

추가할 것:
- 첫 화면 CTA 버튼
- 중간 또는 하단 CTA 반복
- 신청 링크 또는 문의 링크
- CTA 버튼의 hover/focus 상태
- 모바일에서 터치하기 좋은 크기

주의:
- 링크가 비어 있으면 임시 링크라고 명확히 표시해라.
- href="#"는 사용하지 마라.
- 완료 후 CTA 링크가 어디에 연결되는지 알려줘.
```

### 카드 6. QR과 안내 정보 추가

```text
랜딩페이지에 QR 또는 안내 정보를 추가해줘.

추가할 수 있는 항목:
- 신청 QR
- 입장 QR
- 후원 QR
- 계좌 정보
- 연락처
- 이메일

주의:
- QR 이미지는 본문 안내용으로만 사용한다.
- QR 이미지가 카카오톡 대표 이미지 og:image로 잡히지 않게 한다.
- 예금주, 계좌번호, 링크 등은 사용자가 확인할 수 있게 표시한다.
```

### 카드 7. 카카오톡 공유 이미지 설정

```text
카카오톡 공유 시 원하는 대표 이미지가 나오도록 OG 메타를 설정해줘.

필요한 것:
- og:title
- og:description
- og:type
- og:url
- og:image
- og:image:width
- og:image:height
- og:image:alt
- twitter:card
- twitter:image

주의:
- og:image는 QR 이미지가 아니라 별도 대표 이미지여야 한다.
- 배포 주소 기준 절대 URL을 사용한다.
- 같은 URL이 카카오톡에서 캐시될 수 있으니 캐시 우회용 공유 경로 또는 쿼리스트링도 제안해라.
```

### 카드 8. footer와 개인정보 문구 추가

```text
랜딩페이지 하단 footer를 정리해줘.

포함할 수 있는 정보:
- 이름 또는 단체명
- 이메일
- 연락처
- 대표자
- 개인정보 문의 문구
- 상단/일정/신청 영역으로 이동하는 내비게이션

주의:
- 사용자가 요청하지 않은 식별번호나 민감한 정보는 넣지 마라.
- 전화번호 링크나 외부 링크는 사용자 확인 후 넣어라.
```

### 카드 9. 검증 스크립트 만들기

```text
이 랜딩페이지의 요구사항을 검증하는 스크립트를 만들어줘.

검증해야 할 것:
- 필수 문구가 모두 있는지
- CTA 링크가 있는지
- footer 정보가 있는지
- og:image가 QR 이미지가 아닌 대표 이미지인지
- 금지 문구가 없는지
- 배포용 공유 경로가 있는지
- 필요한 이미지 파일이 존재하는지

요구:
- package.json의 npm run verify로 실행되게 해라.
- 먼저 실패해야 할 검증 조건을 만든 뒤, 수정해서 통과시켜라.
- 검증 결과가 실패하면 무엇이 빠졌는지 알려줘.
```

### 카드 10. 로컬 미리보기와 QA

```text
랜딩페이지를 로컬에서 확인하고 QA해줘.

확인할 것:
- 첫 화면에서 제목과 CTA가 잘 보이는지
- 모바일 화면에서 텍스트가 깨지지 않는지
- 버튼 링크가 올바른지
- QR 이미지가 로드되는지
- console error가 없는지
- og:image 메타가 원하는 이미지인지

가능하면 브라우저 미리보기로 확인하고, 확인한 결과와 남은 위험을 알려줘.
```

### 카드 11. Vercel 배포

```text
검증이 통과하면 Vercel에 프로덕션 배포해줘.

순서:
1. npm run verify 실행
2. vercel --prod --yes 실행
3. 배포 URL 확인
4. curl로 배포된 HTML의 og:image 확인
5. 대표 이미지 파일이 200 OK로 제공되는지 확인
6. 최종 공유 URL을 알려줘

주의:
- 검증 실패가 있으면 배포하지 마라.
- 카카오톡 캐시 문제가 생길 수 있으므로 새 공유 경로 또는 버전 쿼리를 제안해라.
```

### 카드 12. 수정 요청 처리

```text
사용자 피드백을 반영해줘.

피드백:
[여기에 수정 요청 붙여넣기]

작업 방식:
1. 피드백이 어느 파일/영역에 해당하는지 먼저 설명해라.
2. 수정 범위를 최소화해라.
3. 검증 스크립트가 필요하면 먼저 업데이트해라.
4. 수정 후 npm run verify를 다시 실행해라.
5. 배포가 필요한 변경이면 Vercel 재배포까지 진행해라.
```

## 3. 전체 자동화 마스터 프롬프트

아래 프롬프트는 강의 마지막에 사용하는 통합 프롬프트입니다.

```text
다음 브리프를 바탕으로 개인/이벤트 랜딩페이지를 끝까지 제작해줘.

자동으로 수행할 것:
1. 현재 폴더 구조 읽기
2. 요구사항 분석
3. 페이지 구조 설계
4. MVP 구현
5. CTA/QR/OG/footer 추가
6. 검증 스크립트 작성
7. npm run verify 통과
8. Vercel 배포
9. 배포 URL과 카카오톡 공유용 URL 보고

작업 원칙:
- 구현 전에 계획을 말해라.
- 현재 프로젝트 구조를 따라가라.
- 정적 HTML/CSS/JS로 충분하면 프레임워크를 추가하지 마라.
- 필수 문구와 금지 문구를 검증 스크립트에 반영해라.
- QR 이미지는 본문용으로만 쓰고, og:image는 별도 대표 이미지로 설정해라.
- 검증 없이 완료라고 말하지 마라.
- 배포 전 npm run verify를 실행해라.
- 배포 후 HTML의 og:image와 이미지 응답을 확인해라.

브리프:
[여기에 브리프 붙여넣기]
```

## 4. Skill화 프롬프트

반복해서 쓸 거라면 이 작업을 Codex Skill로 만들 수 있습니다.

```text
방금 만든 랜딩페이지 제작 워크플로우를 재사용 가능한 Codex Skill로 설계해줘.

Skill 이름:
landing-page-factory

Skill이 해야 할 일:
- 랜딩페이지 브리프를 입력받는다.
- 현재 폴더 구조를 읽는다.
- 페이지 구조를 설계한다.
- 정적 HTML/CSS/JS MVP를 만든다.
- CTA, QR, footer, OG 이미지를 구성한다.
- 검증 스크립트를 만든다.
- Vercel 배포 전후 체크리스트를 제공한다.

출력:
1. SKILL.md 초안
2. 브리프 템플릿
3. 검증 체크리스트
4. 배포 체크리스트
5. 사용 예시 프롬프트

주의:
- 아직 파일을 만들지 말고 먼저 설계안을 보여줘.
```

## 5. 문제 해결 프롬프트

### 카카오톡에서 예전 이미지가 계속 나올 때

```text
카카오톡 링크 미리보기에서 예전 이미지가 계속 나옵니다.

확인해줘:
- 배포된 HTML의 og:image가 새 이미지인지
- 루트 주소와 실제 공유 주소가 같은 OG 메타를 갖는지
- 대표 이미지 파일이 200 OK로 제공되는지
- 카카오 캐시 우회를 위해 새 공유 경로나 버전 쿼리가 필요한지

필요하면 새 공유 경로를 만들고 Vercel에 재배포해줘.
```

### Codex가 너무 많은 파일을 만들려고 할 때

```text
작업 범위를 줄여줘.

이번 수정은 아래 파일만 대상으로 해줘:
[파일 경로]

요구:
- 관련 없는 파일은 수정하지 마라.
- 변경 전후를 짧게 설명해라.
- 검증 명령을 다시 실행해라.
```

### 배포가 실패할 때

```text
Vercel 배포가 실패했습니다.

로그를 읽고 원인을 분류해줘:
1. 로그인 문제
2. 프로젝트 설정 문제
3. 빌드 명령 문제
4. 파일 경로 문제
5. 네트워크 또는 권한 문제

수정 가능한 항목은 최소 수정으로 고치고, 다시 배포 전에 npm run verify를 실행해줘.
```

## 6. 제출 체크리스트

수강생 최종 제출:

- 배포 URL
- 카카오톡 공유용 URL
- 브리프 원문
- 사용한 대표 이미지
- `npm run verify` 통과 여부
- 오늘 배운 프롬프트 중 가장 유용했던 것 하나
