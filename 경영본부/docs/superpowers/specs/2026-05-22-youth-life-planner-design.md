# youth-life-planner 스킬 설계 문서

**작성일:** 2026-05-22  
**기반 스킬:** pastor-life-planner (A안 — 완전 답습 구조)  
**상태:** 설계 완료, 구현 대기

---

## 개요

중·고등학생(13~18세) 대상 통합 인생 계획 스킬.  
청소년 본인과 청소년부 사역자 모두 사용 가능한 이중 사용자 구조.  
범용 배포 기반이며 교회별 커스터마이징 가능.

---

## SKILL.md 핵심 구조

### 스킬 메타데이터

```yaml
name: youth-life-planner
description: |
  중·고등학생(13~18세) 전용 통합 인생 계획 스킬.
  청소년 본인이 직접 사용하거나, 사역자가 코칭 도구로 사용할 수 있다.
  수련회와 평상시 모두 사용 가능.

  사용할 때:
  - 청소년이 진로·소명·신앙·관계를 통합 설계할 때
  - 사역자가 청소년 1:1 코칭 계획서를 만들 때
  - 수련회에서 청소년 자기 발견 프로그램을 진행할 때
  - 중·고 전환기, 대입 전후, 신앙 위기 등 삶의 전환점에서

  사용하지 않을 때:
  - 설교·말씀 준비 → 별도 설교 스킬
  - 성인 목회자 인생 계획 → pastor-life-planner

트리거 키워드:
  청소년 인생계획, 청소년부 코칭, 수련회 계획, 청소년 진로,
  청소년 신앙 설계, 청소년 관계 정리, 중학생 계획, 고등학생 계획,
  청소년 회고, 나는 잘 자라고 있는가, 청소년 번아웃
```

## AI 페르소나

```
"나는 청소년의 편에서 생각하는 인생 설계 동반자다."

- 중학생에게는 친근한 형·누나처럼, 고등학생에게는 신뢰할 수 있는
  선배·멘토처럼 말한다
- 정답을 주지 않는다. 스스로 발견하도록 질문한다
- "잘했어"는 근거가 있을 때만. 막연한 칭찬은 하지 않는다
- 사역자 모드에서는 pastor-life-planner 톤 유지 (코칭 전문가)
- 신학적으로 틀린 방향은 정중히 교정한다
```

## 안전 장치

### 전역 위기 감지 하드스톱 (어느 모드에서나 즉시 발동)

| 감지 키워드 | 처리 |
|------------|------|
| 자해·자살·죽고 싶다·사라지고 싶다 | ⚠ 자살예방상담전화 **1393** 안내. 스킬 중단. 사역자 플랜에 위기 플래그 |
| 학교폭력·따돌림·맞는다·괴롭힘 | ⚠ **117** (학교폭력신고) 안내 + 신뢰 어른에게 알리도록 권고 |
| 가정폭력·부모한테 맞는다·방임 | ⚠ 아동보호전문기관 **1391** 안내. 스킬 일시 중단 |
| 이단 접근·신천지·JMS·하나님의교회 등 | ⚠ 접근 차단 + 사역자 플랜에 경고 표시 |
| 번아웃·지쳐있다·아무것도 하기 싫다 | ⚠ `/나의삶`으로 유도, 계획 전 회복 먼저 |

### 미성년자 보호 원칙

- 이름·학교명·개인정보 수집 최소화 (닉네임 사용 권장)
- 민감 정보(가정폭력·정신건강)는 사역자 플랜에만 기록, 청소년 결과 카드 미포함
- 사역자 코칭 플랜 상단 고정 문구:
  > "이 문서는 코칭 목적으로만 사용하며, 당사자 동의 없이 제3자 공유를 금합니다."

### 신학 안전 원칙

- 이단·사이비 관련 방향 제시 금지
- "믿음으로 기도하면 원하는 대학 간다" 류 번영신학 금지
- 개인 주관적 계시를 진로 결정의 유일 근거로 제시하는 구조 금지

## 7개 영역 상세 설계

### `/인터뷰` — 전체 시작점

**학년대 분기:**
- 중학생(1~3학년) → 질문 언어 쉽게, 부모·가정 비중 높임
- 고등학생(1~3학년) → 진로·대입 비중 높임, 자기결정권 존중

**공통 수집 항목 (5분 이내):**
1. 학년 + 학교 유형 (공립/기독교학교 등)
2. 가족 구성 (부모 신앙 여부 포함)
3. 올해 가장 크게 결정해야 하는 것 하나
4. 지금 가장 힘든 것 하나
5. 교회 청소년부 참여 상태

---

### `/진로소명` — 진로·소명 탐색

pastor의 `/목회방향` 대응. 3가지 축으로 탐색:
- 관심: 무엇을 할 때 시간이 가는 줄 모르는가
- 재능: 남들보다 자연스럽게 잘 되는 것은 무엇인가
- 하나님 나라: 이 재능으로 세상에 기여할 수 있는 방식은

**학년대 분기:**
- 중학생: "무엇이 좋은가" 탐색 중심
- 고등학생: 대학·전공·직업 방향 시나리오 비교

---

### `/가족관계` — 부모·가족 관계

pastor의 `/가정계획` 대응.

**설계 질문:**
- 부모와의 갈등·소통·신뢰 수준
- 부모 신앙 여부에 따른 접근 분기 (신앙 가정 / 비신앙 가정)
- 가정 경제 압박이 청소년에게 미치는 영향
- 형제 관계

---

### `/또래관계` — 친구·학교·교회 관계

pastor의 `/관계지도` 대응. 관계 에너지 분류:

| 분류 | 전략 |
|------|------|
| 투자 관계 | 의도적으로 늘린다 |
| 중립 관계 | 효율적으로 관리한다 |
| 소모 관계 | 경계를 세운다 |
| 방어 대상 | 거리 유지 + 위기 감지 연계 |

디지털 관계(SNS·온라인 커뮤니티) 포함.

---

### `/나의삶` — 신앙·정체성·자기돌봄

pastor의 `/나의삶` 대응.

- **말씀·기도:** 예배하는 자로서의 루틴 (집례자가 아닌)
- **정체성:** "나는 누구인가" (신앙 정체성 + 자아 정체성)
- **자기돌봄:** 수면·운동·취미·디지털 사용 시간

---

### `/캘린더` — 학사일정 + 신앙 루틴 통합

pastor의 `/캘린더` 대응.
- 시험기간·방학·수련회 일정 반영
- 구글 캘린더 포맷 출력 (pastor와 동일 포맷)

---

### `/반기회고` — "나는 잘 자라고 있는가" (RetrospectiveAgent)

pastor의 `/6개월회고` 대응. 12문 → 청소년 10문으로 재구성.
번아웃 지수 포함 (1=탈진, 5=보통, 10=충만).

**RetrospectiveAgent 인터뷰 10문:**

1묶음 — 성장 (1~3문)
1. 반년 전 세운 목표 중 실제로 이룬 것과 멈춘 것은?
2. 이 6개월 동안 가장 많은 에너지를 쓴 상황 3가지는?
3. 내 의지와 무관하게 외부에서 온 방해 요인은?

2묶음 — 관계 (4~6문)
4. 가족과 이 6개월 동안 실제로 함께한 시간은 충분했나?
5. 힘을 준 관계와 에너지를 빼앗은 관계를 각각 한 명씩 꼽는다면?
6. 학교·교회에서 나를 가장 어렵게 한 상황은?

3묶음 — 나 자신 (7~9문)
7. 이 6개월 동안 순전히 나를 위해 한 일이 있나?
8. 신앙 생활이 살아있었던 날과 그렇지 못한 날 중 어느 쪽이 더 많았나?
9. 지금 몸과 마음 상태는? (번아웃 지수 1~10)

4묶음 — 재설계 (10문)
10. 남은 6개월, 딱 한 가지만 다르게 한다면 무엇을 바꾸겠나?

**출력:** 성찰 분석 블록 → YouthCardAgent·PastorPlanAgent (회고 버전)

## 수련회 모드 (`/수련회`)

**특성:** 시간 제한 45~60분, 감정 고조, 집단 환경

```
STEP 1  나를 아는 5문 인터뷰            (10분)
STEP 2  올해의 한 가지 결정             (10분)
STEP 3  관계 에너지 지도 (간략)         (10분)
STEP 4  신앙 상태 체크 + 한 문장 서약    (10분)
STEP 5  이중 출력 생성                 (5분)
        + 수련회 후속 계획 제안          (5분)
```

**수련회 전용 주의사항:**
- 집단 환경이므로 민감 정보 입력 최소화 권고
- 위기 감지 시 "사역자에게 개별 상담 요청" 유도

### 결과물 저장 경로 및 파일 포맷

**저장 경로:**
```
output/youth-life-planner/{YYYY-MM-DD}_{닉네임}/
├── youth-card.md          ← 청소년 결과 카드
├── youth-card.txt
├── youth-card.pdf
├── pastor-plan.md         ← 사역자 코칭 플랜
├── pastor-plan.txt
├── pastor-plan.pdf
├── retrospective.md       ← 반기회고 (해당 시)
├── retrospective.txt
└── retrospective.pdf
```

**수련회 모드 저장 경로:**
```
output/youth-life-planner/retreat/{YYYY-MM-DD}_{교회명}/
├── youth-card-{닉네임}.md|txt|pdf   ← 참가자별 개별 생성
└── pastor-plan-{닉네임}.md|txt|pdf
```

**파일 발행 원칙:**
- md: 기본 저장 포맷, 편집 가능
- txt: 공유·인쇄 단순 버전
- pdf: 보관·배포용 (pandoc 또는 브라우저 출력 활용)
- 파일명에 개인정보(실명·학교명) 미포함, 닉네임만 사용

### 세션 간 컨텍스트 전달

각 영역 완료 시 결과를 누적 요약 블록으로 유지한다.
`/전체출력` 또는 마지막 영역 완료 시 누적 블록을 통합해 이중 문서를 생성한다.
세션이 끊길 경우: "이전 영역 결과를 요약해서 붙여넣으시면 이어서 진행합니다"를 안내한다.

## 멀티 에이전트 아키텍처

### 실행 흐름

```
[인터뷰]
    │
    ▼ 병렬 실행
    ├── CallingSoningAgent   ← /진로소명 전문 에이전트
    ├── FamilyAgent          ← /가족관계 전문 에이전트
    ├── PeersAgent           ← /또래관계 전문 에이전트
    └── FaithLifeAgent       ← /나의삶 전문 에이전트
    │
    ▼ 직렬 실행
    AnalysisAgent            ← 4개 도메인 결과 통합 분석
    │
    ▼ 직렬 실행
    CoachingAgent            ← 분석 결과 기반 코칭 플랜 생성
    │
    ▼ 병렬 실행
    ├── YouthCardAgent       ← 청소년 결과 카드 생성
    └── PastorPlanAgent      ← 사역자 코칭 플랜 생성
```

수련회 모드는 도메인 에이전트가 간략 버전으로 동일 구조 실행.

### 에이전트 역할 정의

| 에이전트 | 타입 | 입력 | 출력 |
|---------|------|------|------|
| CallingSoningAgent | 도메인 | 인터뷰 + `/진로소명` 답변 | 진로·소명 분석 블록 |
| FamilyAgent | 도메인 | 인터뷰 + `/가족관계` 답변 | 가족관계 분석 블록 |
| PeersAgent | 도메인 | 인터뷰 + `/또래관계` 답변 | 또래관계 분석 블록 |
| FaithLifeAgent | 도메인 | 인터뷰 + `/나의삶` 답변 | 신앙·정체성 분석 블록 |
| AnalysisAgent | 통합 | 4개 도메인 블록 전체 | 통합 분석 (강점·위험·우선순위) |
| CoachingAgent | 코칭 | AnalysisAgent 결과 | 코칭 포인트 + 후속 제안 |
| RetrospectiveAgent | 회고 | 반기 인터뷰 10문 답변 | 성찰 분석 + 재설계안 |
| YouthCardAgent | 출력 | CoachingAgent 결과 | 청소년 결과 카드 |
| PastorPlanAgent | 출력 | 입력 원문 + AnalysisAgent + CoachingAgent | 사역자 코칭 플랜 |

### 에이전트 의존 관계 원칙

- AnalysisAgent는 4개 도메인 블록이 모두 완료된 후에만 실행
- CoachingAgent는 AnalysisAgent 결과 없이 단독 실행 불가
- YouthCardAgent·PastorPlanAgent는 CoachingAgent 결과 필수 입력
- RetrospectiveAgent는 독립 실행 — 평상시 계획 흐름과 별도
- 도메인 에이전트는 상호 독립 — 병렬 실행 가능

## TDD 적용 방식

스킬 파일은 실행 가능한 코드가 아닌 마크다운 프롬프트다.
TDD를 아래와 같이 적용한다.

### RED → GREEN → REFACTOR

```
RED      각 에이전트의 수용 기준(Acceptance Criteria)을 먼저 작성
          "이 입력을 받으면 이 출력이 나와야 한다"를 명세로 정의

GREEN    명세를 만족하는 에이전트 프롬프트 작성
          실제 대화 시나리오로 검증 (입력 → 출력 확인)

REFACTOR 출력이 일관되면 프롬프트 정제
```

### 에이전트별 수용 기준 예시

**FaithLifeAgent:**
```
입력: "큐티를 한 번도 못 했어요. 기도도 안 되고요."
기대 출력:
  ✅ 번아웃 감지 → /나의삶 우선 유도
  ✅ 정죄 언어 없음 ("못했다"를 탓하지 않음)
  ✅ 구체적 루틴 제안 (주 N회, N분)
  ❌ "더 열심히 하세요" 류 출력 금지
```

**AnalysisAgent:**
```
입력: 4개 도메인 블록 (위험신호 포함)
기대 출력:
  ✅ 위험신호 ⚠ 플래그 포함
  ✅ 코칭 우선순위 영역 1~3위 명시
  ✅ 강점 2개 이상 포함
  ❌ 도메인 블록 없이 단독 실행 불가
```

**PastorPlanAgent:**
```
입력: 청소년 원문 입력 + AnalysisAgent 결과 + CoachingAgent 결과
기대 출력:
  ✅ 원문 전체 보존
  ✅ 위기 신호 요약 섹션 포함
  ✅ 개인정보 보호 문구 상단 고정
  ❌ 청소년 결과 카드와 내용 중복 최소화
```

## 구현 순서 (TDD 기반)

각 단계는 수용 기준(RED) 작성 → 구현(GREEN) → 정제(REFACTOR) 순서로 진행한다.

### Phase 1 — 기반 구조
1. 각 에이전트 수용 기준 문서 작성 (RED 먼저)
2. `SKILL.md` — 진입 분기 + 7영역 라우팅 + 안전 장치
3. `references/interview_mode.md` — 학년대 분기 인터뷰

### Phase 2 — 도메인 에이전트 (병렬 개발 가능)
4. `references/calling_direction_mode.md` + CallingSoningAgent 수용 기준 검증
5. `references/family_mode.md` + FamilyAgent 수용 기준 검증
6. `references/peers_mode.md` + PeersAgent 수용 기준 검증
7. `references/faith_life_mode.md` + FaithLifeAgent 수용 기준 검증

### Phase 3 — 통합·코칭 에이전트 (직렬, Phase 2 완료 후)
8. AnalysisAgent — 4개 도메인 결과 통합 검증
9. CoachingAgent — 분석 결과 기반 코칭 플랜 검증

### Phase 4 — 출력 + 수련회
10. `references/output_templates.md` — 이중 출력 포맷 검증
11. `references/retreat_mode.md` — 수련회 모드 전체 흐름 검증

### Phase 5 — 나머지 영역
12. `references/calendar_mode.md`
13. `references/retrospective_mode.md`
