## 1. 배경과 목표

## 4. 매트릭스 작동 원리

1. **사업부장 = 결과 책임자**: CEO가 목표 위임 → 사업부장이 마감·품질·산출물 소유.
2. **공유기능본부 = 전문가 센터**: 각 본부가 그 능력의 표준·SOP·템플릿·스킬·품질바를 소유·관리.
3. **실행 흐름 (Virtual Matrix — 적대검증 H1 반영)**: 기존 커맨드(`/주간총괄` 등)는 **사업부장 노드가 단독 실행**해 100% 보존한다. 매트릭스는 무거운 inter-pane 소켓 위임이 아니라 **SOP 결합**으로 구현 — 사업부장이 sub-agent를 스폰할 때 대상 본부의 헌장·SOP를 시스템 프롬프트에 결합한다(가상 매트릭스). 진짜 무겁거나 크로스-사업부 능력작업만 본부 노드에 정식 의뢰.
4. **충돌 조율**: 두 사업부가 같은 본부 자원 경합 → CEO(Master) 중앙 중재(사람 매트릭스의 "두 상사 정치" = AI 조직엔 0 비용).
5. **이원화 검증 게이트 (적대검증 H3 반영)**: ① **리서치·검증본부 = Fact Validation** — 원천 SOT 자료의 사실 유무·출처·환각 검증. ② **품질감사실 = Value & Logic Validation** — 전략적 타당성·신학 해석·정서적 문체. 두 게이트 완전 격리 → CEO → 회장 보고.

### 흐름 예시: 강의
```
강의 발주·소유 → 주제 사업부 (청소년→비전교육 / 신학→목회 / 범용→기획본부)
   기획        → 기획·전략본부 (커리큘럼·시간척추 방법론)
   제작        → 제작본부 셀3 교육콘텐츠 (교안·슬라이드·핸드아웃) + 셀1/셀2 협업
   검증        → 품질감사실 → CEO → 회장
```
강의는 **산출물 유형**이지 부서가 아니다. (Phase 2 외부 판매 시 "교육사업부" 승격 검토)

### 흐름 예시: 정보 → 제품
```
리서치본부(F): 환경스캐닝·뉴스크롤링·딥리서치·검증 (input 수집·검증)
        ↓
인텔리전스 사업부(②): 투자신호·통찰보고서 (output 제품 생산)
```

## 5. 상주·대기모드 (자원 규율)

과거 마비 원인은 *idle pane이 아니라 미종료 백그라운드 서버*였음(load 수십배·32GB heap·401). 현재 8노드 load 18~23%로 건강 공존. 따라서 13노드 상주는 다음 규율 하에 안전:

### 이벤트 구동형 수명주기 (적대검증 H2·M1 반영 — L1 상시대기 의존 제거)
**Charter-level 상주**(전 부서 헌장 상시 존재) ≠ **pane-level 상주**(물리 프로세스). 후자는 이벤트 구동으로 자원 점유를 최소화한다. **CSO = 중앙 메시지 큐·라우터.**
- **L0 활성(Active)**: 작업 수행 중. 병렬은 sub-agent fan-out(pane 추가 금지).
- **L1 대기(Idle, 단기)**: 작업 직후 짧은 유휴. 후속 작업 즉응용 잠깐 유지, 토큰 0.
- **L2 동면(Hibernate, 기본 휴지)**: 유휴 임계 초과 시 CSO가 핸드오프 저장 → **pane 종료(메모리 회수)**. 신규 작업 라우팅 시 CSO가 L2→L0 재기동. → *희소 부서는 평소 L2, 활성 부서만 L1 단기 유지(13 pane 동시 강제 기동 금지).*

### 규율(불가침)
- 각 부서 = 단일 에이전트 pane, **백그라운드 서버 0**(작업 시만 띄우고 즉시 kill).
- 실무 sub-worker는 작업 시 소환 → 완료 시 종료.
- CSO watchdog: 13노드 메모리·load·컨텍스트 60% 상시 감시 → 임계 시 관리형 /clear, 장기 idle → L2 동면.
- 전 부서 idle이면 감시 루프도 중단([[feedback_monitoring_only_when_working]]).
- 진짜 한계 = 메모리·동시 토큰예산 → 임계 시 CSO가 회장께 에스컬레이션.

## 6. 부서 헌장 표준 (각 부서 카드 구성요소)

각 부서는 다음을 담은 헌장 파일(`.claude/org/<부서>.md`)을 보유:
- **미션** — 한 줄 존재 이유
- **책임 범위(Owns)** — 무엇의 결과를 책임지는가
- **SOP** — 표준 작업 절차(단계·게이트)
- **산출물 경로** — `output/...` 또는 사업부별 폴더 규칙
- **전속 스킬** — 발동할 핵심 스킬 목록
- **엔진** — Claude/Codex/agy
- **영구기억** — 부서 memory 파일(누적 학습·SOP 개선)
- **협업 라우팅** — 어느 본부/사업부와 주로 협업

## 7. 상주 인프라

- **부서별 영구기억**: `.claude/org/memory/<부서>.md` — 부서 단위 학습·SOP 누적(재귀적 자기개선 5단계 저장처).
- **노드 레지스트리**: `SESSION_STATE.md` 노드 표 확장 — 13노드 ws/surface·역할·상태(L0/L1/L2). 회전ID 동적 해소 규칙 유지.
- **라우팅 규칙**: 사업부↔본부↔CEO 양방향 소켓(--workspace + --surface 둘 다). 크로스팀 자료는 CEO 능동 라우팅.
- **통합 대시보드**: ⏸️ **Phase 후반 과제** — 전체 시스템 구축 후 별도 설계(조직 상태·각 부서 작업·자원·산출물 한눈에).

## 8. Phase 계획

- **Phase 1 (내부 구축)**: 13부서 헌장 작성 → 노드 레지스트리 확장 → 상주 인프라(메모리·라우팅) → 대기모드 수명주기 → 기존 커맨드 부서 귀속 → 파일럿(목회사역 사업부 1주간 운영).
- **Phase 1.5 (대시보드)**: 전체 구축 검증 후 통합 대시보드 설계·구현.
- **Phase 2 (외부 확장)**: 검증된 사업부(비전교육 1순위)를 외부 상품화 — 영업·CS·과금 신설.
