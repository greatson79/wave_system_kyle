# 프롬프트 패턴 (Prompt Patterns)

Suno Style Prompt 작성 공식과 용도별 패턴.

---

## 목차

1. 기본 프롬프트 공식
2. 용도별 패턴
3. 한국어 가사 작성 팁
4. 스타일 프롬프트 최적화 규칙
5. 자주 하는 실수와 해결법

---

## 1. 기본 프롬프트 공식

### 6요소 공식 (권장)

```
[장르 + 서브장르], [무드/감정], [핵심 악기], [보컬 스타일], [프로덕션 품질], [추가 특성]
```

| 요소 | 역할 | 예시 |
|------|------|------|
| 장르 + 서브장르 | 사운드의 기본 틀 | indie folk, synth-pop, K-pop ballad |
| 무드/감정 | 곡의 감정적 방향 | melancholic, uplifting, dark, dreamy |
| 핵심 악기 | 사운드를 정의하는 주 악기 | acoustic guitar, piano, heavy 808s |
| 보컬 스타일 | 보컬의 성격 | warm female vocals, raspy male vocals |
| 프로덕션 품질 | 사운드의 질감 | lo-fi warmth, polished production, raw |
| 추가 특성 | 차별화 요소 | nostalgic, cinematic, minimal, anthemic |

### 최소 프롬프트 (3요소)

```
[장르], [무드], [보컬 또는 instrumental]
```

간단한 테스트나 빠른 생성 시 사용. 나머지는 Suno가 자동 결정.

### 확장 프롬프트 (8요소)

```
[장르 + 서브장르 + 시대], [무드], [에너지 레벨], [핵심 악기 2~3개], [보컬 스타일], [보컬 성별], [프로덕션 품질], [추가 특성]
```

정밀한 사운드 제어가 필요할 때 사용. 8개 초과 시 태그 충돌 위험.

## 2. 용도별 패턴

### 풀곡 (Full Song)

```
[장르], [무드], [핵심 악기], [보컬 스타일], [프로덕션]
```

예시:
```
indie pop, bittersweet, jangly guitars, soft female vocals, dreamy reverb, nostalgic
```

### Instrumental BGM

```
[장르], instrumental, [무드], [핵심 악기], [프로덕션], [용도 키워드]
```

반드시 `instrumental` 태그를 포함하고, Custom Lyrics는 구조 태그만 배치.

예시:
```
lo-fi beats, instrumental, chill, jazzy piano, vinyl warmth, study music
```

### 징글/쇼트 (30초~1분)

```
[장르], catchy, [무드], [핵심 악기], short, memorable hook, jingle
```

### 커버/리믹스

원곡의 특징을 분석해 새로운 장르 스타일로 변환.

```
[변환할 장르], [원곡 특징 유지 요소], [새로운 무드], [보컬 변환]
```

### 배경음악 (콘텐츠용)

```
[장르], instrumental, background, [무드], [에너지: 안정적], [핵심 악기], [용도]
```

유튜브·팟캐스트·강의 배경음악에 적합.

## 3. 한국어 가사 작성 팁

> **상세 발음 가이드**: `references/korean-pronunciation.md` 참조 (받침별 위험도, 음절 매핑, 호흡 구두점, 한영 혼용 전략)

### 음절과 리듬

| 규칙 | 설명 |
|------|------|
| 줄당 7~12음절 | 너무 길면 보컬이 뭉개짐, 너무 짧으면 멜로디가 비어 보임 |
| 코러스는 짧게 | 훅 라인 1~2줄, 5~8음절이 기억에 남음 |
| 음절 균일 | 같은 섹션 내 줄별 음절 수를 비슷하게 맞추면 리듬 안정 |

### 어휘 선택

| 권장 | 지양 |
|------|------|
| 일상 대화체 | 문어체, 한자어 중심 |
| 구체적 상황·행동 | 추상적 감정 나열 |
| 감각적 표현 (소리, 빛, 온도) | 관념적 표현 |
| 짧은 단어 | 4음절 이상 복합어 |

### 한영 혼용 전략

한국어 곡에서 영어 훅을 섞으면 Suno 보컬 품질이 향상되는 경우가 많다.

| 위치 | 효과 |
|------|------|
| 코러스 훅에 영어 1~2줄 | 보컬 명확도 향상, 글로벌 느낌 |
| 인트로/아웃트로 영어 | 분위기 전환 효과 |
| 전체 영어 | 보컬 품질 가장 안정적 |

예시:
```
[Chorus] [Energy: High]
너와 함께라면
I can feel the light
어둠 속에서도
We'll be alright
```

### 발음 최적화

Suno가 한국어 발음을 놓치는 경우 대응법:
- **Style Prompt에 `clear Korean pronunciation` 태그 추가** — 가장 먼저 시도
- 겹받침 음절 → 받침 없는 동의어로 교체 (삶→살아감, 넓은→큰)
- 받침이 복잡한 단어 → 더 단순한 동의어로 교체
- 연음이 일어나는 구간 → 띄어쓰기 조정
- 의성어·의태어 → Suno가 비교적 잘 처리 (반복 리듬에 유리)
- 줄당 13음절 이상 → 2줄로 분리
- 쉼표(`,`)로 호흡 삽입

## 4. 스타일 프롬프트 최적화 규칙

### DO (권장)

| 규칙 | 이유 |
|------|------|
| 카테고리당 1개 태그 | 충돌 방지 (장르 1개, 무드 1개, 악기 1~2개) |
| 서브장르 활용 | "rock"보다 "grunge, 90s" 가 더 정확한 결과 |
| 시대 키워드 추가 | 특정 사운드 시대를 명시하면 일관성 향상 |
| 결과물 기반 태그 | "radio-ready", "club-ready" 같은 목적 태그 |
| 한 번에 1개 변수 변경 | 변형 생성 시 안정적 비교 가능 |
| 악기 지시는 Style Prompt에 | Custom Lyrics가 아닌 Style Prompt에서 악기 지정 |

### DON'T (지양)

| 규칙 | 이유 |
|------|------|
| 상반 태그 조합 | calm + aggressive, minimal + maximalist → 결과 혼란 |
| 9개 이상 태그 | Suno가 우선순위를 정하지 못해 무작위 결과 |
| 아티스트명 직접 입력 | Suno 정책 위반, 무시될 수 있음 |
| 구조 태그를 Style에 | [Verse], [Chorus]는 가사 필드에만 |
| 지나치게 기술적 표현 | "120 BPM, Dorian mode" → "medium tempo, moody" 가 더 효과적 |
| Custom Lyrics에 소괄호 | `( )` 안 텍스트를 Suno가 가사로 부를 수 있음 |

## 5. 자주 하는 실수와 해결법

| 실수 | 문제 | 해결 |
|------|------|------|
| 스타일이 너무 모호 | "좋은 노래 만들어줘" → 기본 팝 출력 | 장르·무드·악기를 구체적으로 지정 |
| 태그 과다 | 12개 태그 → 결과가 뒤섞임 | 6개 이하로 줄이고 핵심에 집중 |
| 가사가 너무 김 | 한 섹션에 10줄 → 구조 무시 | 섹션당 2~6줄 유지 |
| 에너지 변화 없음 | 전체가 같은 에너지 → 밋밋함 | [Energy] 태그로 다이나믹 설계 |
| 메타태그 형식 오류 | `Verse:` (괄호 없음) → 가사로 불림 | 반드시 `[Verse]` 형식 사용 |
| 소괄호 사용 | `(piano solo)` → 보컬이 "piano solo"를 부름 | 대괄호 `[Piano Solo]`로 변환 또는 Style Prompt에 포함 |
| 한국어 발음 뭉개짐 | 복잡한 한자어·긴 문장 | 짧고 단순한 어휘, 음절 줄이기 |
| Instrumental인데 가사 입력 | AI가 가사를 부르려 함 | 가사 비우고 구조 태그만 |
| 크로스오버 실패 | jazz + metal → 혼란 | 에너지·템포가 유사한 장르끼리 조합 |
| 태그를 쉼표로 합침 | `[Chorus, Energy: High]` → 인식 불가 | `[Chorus] [Energy: High]` 나란히 배치 |
