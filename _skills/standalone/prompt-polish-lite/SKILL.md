# 프롬프트 다듬기 — 범용 진단·처방 워크플로우

## 이 스킬의 역할

기존 프롬프트가 원하는 출력을 내지 못할 때, 처음부터 다시 쓰는 대신 **어느 축이 약한지 진단하고 그 축만 보강**하는 도구다. 단발 요청·모드 인스트럭션·커스텀 GPT 지침서·Gem 시스템 프롬프트 등 형식과 무관하게 작동한다.

진단 기준은 **7축 체크리스트**, 처방 재료는 **처방 패턴집**이다.

---

## 작동 방식 — 5단계

### Phase 1. 입력 받기

다음 중 하나가 들어오면 즉시 진단을 시작한다.

- 프롬프트 전문 (인스트럭션·모드·단발 프롬프트)
- 프롬프트 + "이게 왜 이상하게 나오지?" 같은 불만 표현
- "이 프롬프트 다듬어줘", "이 모드 점검해줘" 같은 지목
- 아직 프롬프트 없이 목적만 제시된 경우 → **목적 → 초안 생성 → 진단** 순서로 진행

판단이 애매하면 한 번만 묻는다: "이 프롬프트의 목적과 아쉬웠던 출력 예시를 하나만 말씀해 주시면 진단 정확도가 올라갑니다."

### Phase 2. 7축 진단 (references/01_진단_7축_체크리스트.md)

각 축을 0~3점으로 평가한다. 0=부재, 1=약함, 2=보통, 3=탄탄. 총점 21점.

1. **V 벡터 축** — 역할·청중·톤이 AI가 정확한 지점을 찾을 수 있을 만큼 구체적인가
2. **L 손실함수 축** — 이상적 출력과 실패한 출력의 기준이 명시되어 있는가
3. **M 행렬 분해 축** — 맥락 변수로 개인화되는 설계인가
4. **C 분류 축** — 입력 유형을 자동 분기할 조건이 있는가
5. **F 합성함수 축** — 복잡한 작업이 단계로 분리되어 있는가
6. **B CNN/베이지안 축** — 핵심 디테일에 포커스가 있고 사전정보가 주입되어 있는가
7. **G 생성 축** — 출력 형식(섹션·분량·예시)이 완성형으로 지정되어 있는가

총점과 함께 **가장 약한 축 2~3개**를 자동 선정한다.

### Phase 3. 품질 원칙 점검 (references/02_품질_원칙.md)

7축 점수와 별도로 **최소 품질 기준** 3가지를 점검한다.

- 역할·청중·목적이 명확한가
- 개인정보·위험 지시를 유도하지 않는가
- AI가 감당할 장르 범위 안인가

하나라도 미충족이면 7축 점수와 무관하게 **"품질 기준 보강 필수"** 표식을 단다.

### Phase 4. 처방 적용 (references/04_처방_패턴집.md)

약한 축별 처방 스니펫을 골라 삽입한다. 처방 근거는 "V축 보강 — 벡터 3종 세트 적용" 형식으로 명시한다.

### Phase 5. Before / After 출력

반드시 아래 구조로 출력한다.

```
■ 진단 점수표 (V·L·M·C·F·B·G)
■ 가장 약한 축 2~3개와 근거
■ 품질 원칙 점검 결과
■ Before → After 대조
■ 수정 근거 (축 이름 명시)
■ 다음 사용 팁
```

## 자동 호출 규칙

다음 중 하나라도 충족되면 즉시 스킬 진입한다.

- 프롬프트·인스트럭션을 붙여넣으며 "봐줘", "점검", "평가", "개선", "리팩토링" 동사를 함께 쓴 경우
- "왜 이상하게 나와"라고 호소하며 프롬프트 원문을 보여준 경우
- 커스텀 GPT·Gem·Claude Project 지침서를 공유하며 평가를 요청한 경우
- "프롬프트 다듬기" 또는 `/다듬기` 입력

## 장르 판별 2분기 (스킬 진입 직후 먼저 실행)

### 분기 ① — 전문 도메인 장르
신호: 특정 직종·전문 분야·조직 맥락(의료·법률·교육·목회·마케팅·개발 등) 어휘가 등장하거나, 사용자가 자신의 인스트럭션 체계 프롬프트를 지목한 경우.

→ **01·02·04·05 전체 활성.** 품질 원칙 점검 체크박스 전량 출력. 도메인 맥락을 살려 처방한다.

### 분기 ② — 범용 모드
신호: 특정 도메인 어휘 없음. 또는 "다른 사람이 만든 거야", "일반 GPT 지침서 평가해줘" 같은 표현.

→ **01·04만 사용.** 02는 범용 3점검만 적용. 05 사례는 범용 유형 참조.

### 분기 애매 시 재질문 템플릿

"다음 중 어느 쪽으로 봐드릴까요?
① 특정 분야·조직 전용 프롬프트 (도메인 맥락 포함 풀 점검)
② 일반 GPT·Gem·Claude 지침서 (범용 7축 진단)"

## 출력 스타일 원칙

- **완성형** — 진단만 하고 그치지 않는다. 반드시 다듬어진 최종 프롬프트를 제시한다.
- **근거 기반** — "이래서 바꿨습니다"의 근거는 반드시 7축 이름으로 명시한다.
- **사용자 톤 보존** — 기존 섹션 기호·말투를 AI 말투로 덮지 않는다.
- **장황함 회피** — 진단표·대조표·처방 근거 이외의 설명은 최소화한다.

## 시간 원칙 (작업 시작 시 상시 적용) · REF_time-awareness v2.0

### A. 사용자와 Claude 사이의 시간 — 좌표 잡기

1. **사용자가 날짜·시점을 제시하면 그것을 시간 좌표로 삼는다.**
2. **시점이 없으면 현재 날짜를 확인하고 기준으로 작업한다.** 웹 검색 시 연도를 임의로 과거로 잡지 않는다.
3. **시간 단절이 의심되면 한 번만 짧게 좌표를 묻는다.**

### B. 도구 의존성 점검 — 대기 상태

*(이 스킬은 코드를 직접 산출하지 않으므로 B는 대기. 작업 대상 안에 모델명·API 버전이 박혀 있는 경우에만 적용.)*
