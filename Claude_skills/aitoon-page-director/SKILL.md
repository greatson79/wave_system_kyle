# aitoon-page-director — 페이지 만화 연출+스타일 프롬프트 생성기

스토리와 스타일 이미지를 받아, **GPT(나노바나나)에 복붙하면 연출된 페이지 만화가 나오는 프롬프트**를 만들어 준다.

> **핵심 가치:** "되네!"(운 좋은 한 장)가 아니라 **"이렇게 하면 매번 되네"(재현 방법)**.
> 좋은 페이지 만화는 운이 아니라, 연출·일관성·스타일을 1차 프롬프트에 다 박아 도달하는 것이다.
> **이 스킬을 쓰는 사람은 만화는 만들고 싶지만 과정은 귀찮아한다.** 그러니 씬·컷 구성, 연출 판단,
> 스타일 토큰 추출은 전부 안에서 처리하고, 유저 눈엔 **복붙할 프롬프트만** 내놓는다.

## Quick start

```
User: "이 스토리로 만화 페이지 만들어줘"
→ Step 0  intro.html을 show_widget으로 표시 → ★ 카드로 원고 분기 선택
           ① 클린 원고(말풍선 없음=기존 흐름)  ② 대사 포함(말풍선 사전)
           이어서 스타일 경로(미드저니 sref / GPT)를 텍스트로 묻는다.
→ Step 1  스토리 받기 + (내부) 씬·컷 구성 + 4~6페이지 배분
→ Step 2  미드저니 sref 그리드/코드 받기 → 스타일 토큰 7분해 + 캐릭터 경로 판정
→ Step 3  캐릭터 ref 생성 (★sref 코드 있으면 미드저니로 = 정석 / 없으면 GPT 폴백)
→ Step 4  페이지별 복붙 프롬프트 생성
           ├─ 클린 원고: 연출+일관성+스타일 (말풍선 없음 = 기존)
           └─ 대사 포함: 위 + 각 컷 💬 말풍선(balloon-dictionary.md)
→ Step 5  사용 안내 (첨부 순서·비율·GPT 사용법)  ← 여기까지가 공식 끝
→ (선택) SFX  완성본 받아 효과음 2패스 프롬프트 생성 (sfx-dictionary)
→ (선택) Step 6  결과 이미지 업로드 → 진단 → 그 페이지 프롬프트만 수정
```

## 유저 터치포인트 (나머지는 다 내부 처리)

유저가 손대는 접점은 이게 전부다. 이 사이의 모든 판단은 안에서 하고, 중간 산출물
(씬 분할표·컷 설계표·페이지 배분·토큰 추출 과정)은 **유저에게 보여주지 않는다.** SVG 레이아웃
시안도 만들지 않는다 — 유저는 그런 걸 원하지 않는다.

0. **시작 카드에서 원고 종류 고르기** (클린 원고 / 대사 포함 — 시작에서 한 번)
1. **스토리 던지기** (한 번)
2. **스타일 이미지 첨부** (미드저니 sref 그리드 — 이건 유저만 줄 수 있다)
3. **프롬프트 복붙 → GPT 생성** (페이지마다)
4. **(선택) 결과 이미지 업로드** (고치고 싶을 때만)

> 산출물은 결국 ① 캐릭터 ref 프롬프트 ② 페이지별 복붙 프롬프트 ③ 사용 안내 — 이 세 덩어리다.
> 연출 명세의 빡센 통제는 전부 ②번 1차 프롬프트 안에 녹아 들어가 한 방 성공률을 올리는 데 쓰인다.

## 가장 먼저 읽을 것

연출의 모든 판단 기준은 **`reference/direction-rules.md`** 에 있다. 컷 수 결정·컷 크기·앵글·칸 모양·
캐릭터/무기/방향 일관성·말풍선 타입·에피소드 전체 흐름·체크리스트가 거기 다 있다. **Step 1에서
이 파일을 먼저 읽고**, 그 기준으로 모든 페이지를 설계한다. 이 SKILL.md는 흐름만 잡고, 연출 디테일은
direction-rules.md가 권위다.

## Step 0 — intro.html 표시 + 원고 분기 (가장 먼저)

스킬이 트리거되면 **Step 1보다 먼저** `intro.html`을 읽어 `show_widget`으로 표시한다.

- **파일 경로**: `(스킬 루트)/intro.html`. **절대 새로 생성하지 않는다** — 파일 내용을 그대로 `widget_code`에 넣어 출력.
- intro.html은 **elicitation 선택 폼**이다(카드 2개 + 계속/건너뛰기). 사용자가 위젯 안에서 원고 종류를 **고르고 "계속"을 누르면** 그 선택이 다음 메시지로 들어온다(`원고 종류: 클린 원고` 또는 `원고 종류: 대사 포함`). 입력란에 텍스트가 찍히지 않는다.
- 위젯과 함께 한 줄만 안내한다: "원고 종류를 고르면 스토리를 붙여넣어 주세요. 미드저니 sref 그리드가 있으면 같이 주세요."
- 선택 결과로 분기:
  - **클린 원고** = 말풍선 없는 그림만(기존 흐름). Step 4는 클린 경로로.
  - **대사 포함** = GPT가 말풍선까지 그림. Step 4에서 `reference/balloon-dictionary.md`를 읽어 말풍선 분기로.
  - **건너뛰기** 시 기본값 = 클린 원고로 진행(모호하면 텍스트로 한 번 확인).
- 분기를 받은 뒤 **스타일 경로**를 텍스트로 묻는다: "미드저니 sref 그리드(가능하면 코드도)가 있으신가요, 아니면 GPT로 캐릭터를 만들어 진행할까요?"
- **원고 분기는 시작에서 한 번만** 정하고 중간에 바꾸지 않는다(프로세스·컨텍스트 안정). 클린 원고 경로는 기존과 100% 동일하게 보존 — 말풍선은 추가 옵션이다.

## Setup — 첫 회차에만 (한 번 정하고 재사용)

시리즈로 연재할 거면 첫 회차에 다음을 한 번 정하고 이후 회차에서 재사용한다. 매번 다시 묻지 않는다.

- **스타일**: sref 그리드 1세트 → 스타일 토큰(Step 2). 시리즈 내내 같은 화풍.
- **캐릭터 ref**: 주요 인물 ref(Step 3). **sref 코드가 있으면 미드저니로 뽑는 게 정석**(GPT 화풍 탈피, 화풍 또렷). 이후 회차는 이미 만든 ref를 첨부만.
- **페이지 비율**: 예 3:4. 시리즈 내내 고정.

이미 스타일·캐릭터가 있으면 Step 2·3을 건너뛰고 Step 4부터 간다.

## Workflow

### Step 1 — 스토리 받기 + 내부 구성

먼저 `reference/direction-rules.md`를 읽는다. 그다음 스토리(소설·시나리오·줄거리)를 받아 **내부에서**:

1. 씬으로 나누고 **페이지에 배분한다. 권장 4페이지 / 맥스 6페이지.** (분량이 많으면 §아래 분할 규칙.)
2. 페이지마다 **감정 비트를 한 줄로** 정한다("이 페이지는 정적인 대치", "여기서 격돌 폭발").
3. 비트에 맞는 **컷 수(1~8 탄력)**를 direction-rules §1로 고른다. **6은 자동이 아니다** — 정적/충격이면 1~2컷도 과감히.
4. 컷마다 [크기 / 앵글 / 칸 모양]과 등장인물·무기·방향을 direction-rules §2~5, §8 설계표로 정한다.
5. **대사·효과음(SFX)이 있으면 어느 컷에 무엇이 들어갈지 함께 정리한다.** (SFX는 2패스라 1패스 그림엔 안 그리지만, 미리 계획해 두면 2패스가 빨라지고 1패스 구도에서 SFX 자리도 비워둘 수 있다 — `reference/sfx-dictionary.md`.)

이 설계표·페이지 배분은 **내부 작업물이다. 유저에게 보여주지 않는다.** 바로 프롬프트로 간다.

**6페이지 초과 분할:** 긴 에피소드는 1~6 / 7~12로 나눈다. 한 배치를 끝내면 "확정된 페이지 상태"
(캐릭터·무기·방향)를 짧은 텍스트로 요약해 두고(아래 컨텍스트 관리), 다음 배치를 잇는다.

### Step 2 — 스타일 입력 → 토큰 추출

유저가 첨부한 **미드저니 sref 그리드 이미지**를 `reference/style-tokens.md` 절차로 7토큰(팔레트·
기법·윤곽선·색면·텍스처·무드·폰트무드)으로 분해한다. 피사체는 무시하고 그리는 방식만 본다.

**여기서 sref 코드 보유 여부를 파악한다 — 이게 Step 3 캐릭터 경로를 가른다.** 코드(예: `--sref 2567811006`)가
있으면 캐릭터를 **미드저니로 뽑는 정석 경로**로(코드를 GPT엔 직접 못 쓰지만, 미드저니 캐릭터 생성에
`--sref`로 쓰는 게 화풍 상위호환), 그리드 이미지만 있으면 GPT 폴백으로 간다.

스타일 이미지가 아직 없으면, 여기서 한 번 요청한다: "화풍을 입힐 미드저니 sref 그리드(가능하면 sref
코드도)를 주세요. 코드가 있으면 캐릭터를 더 또렷한 화풍으로 뽑을 수 있어요. 없으면 그리드 이미지만이라도요."

### Step 3 — 캐릭터 ref 생성 (★미드저니가 정석)

캐릭터 ref는 **미드저니로 원본을 잡아 그걸 GPT 페이지에 ref로 넣는 게 정석 전략**이다. 그래야 GPT 특유의
평평한 화풍에서 벗어나 sref 원본 화풍이 또렷이 묻는다. (어제 v1은 전 과정 GPT 단일이라 이 강점을 못 살렸다.)
Step 2에서 판정한 sref 코드 보유 여부로 경로를 가른다 — `reference/prompt-templates.md`에서 해당 형을 읽는다:

- **sref 코드 있음 → 미드저니 (권장·정석).** **A-MJ형**으로 캐릭터 시트 프롬프트를 만들어 미드저니
  `--sref [코드]`로 뽑게 한다. **미드저니 프롬프트 규칙**(생성동사 금지·비율은 `--ar`로만·스타일 앵커
  쌍방향·`--no`로 요소 제외)을 따른다 — prompt-templates.md에 내장돼 있다.
- **그리드 이미지만 → GPT (폴백).** **A-GPT형**으로 그리드 첨부 방식 프롬프트를 만든다.

어느 쪽이든 결과 캐릭터 이미지를 **페이지(GPT) 프롬프트에 ref로 첨부**한다. (페이지는 멀티패널 연출이라
미드저니가 약하므로 GPT 유지 — 캐릭터만 분기한다.) **비슷한 두 인물은 실루엣·체형을 극단적으로 차별**해
따로 뽑는다(direction-rules §3). **캐릭터 ref는 중립 기본형으로만** 뽑는다 — 특정 장면의 소품·상황 포즈는
ref에 넣지 않고(그건 페이지 프롬프트에서 해당 컷에 부여), 어느 컷에든 갖다 쓸 기준 외형만 고정한다.
이미 ref가 있으면 이 단계는 건너뛴다.

### Step 4 — 페이지별 복붙 프롬프트 생성 ★ 본체

페이지마다 `reference/prompt-templates.md` B형 골격으로 복붙 프롬프트를 만든다. 프롬프트를 확정하기
전 **direction-rules §10 체크리스트 7줄을 매 페이지 통과시킨다** — 컷 수·크기 대비·앵글·칸 모양·
캐릭터 고정 외형·무기 개수(쌍검 금지, 격돌 컷은 손까지)·180도·스타일 앵커·클린 원고. 이걸 1차에
다 박는 게 한 방 성공률의 핵심이다(터널비전 방지).

각 프롬프트에는 **영어 스타일 앵커 블록 + 내용물 가드**(style-tokens.md)와, 산출물 맨 앞 **첨부 경고
배너**를 넣는다. 연속 페이지는 직전 페이지 결과를 추가 첨부하도록 안내한다(prompt-templates C·세션 관성).

**★ 원고 분기 (Step 0에서 정함) — 여기서 갈린다:**

- **클린 원고 (기본·기존):** 위 그대로. 말풍선·텍스트·효과음 글자는 그림에 넣지 않는다. 대사는 Step 5에서 별도 메모(prompt-templates D형)로 넘긴다. **이 경로는 기존 동작을 그대로 유지한다.**
- **대사 포함 (말풍선):** 먼저 **`reference/balloon-dictionary.md`를 읽는다.** 각 컷의 장면 묘사 아래에 `💬 [사전 영어 스니펫] + 위치 한 줄 + 한국어 대사`를 박는다. 감정에 맞는 **이름을 사전에서 골라 스니펫을 그대로** 가져다 쓴다(이름이 곧 작동 토큰 — 해석·번역 금지). 프롬프트 맨 끝의 클린 원고 경고문은 **"지정된 💬 말풍선만 그리고 그 외 텍스트는 넣지 마세요"**로 바꾼다. 폰트는 깔끔한 산세리프(손글씨 금지 — 손글씨는 효과음 전용). 꼬리는 화자 입쪽(생각·전화·나레이션·Held-Back은 꼬리 없음). 사전 §6 위치 거동(컷 안/걸침/오버플로우)으로 컷과의 관계도 지정한다.

### Step 5 — 사용 안내 (공식 끝)

복붙 프롬프트를 다 내놓은 뒤 GPT(나노바나나) 사용법을 짧게 안내하고 **여기서 공식 종료**한다:

- 첨부 순서를 서수로(① 캐릭터 ref들 각각 → ② 스타일 그리드 → 연속이면 ③ 직전 페이지). ★ 캐릭터가 여럿이면 **각각 개별 서수+이름 1:1**(뭉뚱그리기 금지), 직전 페이지 서수는 첨부 개수에 맞춰 계산(=인물 수+2, prompt-templates C).
- 비율 고정.
  - **클린 원고 분기:** 말풍선은 그림에 안 넣음 — 대사는 별도 메모(direction-rules §7-1 타입)로 준다.
  - **대사 포함 분기:** 말풍선이 이미 그림에 들어가므로 별도 대사 메모는 생략한다.
- 가능하면 1→2→3페이지를 **같은 GPT 세션**에서 이어서(연속성↑).

클린 원고 분기에서 대사가 있으면 prompt-templates D형 대사 메모를 별도로 같이 준다(편집 도구에서 얹을 용).

### (선택) SFX 2패스 — 효과음 추가

Step 5에서 공식 종료한 뒤, 효과음을 원하는 유저를 위한 **독립·선택 옵션**이다. 사용 안내 끝에 이렇게 알린다:

> "효과음을 넣고 싶으면, 완성된 페이지를 작업 폴더에 복사하고 알려주세요. 이미지를 분석해 적당한 SFX 위치를 잡아 추가 프롬프트(2패스)를 써드려요. (직접 편집으로 얹으셔도 됩니다.)"

유저가 완성본을 주고 요청하면 `reference/sfx-dictionary.md`로:
1. 완성본을 분석해 **컷별 SFX 위치(대략) + 화면 맥락**을 잡는다(정밀 좌표 불필요 — 대략 위치 + 맥락이면 GPT가 어울리게 앉힌다).
2. 음 종류 → 글자스타일(L1~10)·효과(E1~10) 매핑으로 디자인을 고른다.
3. **기존 그림·말풍선 100% 보존 + 스타일 앵커(원래 화풍·색) + (필요시)sref 그리드 첨부 요청**을 박은 2패스 프롬프트를 만든다.

- 컷 설계(Step 1)에서 SFX를 미리 정리해 뒀으면 그 맥락을 그대로 쓴다.
- **이 단계는 안 해도 된다** — 직접 편집으로 효과음을 얹는 기존 경로도 그대로 살아 있다.

### Step 6 — (선택) 이미지 QC → 프롬프트 수정

유저가 "여기 이상해"라며 **결과 이미지를 올릴 때만** 발동한다. `reference/image-qc-fix.md`로 진단하고
**그 페이지 프롬프트만** 고쳐 다시 준다. **자동 v1→v2→v3 루프는 돌리지 않는다** — 유저가 부를 때만.
검수는 의심 컷만 **확대(crop)**해서 본다(쌍검·말풍선 클립은 썸네일로 놓친다 + 컨텍스트 절약).

## Context management — 맥스 6페이지를 안정적으로 받치는 두 장치

이미지 비전이 컨텍스트의 주범이라(페이지 수가 아니라 **분석 횟수**가 천장을 정한다), 두 가지로 관리한다:

1. **확정 페이지는 텍스트로 요약하고 비전 원본은 흘려보낸다.** 페이지가 OK 나면 "p2 확정: 무진
   왼쪽·검 1·발검 / 혈도 오른쪽·도 1" 같은 텍스트 체크포인트만 남기고, 분석 이미지를 누적하지 않는다.
2. **확대 QC는 페이지 전체가 아니라 의심 컷만 crop.** 전폭 고해상도를 매번 통째로 보지 않는다.

6페이지를 넘기면 배치를 나누고 페이지 체크포인트로 세션을 인계한다.

## Output standards

- 산출물 = ① 캐릭터 ref 프롬프트 ② 페이지별 복붙 프롬프트(클린 원고) ③ 사용 안내. 전부 **복붙 가능한 형태**.
- 비율은 시리즈 내내 고정. 말풍선·텍스트·효과음 글자는 그림에 넣지 않는다(클린 원고).
- 대사는 그리지 말고 별도 메모로(direction-rules §7-1 타입 지정).
- 중간 산출물(설계표·배분·토큰 과정)은 노출하지 않는다.

## Scope boundary

**이 스킬은 — 씬·컷 내부 구성 / 스타일 토큰 추출 / 캐릭터 ref 프롬프트 / 페이지별 복붙 프롬프트
(클린 원고 또는 선택적 말풍선) / 사용 안내 / (선택)이미지 보고 프롬프트 수정 — 을 한다.**

**다음은 하지 않는다:**
- **이미지 직접 생성** — GPT·미드저니 생성은 유저 몫. 이 스킬은 프롬프트까지.
- **자동 v1→v2→v3 반복 루프** — 수정은 유저가 부를 때만.
- **말풍선 픽셀 합성·편집** — 안 한다. 단 **선택적 말풍선**은 지원한다: 대사 포함 분기를 고르면 GPT가 말풍선을 직접 그리도록 프롬프트에 사전 스니펫(`reference/balloon-dictionary.md`)을 박는다. 생성·픽셀 보정은 유저 몫이고, 정밀 한글·위치는 외부 편집 또는 클린 원고 역획득(사전 §7)으로.
- **SFX(효과음) 픽셀 합성·편집** — 직접 합성은 안 한다. 단 **선택적 SFX 2패스**는 지원한다: 완성본을 받아 효과음 위치·디자인을 잡은 추가(오버레이) 프롬프트를 만든다(`reference/sfx-dictionary.md`). 생성은 유저 몫, 직접 편집 경로도 유지.
- **트랙 B 세로 웹툰** — 이 스킬은 페이지형(트랙 A) 전용. 세로 웹툰 요청이면 "이 스킬은 페이지형
  컷만화 전용이에요"라고 안내한다.
- **SVG 레이아웃 시안 노출** — 내부 설계는 텍스트로만, 유저에겐 프롬프트만.
