# SNS Card News Creator

설교의 핵심을 **시각적으로 소비 가능한 SNS 콘텐츠**로 변환하는 것이 핵심 임무다.
설교 전체를 압축하는 것이 아니라, **가장 강력한 한 가지 메시지**를 전달한다.

> **나선 구조 주의 (sermon-context 전개방식=나선):** "가장 강력한 한 가지 메시지"는 누적된 FCF가 아니라 **우산 CMT/복음 폭발 지점(그리스도·복음)**이다. 공유성(relatability)을 이유로 복음 비트를 밀어내지 않는다. 슬라이드 4(복음 적용)에는 그리스도를 가리키는 복음 전환이 반드시 살아 있어야 한다 (→ `quality-gates.md` 복음 비트 생존 게이트 — 부재 시 폐기·재생성).

## 입력

| 입력 | 출처 | 필수 |
|------|------|------|
| sermon-context.md | Team Leader가 설교 output에서 추출 | 필수 |

sermon-context.md가 없으면: "설교 컨텍스트가 필요합니다. `/주간작업`을 먼저 실행하거나, 설교 제목/본문/CMT/FCF/HP를 직접 입력해주세요."

## 출력

| 산출물 | 파일명 | 설명 |
|--------|--------|------|
| 슬라이드 텍스트 | `slides.md` | 5-7장 슬라이드별 텍스트 + 디자인 지시 |

| 카카오톡 메시지 | `message-kakao.txt` | 150자 이내 |

## 카드뉴스 슬라이드 구조 (5-7장)

### 1장: 표지
- **콘텐츠용 제목** 사용 (sermon-context.md의 콘텐츠 제목)
  - 예배용 제목이 아닌, CTR 최적화된 제목을 표지에 사용한다
  - 콘텐츠 제목이 없으면 설교 제목을 짧게 다듬어 사용
- 성경 본문
- 교회 로고 또는 브랜드 마크
- 디자인: 깔끔, 여백 충분, 텍스트 중심

### 2장: 공감 / 질문
- FCF 기반 공감 문구
- "혹시 이런 경험 없으신가요?"
- "왜 우리는 ~ 할까요?"
- 독자가 "나 얘기다" 느끼게

### 3장: 핵심 메시지 1
- 본문에서 발견한 진리 (CMT 기반)
- 성경 구절 인용 1개
- 1-2문장으로 핵심 전달

### 4장: 핵심 메시지 2
- HP 기반 복음 적용
- "그러나 하나님은 ~ 하셨습니다"
- "그래서 우리는 ~ 할 수 있습니다"
- 희망과 은혜의 메시지

### 5장: 적용 / 초대
- 이번 주 실천 1가지
- 또는 예배 초대 메시지
- CTA (Call to Action) 포함

### 6장 (선택): 인용구
- 설교 중 가장 인상적인 문구
- 큰 따옴표, 큰 폰트
- 공유하고 싶은 한 마디

### 7장: 마무리
- 교회 이름, 예배 시간
- SNS 계정 안내
- "함께 예배해요" 초대 문구

## 인스타그램 캡션 규칙

→ `rules/instagram.md` 참조

- 300자 이내
- 첫 문장이 가장 중요 (피드에서 보이는 부분)
- 줄바꿈으로 가독성 확보
- 해시태그 5-8개 (마지막에 모아서)
- 기본 해시태그: #디딤교회 #주일설교 #말씀카드
- 본문 관련 해시태그 3-5개 추가

---

## 카카오톡 메시지 규칙

→ `rules/kakaotalk.md` 참조

- 150자 이내
- 따뜻하고 짧게
- 핵심 메시지 1개 + 본문 인용
- "이번 주일 함께 예배해요" 초대 포함

## 디자인 지시서 형식

각 슬라이드에 디자인 방향을 함께 기록한다:

```markdown
## 슬라이드 1: 표지
**텍스트:**
섬김의 리더십
막 10:35-45
디딤교회

**디자인 지시:**
- 배경: 차분한 단색 (네이비 또는 딥그린)
- 폰트: 제목 굵게, 본문 가늘게
- 교회 로고 하단 중앙
- 여백 충분히
```

## 생성 절차

### Step 0 — 디자인 브리프 준비 (WK-G 협업)

`design-brief.md`가 이미 존재하면 Step 1로 넘어간다.  
없으면 **Design Agent(WK-G)**를 먼저 실행한다:

```
[Design Agent 실행]
  입력: sermon-context.md + brand-guide.md
  출력: output/{월}/{주차}/카드뉴스/design-brief.md
```

- `--design-skip` 플래그가 있으면 WK-G를 건너뛰고 기본 브랜드 가이드 사용
- design-brief.md가 생성되면 **`frontend-design` 스킬 활성화** 상태로 HTML 생성

### Step 1-6 — 콘텐츠 생성

1. sermon-context.md에서 CMT, FCF, HP, 제목(콘텐츠용), 본문, 예화 추출
2. 슬라이드 5-7장 텍스트 + 디자인 지시 작성 → `slides.md`
   - design-brief.md의 슬라이드별 지시를 slides.md에 반영
3. **HTML 미리보기 생성** (1080×1080 시뮬레이션) → `slide-preview.html`
   - `frontend-design` 스킬 가이드라인 준수:
     - Noto Serif KR (display) × Noto Sans KR (body) 폰트 페어링
     - 슬라이드별 고유 레이아웃 (단일 패턴 반복 금지)
     - 고스트 타이포그래피, 그레인 텍스처 등 design-brief.md 지시 적용
     - 슬라이드 7: 반드시 `didim-logo.png` 이미지 사용 (동그라미 십자가 텍스트 금지)
   - 각 슬라이드는 `.slide` 클래스, 540×540px
4. **PNG 캡쳐** → `slide-1.png` ~ `slide-N.png`
   ```bash
   node src/scripts/capture-cardnews.js output/{월}/{주차}주차/카드뉴스/slide-preview.html
   ```
   - Puppeteer로 각 `.slide` 요소를 개별 캡쳐
   - deviceScaleFactor: 2 → 1080×1080 고해상도 PNG
5. 인스타그램 캡션 작성 → `caption-instagram.txt`
6. 카카오톡 메시지 작성 → `message-kakao.txt`
