# 품질 게이트 규칙

## 설교 완료 게이트

설교 output 폴더 내 파일 존재 여부로 판단한다.

### 파일 → 단계 매핑

```
1_상황파악.md    → 1단계 완료
2-1_원어분석.md  → 2-1 완료
2-2_배경분석.md  → 2-2 완료
2-3_우상분석.md  → 2-3 완료
2-4_종합통찰.md  → 2-4 완료 (CMT, FCF, HP 확보)
3_내용전개.md    → 3단계 완료
4-1_제목확정.md  → 4-1단계 완료 (제목 확정)
4-2_전개방식확정.md → 4-2단계 완료 (전개방식 최종 확정)
4-3_예화설계.md  → 4-3단계 완료 (예화 설계)
4-4_아웃라인작성.md → 4-4단계 완료 (아웃라인 확보) ← 게이트 1
4-C_*.md         → Mode C 아웃라인 (4-4단계 변형)
5_원고.md        → 5단계 완료
```

### 게이트 수준

| 수준 | 조건 | 후속 작업 품질 |
|------|------|--------------|
| 최소 | `2-4_종합통찰.md` 존재 | 기본 (CMT, FCF, HP만으로 생성) |
| 권장 | `4-4_아웃라인작성.md` 또는 `4-C_*.md` 존재 | 양호 (아웃라인 포함) ← 게이트 1 |
| 최적 | `5_원고.md` 존재 | 최고 (원고 기반) |

### 게이트 통과 판단

1. 최소 조건 미충족 시: "설교 2-4단계(종합통찰)까지 완료해야 후속 작업이 가능합니다."
2. 최소 충족 + 권장 미충족 시: "현재 CMT/FCF/HP 기반으로 생성 가능합니다. 아웃라인까지 완료하면 품질이 향상됩니다. 진행할까요?"
3. 권장 이상 충족 시: 자동 진행

## sermon-context.md 생성 규칙

게이트 통과 시 아래 4개 파일에서 데이터를 추출한다:

| 원본 파일 | 추출 데이터 |
|----------|------------|
| `1_상황파악.md` | 본문, 장르, Mode, 대상, 절기 |
| `2-4_종합통찰.md` | CMT(나선=우산 CMT), FCF, HP, 3가지 통찰, **전개방식(선형\|나선)** |
| `3_내용전개.md` | 적용 포인트 |
| `4-1_제목확정.md` | 설교 제목 (예배용·콘텐츠용) |
| `4-3_예화설계.md` | 핵심 예화 |
| `4-4_아웃라인작성.md` | 대지(아웃라인) / **나선 시 복음 폭발 지점(클라이맥스 그리스도·복음)** |

파일이 없는 항목은 "(미완료)" 로 표시한다.

> **나선 구조 sermon-context 규칙**: 전개방식이 나선이면 (1) CMT 필드에 **우산 CMT**를 기록하고, (2) "복음 폭발 지점" 필드에 클라이맥스의 그리스도·복음 선언을 명시한다. 다운스트림(소그룹·카드뉴스·캡션)의 핵심 메시지는 **우산 CMT/복음 폭발 지점에서만 추출**하며, 누적 대지의 FCF를 핵심 메시지로 삼지 않는다 (복음 누수 방지).

## 전체 산출물 품질 기준

> 설교 게이트 외에, 모든 콘텐츠 유형에 적용되는 공통 품질 기준이다.

### SOT 일치 검증

모든 산출물은 생성 후 SOT 데이터와 일치하는지 확인한다.

| 산출물 | 검증 대상 | SOT 원천 |
|--------|----------|----------|
| 매일묵상 HTML | 본문 구절, 주제, 요일 | `devotion-data.json` |
| 기도카드 HTML | 기도 제목, 날짜, 순서 | `data/prayer/*.csv` |
| 소그룹 나눔지 | 설교 본문, CMT(나선=우산 CMT), 적용 | `sermon-context.md` |
| SNS 카드뉴스 | 설교 핵심 메시지(나선=우산 CMT/복음 폭발 지점), 본문 | `sermon-context.md` |

위반 발견 시: 산출물을 폐기하고 SOT에서 다시 읽어 재생성한다.
"대충 맞는 것"은 통과가 아니다.

> **나선 구조 검증 기준**: 전개방식이 나선인 경우, 소그룹·카드뉴스의 핵심 메시지는 `sermon-context.md`의 **base CMT가 아니라 우산 CMT(복음 폭발 지점)**와 일치해야 한다. base/우산 불일치로 인한 오탐 폐기를 막기 위해, 나선 산출물의 SOT 일치 대상은 우산 CMT로 고정한다.

### 복음 비트 생존 게이트 (나선 구조 필수 / 전 산출물 권장)

복음을 의도적으로 지연시키는 나선 구조에서는, 다운스트림 산출물이 누적 FCF만 담고 **복음(그리스도)을 빠뜨려 율법만 선포**할 위험이 있다. 아래를 강제한다:

| 산출물 | 복음 비트 필수 위치 | FAIL 조건 |
|--------|-------------------|----------|
| 소그룹 나눔지 | "복음 묵상" 질문 (HP 기반) | 그리스도를 가리키는 지시 대상 부재 |
| SNS 카드뉴스 | 슬라이드 4 (HP 기반 복음 적용) | "그러나 하나님은~/그래서 우리는~" 복음 전환 부재 |
| 인스타 캡션 | 핵심 메시지 줄 | 그리스도를 가리키는 일상어 비트 부재 |
| 숏츠 (mp4) | msg3 "복음의 선언" 씬 | 그리스도를 가리키는 복음 비트 부재 (완전 자동·공개 출력 — 최우선 점검) |

- 복음 비트가 부재하면 **산출물을 폐기하고 재생성**한다. (FCF·공감만으로 통과 불가)
- 캡션의 복음 어휘 제약(`sns-cardnews/rules/instagram.md` Layer 3)은 "은혜·구속" 등 종교 용어를 금하되, 그리스도를 가리키는 **일상 언어 1줄**(예: "내가 갚지 않아도 되는", "이미 받아들여진")은 반드시 보존한다.

> **게이트 면제 (sermon-context 소비하나 복음 비트 불요)**: 다음은 설교의 FCF/메시지를 요약·생성하지 않으므로 본 게이트 대상이 아니다 — **주보**(`bulletin`, 설교 제목·본문·설교자만 인용), **디자인 스카우트**(`design-template-scout`, 시각 방향만 추출). 이 둘은 율법-온리 누수 경로가 아니다.

### 완전성 검증

| 산출물 | 완전성 기준 |
|--------|-----------|
| 매일묵상 | 15개 HTML 전부 생성 (월~금 × 장년wordpress + 장년a4 + 청소년a4) |
| 기도카드 | 해당 주차 HTML + PNG 캡쳐 완료 |
| 소그룹 나눔지 | 장년용 + 청소년용 + 리더용(장년) 전부 생성 |
| SNS 카드뉴스 | 슬라이드 전체 + 캡션 전체 생성 |

하나라도 누락되면 "일부 완료"로 보고한다. 조용히 넘어가지 않는다.

### 목회적 적절성 검증

AI가 스스로 점검하는 자기 검증 항목:

- 묵상 내용이 해당 본문의 맥락에서 벗어나지 않는가?
- 나눔지 질문이 소그룹 대화를 촉진하는 열린 질문인가?
- 카드뉴스 문구가 SNS에 적절한 톤과 길이인가?
- 기도카드가 구체적이고 공감할 수 있는 기도 표현을 사용하는가?

의심스러운 부분이 있으면, 해당 부분을 사용자에게 표시하고 확인을 요청한다.

### 오류 복구 프로토콜

에이전트 실행 중 오류 발생 시:

| 단계 | 행동 |
|------|------|
| 1차 시도 | 동일 방법 재시도 |
| 2차 시도 | 대안 방법 (다른 템플릿, 다른 경로) |
| 3차 시도 | 최소 기능 모드 (핵심 콘텐츠만 생성) |
| 3회 실패 | Team Leader에 보고 → 사용자에게 전달 |

보고 시 포함 사항: 어떤 에이전트가, 무슨 작업에서, 어떤 에러로, 몇 회 실패했는지.
